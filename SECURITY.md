# Security policy

## Supported versions

Security fixes go into the latest release of each SMF package on pub.dev. If you use an older version, upgrade first and check whether the problem is still there.

## Reporting a vulnerability

Please don't open a public issue for a vulnerability. Report it privately in either of these ways:

- On GitHub, with a [private vulnerability report](https://github.com/saymyframe/smf_flutter_cli/security/advisories/new) from the Security tab of this repository.
- By email to security@saymyframe.com. You can encrypt the message with the [PGP key](https://saymyframe.com/pgp.asc) whose fingerprint is `8163 AD35 6408 409D 0C73 9371 9BF2 D190 5017 7436`.

Describe the problem, the package and version, how to reproduce it and what an attacker could do with it. If you have an idea for a fix, include it too.

## What happens next

SMF is a free project maintained in spare time, so there are no fixed response times. Security reports come before other work. Once a fix is out, a GitHub security advisory describes the vulnerability and credits you, unless you'd rather not be named.

## Scope

This policy covers the `smf` CLI, the packages in this repository and the code they generate. Report vulnerabilities in Flutter, Firebase, FlutterFire or other third-party tools and packages to their own maintainers.
