# AGENTS.md

This guide tells coding agents what the code of this Flutter app does not show. Setup that needs a person or an account is in [README.md](README.md). When you change what a section describes, change the section too.

## App entry

The app is plain Flutter code that nothing regenerates. Change it by hand, unless a section below says what writes a file.

- `main()` in `lib/main.dart` initializes the binding, awaits `bootstrap()` and calls `runApp()`, in this order. Start-up code goes into `bootstrap()`.
- `bootstrap()` in `lib/bootstrap.dart` runs before the first frame, in four phases: what must come before anything else, then the platform services, then the services of the app, then what needs them. Put a new statement into its phase, and import neither `package:flutter/material.dart` nor `package:flutter/cupertino.dart` there.
- Put code that features share into `lib/core/<concern>/`, one directory for each concern. Put a feature, with its screens and their state, into `lib/features/<feature>/`.
- The root of the app asks the system for the icons of the status bar that suit the theme, around every screen, with `StatusBarIcons` of `lib/core/app/status_bar_icons.dart`: dark icons on a light theme, light ones on a dark theme. A screen without an app bar needs no `AnnotatedRegion` for them. Add one only to a screen whose top has another brightness than the theme, such as a picture behind the status bar.

After a change, run:

```bash
dart format lib test
flutter analyze
flutter test
```

Format only `lib/` and `test/`: `dart format .` also formats what Flutter writes into `build/`. The app as generated is formatted, `flutter analyze` finds no issue in it and `flutter test` passes.

- `App` in `lib/app.dart` is the root widget of the app and creates its one `MaterialApp`. Create no other in `lib/`: every screen is below it.
- The `theme`, `darkTheme`, `themeMode`, `locale` and localizations of the app go into the arguments of that `MaterialApp`.
- Tests mirror `lib/`: the test of `lib/<path>.dart` is `test/<path>_test.dart`.
- The app has only an Android and an iOS project, in `android/` and `ios/`.
- The entitlements of the iOS app, such as Push Notifications or Sign in with Apple, are in `ios/Runner/Runner.entitlements`. Every build configuration of the Runner target signs with this file, even while it is empty. The Signing & Capabilities tab of Xcode edits the same file.

## Localization

- Show the user no text but the name of the app from a string literal. Read each text as `context.l10n.<name>`, with `lib/core/l10n/l10n.dart` imported, where `context` is a `BuildContext` below the root of the app. Such an expression is no constant, so the widget around it cannot be `const`.
- `lib/core/l10n/app_locale.dart` has `appLocales`, the languages of the app, and `appLocale`, the one that the user chose. Change the language only with `appLocale.choose(locale)`, which also saves the choice in the preferences, and write nothing under the key `localization.locale` yourself. The root `MaterialApp` gets its `locale` and its `supportedLocales` from that file: leave both as they are.
- Every delegate among the `localizationsDelegates` of the root has to support each language of `appLocales`. A new language, one in which Flutter has the texts of its own widgets, goes into `appLocales`, into `CFBundleLocalizations` in the Info.plist of the iOS app, and into the texts of the app.

- A new language also needs its name in `_names` in `lib/core/l10n/language_setting.dart`: the setting of the language on the settings screen shows a language by that name, and by its code without one. Each name there is a string literal, the name of the language in that language, which is the same whatever language the app is in.

With `gen-l10n` of Flutter:

- The texts of the app are in the ARB files of `lib/l10n`. `lib/l10n/app_en.arb` has every text in English, and `lib/l10n/app_<code>.arb` the translations into another language. A text that such a file lacks reads in English there.
- To add a text, add it to `lib/l10n/app_en.arb` under a name in lowerCamelCase, and its translations under the same name to the other files.
- After every change of the ARB files, a new file included, run `flutter gen-l10n`, which generates `context.l10n.<name>`. Do not edit `lib/l10n/app_localizations*.dart`: `gen-l10n` writes those files from the ARB files, as `l10n.yaml` says.
- Write an apostrophe in a text once: `l10n.yaml` turns the escapes of `gen-l10n` off (`use-escaping: false`).

## Notifications

- `appNotifications` in `lib/core/notifications/app_notifications.dart` shows the notifications of the app. `show()` shows one now, `schedule(notification, at: time)` at about that time, not to the minute, even if the app is closed by then. `cancel()` and `cancelAll()` remove them, and `scheduled()` lists those still to come, those of an owner too. A notification is an `AppNotification` with an `id`, a `title`, a `body` and `data`, and one with the id of a notification that is shown or scheduled takes its place. Give it an id from 0 up: a negative id is for a notification with an owner, which names it under `notificationOwnerKey` in its `data`, and whose taps go to `tapsOf(owner)` and `launchTapOf(owner)`.
- `appNotifications.permission` is `granted`, `denied` or `notAsked`. Ask with `appNotifications.request()` where the user turns on something that notifies, so that the question explains itself. Where the system has no question to show, as on Android before 13, the request opens its settings instead. After `denied` the system may not ask again (iOS asks only once, and Android stops after a second no), so open its settings with `appNotifications.openSettings()`. The app remembers that it asked under `notifications.asked`, so write nothing under that key.
- A tap on a notification reaches `appNotifications.taps` with the `data` of the notification, and the tap that launched the app is `appNotifications.launchTap`. Handle both once the first screen is shown, and navigate as the rest of the app does. A notification runs no code of the app when it shows.
- On Android a notification shows `android/app/src/main/res/drawable/ic_notification.xml` as its small icon. Change the drawing there and keep the name of the file.
- A new provider implements `NotificationsService` of `lib/core/notifications/notifications_service.dart`, and only the files of that implementation import it. The code of the app imports `lib/core/notifications/app_notifications.dart`, which exports `AppNotification` and `NotificationTap`, and calls neither `initNotifications()` nor `createNotificationsService()` nor `appNotifications.start()`.

- `NotificationsSetting` in `lib/core/notifications/notifications_setting.dart`, an entry of the settings screen, shows whether the app may show notifications. A tap asks while the app has not asked, and opens the settings of the system after that.

With `flutter_local_notifications`:

- `LocalNotificationsService` in `lib/core/notifications/local_notifications_service.dart` implements `NotificationsService` on `FlutterLocalNotificationsPlugin`. In `lib/`, only that file imports the package: other code shows notifications through `appNotifications`.
- Every notification goes to the channel `notificationChannelId` with the details in `_details` of that file. For another channel, such as one with another sound, create it with `createNotificationChannel()` of `AndroidFlutterLocalNotificationsPlugin` in `openLocalNotifications()`, and show a notification in it with details of its own.
- A scheduled notification uses an inexact alarm (`AndroidScheduleMode.inexactAllowWhileIdle`). Exact alarms need the permission `SCHEDULE_EXACT_ALARM`, which Google Play allows only for an app whose main feature needs them: change the mode only when asked.
- `android/app/src/main/AndroidManifest.xml` declares the receivers of the package, `android/app/build.gradle.kts` turns on core library desugaring, and `ios/Runner/AppDelegate.swift` sets the delegate of the notification center. Keep them: scheduled notifications, the Android build and the taps on iOS need them.
- The package has no platform side for tests. A test that runs `bootstrap()` answers the method channel `dexterous.com/flutter/local_notifications` itself, with `setMockMethodCallHandler` of `TestDefaultBinaryMessengerBinding.instance.defaultBinaryMessenger`, after `AndroidFlutterLocalNotificationsPlugin.registerWith()`.

## Preferences

- `AppPreferences` in `lib/core/preferences/app_preferences.dart` remembers the settings of the app between its launches, such as the theme mode. It is not encrypted: never save a token, a password, an API key or an encryption key in it.
- To remember a setting, write a function that takes the `AppPreferences` and add it to `_restorers` in that file. In it, read the setting, put it into the state that the widgets listen to, and keep the preferences in that state for its writes. The function awaits nothing, and keeps the current value when nothing is saved.
- Name a key `<owner id>.<setting>`, such as `theme.mode`, where the owner is the feature or the concern whose code keeps the setting.
- In the code of the app, do not call `createAppPreferences()` or `initPreferences()`. `bootstrap()` opens the preferences, and code gets them as the argument of its function in `_restorers`, or, with a DI container in the app, from the container. Widgets use the state and do not touch the preferences. A test may call both: `initPreferences()` opens the preferences again, as the next launch of the app does, and `createAppPreferences()` returns them.

With `shared_preferences`:

- In `lib/`, only `lib/core/preferences/shared_app_preferences.dart` imports the package. Other code uses `AppPreferences`.
- A number is read only as the type that it was saved as: `getDouble()` returns `null` for a key with an `int`, and `getInt()` for a key with a `double`.
- In a test that runs `bootstrap()`, first set `SharedPreferencesAsyncPlatform.instance = InMemorySharedPreferencesAsync.empty()`. Without it, opening the preferences throws. Both names are from the package `shared_preferences_platform_interface`: add it as a dev dependency.
- `pubspec.yaml` keeps `shared_preferences_android` below 2.5.0. With 2.5.0, a release build fails to open the preferences on Android, because R8 renames Kotlin classes that the package looks up by name. Before you raise the constraint, check that a release build of the app starts on Android.

## Router

- Navigate with `context.nav.<feature>.<route>(...)`, never with the package of the router. It returns a `NavLink`, whose `go()`, `push<T>()` and `replace()` show the location. In `context.nav` both names are in lowerCamelCase; elsewhere `<feature>` is the id of the feature.
- A route is in three places, which agree on its name, `<feature>.<route>`, and on its path, which starts with `/<feature>`:
  1. its screen, a widget in `lib/features/<feature>/` whose `const` constructor takes each value of the route as a named parameter;
  2. `lib/core/router/navigation.dart`: its location class, which extends the sealed `AppLocation` with its `routeName`, its `path` and, below another route, its `parent`, and a method that returns its `NavLink` in the class of the routes of its feature. `AppNav` returns that class from a getter with the name of the feature, and both classes pass on the `BuildContext` that `NavLink` takes;
  3. the route itself, where the provider of the router declares its routes.
- A value of a route is a `String`, an `int`, a `double` or a `bool`, from a `:<name>` segment of its path or from the query.
- `appRouter` of `lib/core/router/app_router.dart` is the one router of the app: create no other.

With `go_router`:

- `lib/core/router/app_router_factory.dart` has the one `GoRouter` of the app. A route is a `GoRoute` in its `routes`, or in the `routes` of its parent: `path` is the full path of a top-level route and the path from its parent otherwise, and `name` is `<feature>.<route>`. The values of a route come from `state.pathParameters` and `state.uri.queryParameters`. Parse one that is not a `String` with `tryParse`, and throw a `GoException` in the `redirect` of the route when a required value is missing or does not parse, so that the router shows its error screen.
- The app opens at `initialLocation`, and the route `/` leads to the same screen: change both together.
- To follow the screen that the user sees, add a function to `_screenListeners`.

## Settings screen

- The settings screen is a list with an entry for each setting of the app. An entry is a widget in a file of the code that owns the setting, such as one in `lib/core/<concern>/` or `lib/features/<feature>/`, and not in the file of the screen. It reads and changes its setting itself.
- To add a setting, write such a widget with a `const` constructor that requires no arguments. Create it in the list of the screen, and import its file there with a prefix that no other import there has, because two entries may have the same class name.
- The screen puts each entry on a `Material`, sets its width and puts no limit on its height, so an entry can be a `ListTile` or a `Column` of them. Pass an entry no arguments: it gets its state from its owner.

- `SettingsScreen` in `lib/features/settings/settings_screen.dart`, the route `settings.settings` at `/settings`, is the settings screen. Below its title it shows the entries in one group, and the file imports the files of the entries as `entry0`, `entry1` and so on. While no module of the app has a setting, it shows a note for the developer of the app in place of the group: the first entry replaces that note.
- With a main navigation in the app, the screen is one of its destinations.
- Without a main navigation, no screen leads to the settings screen: open it with `context.nav.settings.settings().push<void>()`, which shows it on top of the current screen, so that its back button leads back. `go()` would replace the stack with the screen alone, and nothing would lead back.

## Texts

The texts of the app are in the ARB files of `lib/l10n`, one for each language. `lib/l10n/app_en.arb` has every text in English, and the file of another language, such as `app_uk.arb`, has the translations into it. [gen-l10n](https://docs.flutter.dev/ui/internationalization) of Flutter generates the `AppLocalizations` class from these files, as `l10n.yaml` says, and writes it into `app_localizations.dart` and a file for each language in the same directory. Run `flutter gen-l10n` after every change of the ARB files. In a fresh clone of the app, `flutter pub get` generates those files, so you can commit them or leave them out of the repository. Code reads a text as `context.l10n.<name>` with `lib/core/l10n/l10n.dart` imported, where `context` is a `BuildContext` below the root of the app.

To add a text, add it to `lib/l10n/app_en.arb` under a name of its own, and its translations under the same name to the files of the other languages. Then run `flutter gen-l10n`. A text without a translation into a language reads in English there.

The texts of a new language, such as German, go into a file of their own:

1. Add `lib/l10n/app_de.arb` with `"@@locale": "de"` and the translations.
2. Run `flutter gen-l10n`.

The section "Languages" tells where else the new language goes.

## flutter_local_notifications

The app shows its notifications with [flutter_local_notifications](https://pub.dev/packages/flutter_local_notifications): `lib/core/notifications/local_notifications_service.dart` implements the notifications service of the app on it (see the section Notifications).

The module set up what the package needs in the native projects:

- `android/app/build.gradle.kts` turns on core library desugaring with `desugar_jdk_libs` 2.1.4, without which the Android build fails.
- `android/app/src/main/AndroidManifest.xml` declares the receivers of the package that show a scheduled notification at its time and set the scheduled ones again after a restart of the device or an update of the app, and the permission `android.permission.RECEIVE_BOOT_COMPLETED` for the restart.
- `ios/Runner/AppDelegate.swift` makes the app delegate the delegate of the notification center of iOS, so that a notification shows while the app is in the foreground and a tap reaches the app, also the tap that launched it.

Every notification goes to the channel `default`, with a high importance, which the service creates when the app starts. A scheduled notification uses an inexact alarm on Android, which needs no permission: Android may show it a few minutes late. To show notifications to the minute, declare `android.permission.SCHEDULE_EXACT_ALARM` in the manifest, ask for it with `requestExactAlarmsPermission()` of `AndroidFlutterLocalNotificationsPlugin`, and schedule with `AndroidScheduleMode.exactAllowWhileIdle`. Google Play allows exact alarms only for apps whose main feature needs them, such as an alarm clock or a calendar.

The app does not set up the actions of a notification, its buttons. They need the receiver `ActionBroadcastReceiver` on Android and, on iOS, a callback that registers the plugins for the isolate in which an action runs: see the README of the package.

## Languages

The app is in the languages of `appLocales` in `lib/core/l10n/app_locale.dart`. It shows its texts in the language that the device prefers among them, and in the first of the list when the device asks for none of them. `appLocale.choose()` puts the app into another of its languages, whatever the device prefers, and the app remembers that choice between its launches. `appLocale.choose(null)` follows the device again. The entry `LanguageSetting` of the settings screen, in `lib/core/l10n/language_setting.dart`, lets the user choose.

To add a language in which Flutter has the texts of its own widgets, such as German, add the texts of the app in German, and then:

1. Add `Locale('de')` to `appLocales`, one locale for each language, since the app tells its languages apart by their codes.
2. Add `de` to `CFBundleLocalizations` in `ios/Runner/Info.plist`, which tells iOS the languages of the app.
3. Add `'de': 'Deutsch'` to `_names` in `lib/core/l10n/language_setting.dart`, the name that the setting shows for the language. Without it, the setting shows `de`.

## Notifications

The app shows notifications through `appNotifications` in `lib/core/notifications/app_notifications.dart`. `show()` shows one now and `schedule()` at a time to come, `cancel()` and `cancelAll()` remove them, and `scheduled()` lists those still to come. A scheduled notification shows at about its time, not to the minute, even if the app is closed by then, and after the device restarts. A tap on a notification reaches `appNotifications.taps` with the `data` of the notification, and `appNotifications.launchTap` is the tap that launched the app.

The app needs the permission of the user to show notifications. `appNotifications.permission` is `granted`, `denied` once the user said no or turned them off, or `notAsked`, and `appNotifications.request()` asks. Where the system has no question to show, as on Android before 13, the request opens the settings of the system for the notifications of the app instead. The entry `NotificationsSetting` of the settings screen, in `lib/core/notifications/notifications_setting.dart`, shows whether the app may show notifications. A tap asks while the app has not asked, and opens the settings of the system after that. After `denied` the system may not ask again: iOS asks only once, and Android stops asking after a second no. `appNotifications.openSettings()` opens the settings of the system, where the user turns the notifications on.

On Android a notification shows `android/app/src/main/res/drawable/ic_notification.xml` as its small icon. Replace the bell there with the icon of the app, a shape on a transparent background, and keep the name of the file: `android/app/src/main/res/raw/notifications_keep.xml` keeps the icon in a release build. In the settings of the system, the channel of the notifications has the name of the app.

/// The languages of the app. The app shows its texts in the language that
/// the device prefers among them, and in the first of the list when the
/// device asks for none of them.
///
/// A language has one locale here. The app tells its languages apart by
/// their codes alone, so of two locales of one language, such as
/// `Locale('pt', 'BR')` and `Locale('pt', 'PT')`, `appLocale.choose()`
/// takes the first, whichever of them it is given.
const appLocales = <Locale>[Locale('en'), Locale('uk')];

/// The key of the preferences of the app under which the app saves the
/// language that the user chose, as the code of the language, such as `uk`.
/// Nothing is saved under it while the app follows the languages of the
/// device.
const _key = 'localization.locale';

/// The language that the user chose for the app, which the app remembers
/// between its launches.
///
/// The root of the app reads it through [AppLocaleScope], and rebuilds in
/// the new language when the choice changes.
final appLocale = AppLocaleController._();

/// Keeps the language that the user chose for the app, and saves each
/// choice in the preferences of the app.
final class AppLocaleController extends ChangeNotifier {
  AppLocaleController._();

  Locale? _locale;

  /// The preferences of the app, once it opened them.
  AppPreferences? _preferences;

  /// The language that the user chose, one of [appLocales], or `null` while
  /// the app follows the languages of the device.
  Locale? get value => _locale;

  /// Chooses the language of [locale] as the language of the app, or with
  /// `null` lets the app follow the languages of the device again.
  ///
  /// The choice is the one of [appLocales] with the language of [locale],
  /// so `Locale('uk', 'UA')` chooses `Locale('uk')`. A locale of a language
  /// that the app is not in is refused: the future completes with an
  /// [ArgumentError], and nothing changes.
  ///
  /// The language of the app changes at once, and the choice is then saved
  /// in the preferences once the app opened them: before that, it changes
  /// only memory. When saving fails, the future completes with the error of
  /// the preferences. The app stays in the new language while it runs, and
  /// its next launch starts with what was saved before; choosing the
  /// language again saves it again.
  Future<void> choose(Locale? locale) async {
    final chosen = locale == null ? null : _ofApp(locale.languageCode);
    if (locale != null && chosen == null) {
      throw ArgumentError.value(
        '$locale',
        'locale',
        'The app is not in the language of this locale',
      );
    }
    _set(chosen);
    final preferences = _preferences;
    if (preferences == null) return;
    if (chosen == null) {
      await preferences.remove(_key);
    } else {
      await preferences.setString(_key, chosen.languageCode);
    }
  }

  void _set(Locale? locale) {
    if (locale == _locale) return;
    _locale = locale;
    notifyListeners();
  }
}

/// The one of [appLocales] with the language of the code [code], or `null`.
Locale? _ofApp(String? code) {
  for (final locale in appLocales) {
    if (locale.languageCode == code) return locale;
  }
  return null;
}

/// Restores the language that the user chose from [preferences], which the
/// app opened, and keeps them for the choices to come: a restorer of the
/// preferences, which the app calls before its first frame.
///
/// When nothing is saved, or what is saved is not the code of one of
/// [appLocales], the choice stays as it is.
void restoreAppLocale(AppPreferences preferences) {
  appLocale._preferences = preferences;
  final saved = _ofApp(preferences.getString(_key));
  if (saved != null) appLocale._set(saved);
}

/// Gives the root of the app the language that the user chose, and rebuilds
/// the root when the choice changes.
class AppLocaleScope extends InheritedNotifier<AppLocaleController> {
  /// Creates the scope of [notifier] around [child].
  const AppLocaleScope({
    required AppLocaleController super.notifier,
    required super.child,
    super.key,
  });

  /// The language that the user chose, or `null` to follow the device; the
  /// widget of [context] rebuilds when the choice changes.
  static Locale? of(BuildContext context) => context
      .dependOnInheritedWidgetOfExactType<AppLocaleScope>()!
      .notifier!
      .value;
}

  NotificationTap? get launchTap => switch (_launchTap) {

    _ => null,
  };

  /// with the data of the notification: a broadcast stream, the same for
  /// the life of the app. It leaves out the taps on the notifications of an
  /// owner, which [tapsOf] gives, and those with a negative id: the
  /// notification of an owner whose data the provider could not read.
  late final Stream<NotificationTap> taps = _taps.stream.where(_isOfApp);

  /// Tells of each tap on a notification whose owner is [owner], as it is
  /// under [notificationOwnerKey] in its data: a broadcast stream.
  Stream<NotificationTap> tapsOf(String owner) =>

  /// app, or `null`.

    final tap? when _ownerOf(tap) == owner => tap,
    _ => null,
  };

  /// the taps, and asks whether the app may show notifications.

  /// with the service that the app has from then on: `initNotifications()`
  /// does so in a test of the next launch of the app, and a test gives it a
  /// service of its own.
  ///

    if (!_started.isCompleted) _started.complete();

  /// question explains itself. Where the platform has no question, the

  /// preferences fail to save that the app asked, the future completes with
  /// their error: [permission] is up to date by then, but the next launch
  /// of the app takes it that the app has not asked.
  Future<NotificationPermission> request() =>

  /// Opens the settings of the system for the notifications of the app.
  Future<void> openSettings() async => (await _ready()).openSettings();

  /// owner under [notificationOwnerKey] in its data, which takes a negative

  Future<void> show(AppNotification notification) async {
    _check(notification);
    await (await _ready()).show(notification);
  }

  /// Shows [notification] at about [at], not to the minute, also when the
  /// app is closed then. Its future fails with an [ArgumentError] when [at]
  /// is not in the future, and for an id that [show] does not take.

  }) async {

      throw ArgumentError.value(at, 'at', 'The time is not in the future');

  }

  Future<void> cancel(int id) async => (await _ready()).cancel(id);

  /// Removes every notification of the app, shown or scheduled, those of an
  /// owner too.
  Future<void> cancelAll() async => (await _ready()).cancelAll();

  /// The notifications that are scheduled and not shown yet, those of an
  /// owner too.
  Future<List<AppNotification>> scheduled() async =>
      (await _ready()).scheduled();

  /// The service, once the app has started for the first time.
  Future<NotificationsService> _ready() async {
    if (!_started.isCompleted) await _started.future;
    return _service!;
  }

  Future<NotificationPermission> _ask() async {
    final service = await _ready();
    if (await service.areEnabled()) {
      _enabled = true;
      _update();
      return _permission.value;
    }
    await service.request();
    _asked = true;
    _enabled = await service.areEnabled();
    _update();
    await _preferences?.setBool(_askedKey, true);
    return _permission.value;
  }

  /// Asks the service whether the app may show notifications.
  Future<void> _refresh() async {
    _enabled = await _service!.areEnabled();
    _update();
  }

  /// Takes that the app asked from [preferences], and keeps it as it is when
  /// they have nothing saved. It keeps [preferences] for the next request.
  void _restore(AppPreferences preferences) {
    _preferences = preferences;
    _asked = preferences.getBool(_askedKey) ?? _asked;
    _update();
  }

  void _update() => _permission.value = _enabled
      ? NotificationPermission.granted
      : _asked
      ? NotificationPermission.denied
      : NotificationPermission.notAsked;

  static String? _ownerOf(NotificationTap tap) =>
      tap.data[notificationOwnerKey];

  /// Whether [tap] is on a notification of the app: one without an owner,
  /// whose id is not negative.
  static bool _isOfApp(NotificationTap tap) =>
      tap.id >= 0 && _ownerOf(tap) == null;

  /// Throws an [ArgumentError] for an id of [notification] that the app

    if (id < _smallestId || id > _largestId) {

    }
    if (id >= 0 && owned) {
      throw ArgumentError.value(
        id,
        'id',
        'A notification with an owner has a negative id',
      );
    }
  }
}

/// The data in [payload], the JSON of a map of texts, as the app gives the
/// plugin a notification, or none for anything else.
Map<String, String> _dataOf(String? payload) {
  if (payload == null || payload.isEmpty) return const {};
  try {
    final decoded = jsonDecode(payload);
    if (decoded is Map<String, Object?> &&
        decoded.values.every((value) => value is String)) {
      return decoded.cast<String, String>();
    }
  } on FormatException {
    // A payload that the app did not write.
  }
  return const {};
}

final class LocalNotificationsService implements NotificationsService {

  final FlutterLocalNotificationsPlugin _plugin;
  final StreamController<NotificationTap> _taps;

  @override
  final NotificationTap? launchTap;

  @override
  Stream<NotificationTap> get taps => _taps.stream;

  AndroidFlutterLocalNotificationsPlugin? get _android => _plugin
      .resolvePlatformSpecificImplementation<
        AndroidFlutterLocalNotificationsPlugin
      >();

  IOSFlutterLocalNotificationsPlugin? get _ios => _plugin
      .resolvePlatformSpecificImplementation<
        IOSFlutterLocalNotificationsPlugin
      >();

  @override
  Future<bool> areEnabled() async {
    if (_android case final android?) {
      return await android.areNotificationsEnabled() ?? false;
    }
    final permissions = await _ios?.checkPermissions();
    return permissions?.isEnabled ?? false;
  }

  @override
  Future<void> request() async {
    final question = _Question(WidgetsBinding.instance.lifecycleState);
    WidgetsBinding.instance.addObserver(question);
    final bool allowed;
    try {
      allowed = await _ask();
    } finally {
      WidgetsBinding.instance.removeObserver(question);
    }
    if (!allowed && !question.shown) await openSettings();
  }

  /// Asks the system for the permission, and returns whether the app may
  /// show notifications then.
  Future<bool> _ask() async {
    if (_android case final android?) {
      return await android.requestNotificationsPermission() ?? false;
    }
    final allowed = await _ios?.requestPermissions(
      alert: true,
      badge: true,
      sound: true,
    );
    return allowed ?? false;
  }

  @override
  Future<void> openSettings() async {
    await _plugin.openAppNotificationSettings();
  }

  @override
  Future<void> show(AppNotification notification) async {
    // Android keeps the alarm of a scheduled notification when one with its
    // id is shown, so it would show again later.
    final pending = await _plugin.pendingNotificationRequests();
    if (pending.any((request) => request.id == notification.id)) {
      await _plugin.cancel(id: notification.id);
    }
    await _plugin.show(
      id: notification.id,
      title: notification.title,
      body: notification.body,
      notificationDetails: _details,
      payload: jsonEncode(notification.data),
    );
  }

      _plugin.zonedSchedule(

        title: notification.title,
        body: notification.body,
        scheduledDate: tz.TZDateTime.from(at, tz.UTC),
        notificationDetails: _details,
        androidScheduleMode: AndroidScheduleMode.inexactAllowWhileIdle,
        payload: jsonEncode(notification.data),
      );

  @override
  Future<void> cancel(int id) => _plugin.cancel(id: id);

  @override
  Future<void> cancelAll() => _plugin.cancelAll();

  @override
  Future<List<AppNotification>> scheduled() async => [
    for (final request in await _plugin.pendingNotificationRequests())
      AppNotification(
        id: request.id,
        title: request.title ?? '',
        body: request.body,
        data: _dataOf(request.payload),
      ),
  ];
}

/// The settings of the app that are no secret, with the shared_preferences
/// package, which keeps them in DataStore on Android and in `UserDefaults`
/// on iOS.
///
/// Neither is encrypted, and a backup of the device carries them: never
/// store a token, a password, an API key or an encryption key in the
/// preferences.
///
/// A number is read only as the type that it was saved as: `getDouble`
/// returns `null` for a key with an `int`, and `getInt` for a key with a
/// `double`, a whole number too.
///
/// A write puts its value into memory before it saves it. If the platform
/// refuses the save, as Android does for a text that starts with the prefix
/// that shared_preferences marks a list with, the write fails, and the
/// reads of this run return the value all the same. The next launch reads
/// what was saved before the write, or nothing if the key had no value.
final class SharedAppPreferences implements AppPreferences {
  /// Creates the preferences on [SharedPreferencesWithCache], which has
  /// read what is saved.
  SharedAppPreferences(this._preferences);

  final SharedPreferencesWithCache _preferences;

  @override
  String? getString(String key) => _read<String>(key);

  @override
  bool? getBool(String key) => _read<bool>(key);

  @override
  int? getInt(String key) => _read<int>(key);

  @override
  double? getDouble(String key) => _read<double>(key);

  @override
  List<String>? getStringList(String key) => switch (_preferences.get(key)) {
    final List<Object?> list => _textsOf(list),
    _ => null,
  };

  @override
  Future<void> setString(String key, String value) =>
      _preferences.setString(key, value);

  @override
  Future<void> setBool(String key, bool value) =>
      _preferences.setBool(key, value);

  @override
  Future<void> setInt(String key, int value) => _preferences.setInt(key, value);

  @override
  Future<void> setDouble(String key, double value) =>
      _preferences.setDouble(key, value);

  /// shared_preferences keeps the list that it is given, so it gets a copy.
  @override
  Future<void> setStringList(String key, List<String> value) =>
      _preferences.setStringList(key, List.of(value));

  @override
  Future<void> remove(String key) => _preferences.remove(key);

  /// The value of [key] if it is a [T], or `null`. The reads of
  /// shared_preferences cast the value instead, and throw on a value of
  /// another type.
  T? _read<T>(String key) => switch (_preferences.get(key)) {
    final T value => value,
    _ => null,
  };

  /// A copy of [list] as a list of texts, or `null` if an item of it is no
  /// text.
  ///
  /// When the preferences are opened, the platform returns a list in a form
  /// of its own: a list of objects on iOS, and on Android a list that casts
  /// each item to a text as it is read, and so throws on an item that is
  /// none. Cast to objects, either gives its items as they are.
  static List<String>? _textsOf(List<Object?> list) {
    final items = list.cast<Object?>();
    return items.every((item) => item is String)
        ? List<String>.from(items)
        : null;
  }

  @override

  /// location, and while it shows its error screen in place of the whole
  /// stack, as for a location that no route matches.
  ///

  /// `GoRouter.push` would keep the error screen and never complete, or

  /// `GoRouter.pushReplacement` throws for want of a page. So [push] and

  /// the pages of its chain, in place of the error screen, and such a push
  /// completes with `null`. An error screen that a push showed over a page
  /// is a page of go_router, which pushes over it and replaces it like any
  /// other.
  bool get _withoutPage =>
      config.routerDelegate.currentConfiguration.matches.isEmpty;

  /// Follows the pages of go_router, whose delegate notifies its listeners
  /// of each change of them: keeps each push completing with the value of
  /// its page, and tells the listeners of the screen about the page on top.
  void _pagesChanged() {
    _keepPushes();
    _showScreen();
  }

  /// Lets each push complete with the value that its page returns when it
  /// closes, whatever completer go_router gives the page.
  ///
  /// go_router completes a push with the completer that it gives the page
  /// it pushed, which the page completes when it closes. When go_router
  /// shows its pages anew from their encoded form, as on [GoRouter.refresh],
  /// such as when its `refreshListenable` notifies, it gives each pushed
  /// page a new completer, though the page keeps its key and its location,
  /// so the push would never complete
  /// (https://github.com/flutter/flutter/issues/128122). So when a page
  /// comes back at its location with another completer, the router passes

  /// main navigation that is not selected keeps its pages as they were, so
  /// a page that comes back with its branch passes on its value as before.

  /// and can go.
  void _keepPushes() {
    final pushed = {
      for (final page in _pushedPages(
        config.routerDelegate.currentConfiguration.matches,
      ))
        page.pageKey: page,
    };
    for (final page in pushed.values) {
      final before = _pushed[page.pageKey];
      if (before == null ||
          before.completer == page.completer ||
          before.matches.uri != page.matches.uri) {
        continue;
      }
      final push = _pushes[before.completer] ?? before.completer;
      _pushes[page.completer] = push;
      unawaited(
        page.completer.future.then((value) {
          if (!push.isCompleted) push.complete(value);
        }),
      );
    }
    _pushed = pushed;
  }

  /// The pages that pushes showed among [matches], in the stacks of the
  /// main navigation too.
  static Iterable<ImperativeRouteMatch> _pushedPages(
    List<RouteMatchBase> matches,
  ) sync* {
    for (final match in matches) {
      if (match is ImperativeRouteMatch) yield match;
      if (match is ShellRouteMatch) yield* _pushedPages(match.matches);
    }
  }

  /// page comes on top, or the page on top shows another location.
  ///
  /// The delegate of go_router notifies its listeners once for each change
  /// of its configuration, a switch of branches included, and may do so
  /// again without a change of the page on top, which the listeners of the
  /// screen do not hear of twice. The location of a pushed page is its own,
  /// as that of the configuration leaves pushed pages out. The error screen
  /// of go_router has no route match, or, for a location pushed in error, a
  /// route without a name.
  void _showScreen() {

    }
  }

/// What the widget asks the system for on a screen in [theme].
Future<SystemUiOverlayStyle> _styleIn(
  WidgetTester tester,
  ThemeData theme,
) async {
  await tester.pumpWidget(
    MaterialApp(
      theme: theme,
      home: const StatusBarIcons(child: Text('A screen')),
    ),
  );
  return tester
      .widget<AnnotatedRegion<SystemUiOverlayStyle>>(
        find.descendant(
          of: find.byType(StatusBarIcons),
          matching: find.byType(AnnotatedRegion<SystemUiOverlayStyle>),
        ),
      )
      .value;
}
