# AGENTS.md

This guide tells coding agents what the code of this Flutter app does not show. Setup that needs a person or an account is in [README.md](README.md). When you change what a section describes, change the section too.

## App entry

The app is plain Flutter code that nothing regenerates. Change it by hand, unless a section below says what writes a file.

- `main()` in `lib/main.dart` initializes the binding, awaits `bootstrap()` and calls `runApp()`, in this order. Start-up code goes into `bootstrap()`.
- `bootstrap()` in `lib/bootstrap.dart` runs before the first frame, in four phases: what must come before anything else, then the platform services, then the services of the app, then what needs them. Put a new statement into its phase, and import neither `package:flutter/material.dart` nor `package:flutter/cupertino.dart` there.
- Put code that features share into `lib/core/<concern>/`, one directory for each concern. Put a feature, with its screens and their state, into `lib/features/<feature>/`.
- The root of the app asks the system for the icons of the status bar that suit the theme, around every screen, with `StatusBarIcons` of `lib/core/app/status_bar_icons.dart`: dark icons on a light theme, light ones on a dark theme. A screen without an app bar needs no `AnnotatedRegion` for them. Add one only to a screen whose top has another brightness than the theme, such as a picture behind the status bar.
- The app has the flavors `dev`, `staging` and `prod`. A `flutter` command without `--flavor` builds `dev`, in release mode too, so a build for a store takes `--flavor prod`. Code reads the flavor from `appFlavor` of `package:flutter/services.dart`. The app has one entry: add no `main_<flavor>.dart`.

After a change, run:

```bash
dart format lib test
flutter analyze
flutter test
```

Format only `lib/` and `test/`: `dart format .` also formats what Flutter writes into `build/`. The app as generated is formatted, `flutter analyze` finds no issue in it and `flutter test` passes.

- `App` in `lib/app.dart` is the root widget of the app and creates its one `MaterialApp`. Create no other in `lib/`: every screen is below it.
- The `theme`, `darkTheme`, `themeMode`, `locale` and localizations of the app go into the arguments of that `MaterialApp`.
- Tests mirror `lib/`: the test of `lib/<path>.dart` is `test/<path>_test.dart`.
- The app has only an Android and an iOS project, in `android/` and `ios/`.
- The entitlements of the iOS app, such as Push Notifications or Sign in with Apple, are in `ios/Runner/Runner.entitlements`. Every build configuration of the Runner target signs with this file, even while it is empty. The Signing & Capabilities tab of Xcode edits the same file.
- Each flavor is in `productFlavors` of `android/app/build.gradle.kts`, and on iOS in `ios/Runner.xcodeproj/xcshareddata/xcschemes/<flavor>.xcscheme` and in the build configurations `Debug-<flavor>`, `Profile-<flavor>` and `Release-<flavor>` of `ios/Runner.xcodeproj/project.pbxproj`. Change both places together. A new setting of the Runner target goes into each of its twelve build configurations.

## Authentication

- `appSession` in `lib/core/auth/app_session.dart` tells who uses the app, and knows it before the first frame. Its `value` is a `SignedOutSession`, an `AnonymousSession` or an `AccountSession`, and `appSession.value.uid` is the id of the user. Sign in, sign up, sign out and delete the account only through `appSession`. The app has one, so create no other `AppSessionController`.
- A call of `appSession` fails only with an `AuthFailure`. Catch it and show a text of the app for its `reason`. Show its `developerHint` in debug mode only. After `recentSignInRequired`, tell the user to sign out and sign in again.
- `authMode` in that file says who may use the app without an account. It gates nothing on its own. What keeps a user from a screen is a guard of the routes. One that reads `appSession.allowsApp` stands before the whole app, and one that reads `appSession.hasAccount` stands only before the routes that it lists, the screens that need an account. In an app without such a guard every screen is open, whatever the mode, and that includes a screen that needs an account. A screen does not redirect itself.
- When an anonymous user signs in to an account that exists already, `takeGuestData()` in `lib/core/auth/guest_data.dart` says what moves from that user to the account. As generated it moves nothing: write there what the app keeps under the id of a user. Call no method of `appSession` in it, since the sign-in that calls it would wait for that call.
- `appSignInMethods` in `lib/core/auth/sign_in_methods.dart` lists the ways to sign in with an identity provider that the modules of the app add, and is empty without them. A screen of sign-in shows a button for each `SignInMethod` whose `isAvailable` is true, with its `label(context)` and its `icon`.
- On a tap, the state of the screen awaits `credential()` of the way to sign in and gives the credential to `appSession.signInWith`. `credential()` returns `null` when the user closed the sheet of the identity provider, which is no failure: the screen goes back to how it was. Call `credential()` from the state of a screen, never within a call of `appSession`.
- `appSession.signInWith` gives an anonymous user the identity with the same id, or signs in to the account that has the identity already, and `takeGuestData()` moves what the anonymous user had. `appSession.deleteAccount()` asks a way to sign in with `revokesOnDeletion` for a credential again itself, and deletes nothing when the user closes its sheet.
- `AccountSession.issuers` lists the identity providers of an account, each the `issuer` of a `SignInMethod`.
- A new provider implements `AuthService` of `lib/core/auth/auth_service.dart`, and only the file of that implementation imports it. The code of the app imports `lib/core/auth/app_session.dart`, which exports `AuthFailure`, `AuthFailureReason`, `SignInCredential` and `IdTokenCredential`, and calls neither `initAuth()` nor `createAuthService()` nor `appSession.start()`.

With `firebase_auth`:

- `FirebaseAuthService` in `lib/core/auth/firebase_auth_service.dart` implements `AuthService` on `FirebaseAuth.instance`. In `lib/`, only that file imports the package: other code signs in through `appSession`.
- That file gives each code of Firebase its `AuthFailureReason`, in `_failureOf()`. A code that it does not know becomes `unknown`: give it a reason there.
- The ways to sign in are enabled in the Firebase project, not in the code. A call that fails with `notConfigured` tells in its `developerHint` how, and so does the section Firebase Authentication of `README.md`.
- `tool/enable_firebase_sign_in.dart` enables them with the Firebase CLI. It changes the Firebase project and needs a Firebase account: run it only when asked.

## Firebase

- `bootstrap()` initializes Firebase with `firebaseOptionsOfFlavor` of `lib/firebase_options_of_flavor.dart`, by the flavor of the build. `lib/firebase_options_dev.dart`, `lib/firebase_options_staging.dart` and `lib/firebase_options_prod.dart` are placeholders until `tool/configure_firebase.dart` writes them, and a build of such a flavor stops at start-up with an `UnsupportedError`. Do not write them by hand.
- `tool/configure_firebase.dart` needs a Firebase account and a project: run it only when asked, with the command of the section Firebase of `README.md`. Do not run `flutterfire configure`, whose files no flavor reads.
- A test that runs `main()` or `bootstrap()` starts Firebase with the options of the flavor of the test, `dev`, which needs a mock of its platform side. Prefer a test of a widget, which needs neither.

# my_app

A new Flutter project.

Generated with [Say My Frame](https://doc.saymyframe.com).

## Flavors

The app has three flavors, which install next to each other on a device, each under an id of its own:

| Flavor | Android application id | iOS bundle id |
| --- | --- | --- |
| `dev` | `com.example.my_app.dev` | `com.example.my-app.dev` |
| `staging` | `com.example.my_app.staging` | `com.example.my-app.staging` |
| `prod` | `com.example.my_app` | `com.example.my-app` |

A `flutter` command without `--flavor` builds `dev`, because `default-flavor` in `pubspec.yaml` says so. That holds in release mode too: `flutter build appbundle` and `flutter build ipa` build a release of `dev`, under its id. For a store, name the flavor:

```bash
flutter run --flavor staging
flutter build appbundle --flavor prod
flutter build ipa --flavor prod
```

Code reads the flavor from `appFlavor` of `package:flutter/services.dart`. A service that knows your app by its id, such as a store or a push provider, knows each flavor as an app of its own, so you repeat a step of its setup for each flavor that needs it.

## Flavors in the native projects

Each flavor is in two places, so change both when you rename, add or remove one:

- Android: `productFlavors` in `android/app/build.gradle.kts`, with its id suffix and its name on the device.
- iOS: `ios/Runner.xcodeproj/xcshareddata/xcschemes/<flavor>.xcscheme`, and the build configurations `Debug-<flavor>`, `Profile-<flavor>` and `Release-<flavor>` in each configuration list of `ios/Runner.xcodeproj/project.pbxproj`. The name of a flavor has no hyphen, since Flutter splits the name of a configuration on it.

In Xcode, select the scheme of a flavor, not `Runner`, which builds the id and the name of `prod`. A scheme sets only the id and the name. `appFlavor` comes from `ios/Flutter/Generated.xcconfig`, which the last `flutter` command wrote, so run `flutter build ios --config-only --flavor <flavor>` before you run the scheme from Xcode.

## Firebase

The app uses [Firebase](https://firebase.google.com/docs/flutter/setup) through `firebase_core`: `bootstrap()` initializes it with `firebaseOptionsOfFlavor` of `lib/firebase_options_of_flavor.dart`, which takes the options of the flavor of the build from `lib/firebase_options_<flavor>.dart`. A flavor may have a Firebase project of its own or share one. Until a flavor is configured, its options are a placeholder, and a build of it stops at start-up with an `UnsupportedError` that gives the command below.

`smf create` configures `dev`. To configure a flavor, or to configure it again, such as for another project or on another machine, run in the directory of the app:

```bash
dart pub global activate flutterfire_cli 1.4.1
firebase login
dart tool/configure_firebase.dart staging --project=<id>
```

Use this script rather than `flutterfire configure`, which would write files that no flavor reads. It registers the Android and iOS apps of the flavor in the project and writes its options, `android/app/src/<flavor>/google-services.json`, `firebase.json` and, on macOS, `ios/flavors/<flavor>/GoogleService-Info.plist`. Commit them. In a terminal you may leave `--project` out, and flutterfire then asks. Other arguments, such as `--account=<email>`, go to flutterfire. The ids of each flavor are at the top of the script: if you change them in the projects, change them there too.

Once one flavor is configured, a build of a flavor that is not fails on Android, with `File google-services.json is missing`. On iOS it builds and stops at start-up, but with Crashlytics it fails in the build too (see that section).

A run from Xcode reads the flavor from `ios/Flutter/Generated.xcconfig`, not from the scheme. After a fresh `flutter pub get` that file has no flavor, so `appFlavor` is `null` under any scheme and `firebaseOptionsOfFlavor` throws an `UnsupportedError`. Run `flutter build ios --config-only --flavor <flavor>` once before you run the app from Xcode.

The script changes the Xcode project only on macOS, and adds a build phase that runs `flutterfire` from `~/.pub-cache/bin`. So every Mac that builds the app for iOS needs the FlutterFire CLI activated, flutterfire_cli 1.4.1 or a later 1.x; if `dart pub global list` shows one already, skip its activation above. flutterfire needs the [Firebase CLI](https://firebase.google.com/docs/cli).

## Firebase Authentication

The app signs in with [Firebase Authentication](https://firebase.google.com/docs/auth) through `firebase_auth`: `lib/core/auth/firebase_auth_service.dart` implements the sign-in service of the app on it.

The ways to sign in are enabled in the Firebase project, not in the code: Email/Password in every mode of the app, and Anonymous when the mode of the app is `anonymous` (see the section Sign-in). Until they are enabled, signing in and signing up fail with the reason `notConfigured`, and the `developerHint` of the failure tells how to enable them. In the mode `anonymous`, the app also starts without a user.

`smf create` asks to enable them right after `flutterfire configure` has configured the app. To enable them later, for another Firebase project, or after you changed the mode of the app to `anonymous`, run in the directory of the app:

```bash
dart tool/enable_firebase_sign_in.dart
```

The script reads the project from `firebase.json`, where `flutterfire configure` wrote it, and the mode from `authMode` in `lib/core/auth/app_session.dart`, and says which project and which mode it enables them for. It enables the methods with `firebase deploy --only auth` of the [Firebase CLI](https://firebase.google.com/docs/cli) 15.34.0 or later. It never disables a method, and it changes no file of the app. `--project <id>` names another project, and the other arguments go to the Firebase CLI as they are. The script runs the Firebase CLI in a temporary directory, where an account that `firebase login:use` chose for the directory of the app does not apply. To name the account:

```bash
dart tool/enable_firebase_sign_in.dart --account <email>
```

You can also enable the methods in the Firebase console, under [Authentication > Sign-in method](https://console.firebase.google.com/project/_/authentication/providers) in the project that the app is configured for.

Firebase sends the message with which a user sets a new password from a template of the project: [Authentication > Templates](https://console.firebase.google.com/project/_/authentication/emails).

When an anonymous user signs in to an account that exists already, the anonymous user stays in the project, and nobody can sign in as that user again. A project that is upgraded to Firebase Authentication with Identity Platform can delete anonymous users that are older than 30 days automatically. See [Automatic clean-up](https://firebase.google.com/docs/auth/android/anonymous-auth#auto-cleanup) in the documentation of Firebase.

## Sign-in

The sign-in mode of the app says who may use it without an account. This app was generated in the mode `required`: `authMode` in `lib/core/auth/app_session.dart` is `AuthMode.required`.

- In `required`, nobody may. `appSession.allowsApp` is true only for a user who signed in to an account.
- In `guest`, everyone may. The app has no user until someone signs in, and `appSession.allowsApp` is always true.
- In `anonymous`, everyone may, as an anonymous user that the app signs in itself when it starts. Code then has the id of a user, `appSession.value.uid`, before anyone has an account, and signing up gives that same user the account. The app waits up to 3 seconds for that sign-in. When it fails or takes longer, the app starts without a user and tries again each time the user comes back to it. `appSession.allowsApp` is always true.

The mode keeps nobody from a screen on its own. A guard of the routes does. One that reads `appSession.allowsApp` stands before the whole app. One that reads `appSession.hasAccount` stands only before the routes that it lists, the screens that need an account. A module with the screens of sign-in declares such guards. If the app was generated without such a module, every screen is open in every mode, `required` too, until you write a guard of your own that reads `appSession.allowsApp`. A screen that a module made for users with an account is open then too. A warning named each such route when the app was generated, and a guard of your own for them reads `appSession.hasAccount`.

To change the mode, change the value of `authMode`. The provider of sign-in has to allow what the new mode needs, such as anonymous users for the mode `anonymous`. Where the provider has a section in this README, that section tells how.

When an anonymous user signs in to an account that exists already, the user of the app changes, and what the app keeps under the id of the anonymous user would be left behind. `takeGuestData()` in `lib/core/auth/guest_data.dart` says what moves to the account. As generated it moves nothing.

Besides an email address and a password, the app signs in with no identity provider, such as the account of a user at another service. Such a way to sign in is a `SignInMethod` of `appSignInMethods` in `lib/core/auth/sign_in_methods.dart`, which the module of the way to sign in adds.

/// The mode of this app, which was chosen when the app was generated.

/// The session of the app: who uses it, known before the first frame, and
/// the way to sign in, up and out.
///
/// Its `value` is the [AppSession], and it tells its listeners when that
/// changes. A widget follows it with a `ValueListenableBuilder`.
final appSession = AppSessionController(
  mode: authMode,
  takeGuestData: takeGuestData,
);

/// Keeps the session of the app up to date with the service of the provider
/// of sign-in, and signs in, up and out through that service. The app has
/// one, [appSession].
///
/// Every call here fails only with an [AuthFailure], whose reason the app
/// shows in a text of its own. An error of another kind becomes a failure
/// with the reason [AuthFailureReason.unknown] and the error as its
/// [AuthFailure.developerHint].
///
/// The calls run one after another, in the order they were made, and none
/// runs next to an anonymous sign-in that is on its way. So the user of the
/// app is the result of the call that was made last. In the mode
/// [AuthMode.anonymous], a call that leaves nobody signed in is followed by
/// an anonymous sign-in.
final class AppSessionController extends ChangeNotifier
    implements ValueListenable<AppSession> {
  /// Creates a controller for an app in [mode]. The app creates
  /// [appSession] and no other. A test creates one to see another mode, or
  /// a shorter [anonymousWait], and disposes of it.
  AppSessionController({
    required this.mode,
    required this.takeGuestData,
    this.anonymousWait = const Duration(seconds: 3),
  });

  /// Who may use the app without an account.
  final AuthMode mode;

  /// Takes what an anonymous user has before that user signs in to an
  /// account: `takeGuestData` of `guest_data.dart`.
  final Future<GiveGuestData?> Function(String guestUid) takeGuestData;

  /// How long the app waits for its anonymous user when it starts, and
  /// after a sign-out or the deletion of an account, in the mode
  /// [AuthMode.anonymous].
  final Duration anonymousWait;

  AuthService? _service;
  StreamSubscription<AuthUser?>? _userChanges;
  AppSession _session = const SignedOutSession();
  bool _disposed = false;

  /// Whether the app has started for the first time.
  bool _started = false;

  /// Completes at the first start. Only the first call made before it waits
  /// for it, and each later call waits for the call before it. That call
  /// creates it, so the start completes it in the zone of the call: created
  /// with the controller, it would complete in a microtask of the zone that
  /// read [appSession] first, which may run none any more, as the fake time
  /// of a widget test that is over before a later test starts the app in
  /// real time.
  Completer<void>? _untilStarted;

  /// The call that was made last, while a call is on its way: the next one
  /// waits for it. It is `null` when none is, and a call then awaits
  /// nothing. A future that completed in another zone would hold the call
  /// back in a widget test, where the app starts in real time and the test
  /// goes on in fake time.
  Future<void>? _lastCall;

  /// The anonymous sign-ins that are on their way, each by its service, so
  /// that the app starts no second one next to it.
  final Map<AuthService, Future<void>> _anonymousSignIns = Map.identity();

  /// Tells when the user comes back to the app, in the mode
  /// [AuthMode.anonymous].
  _ResumeObserver? _observer;

  /// Who uses the app.
  @override
  AppSession get value => _session;

  /// Whether the user may see the app: always in the modes [AuthMode.guest]
  /// and [AuthMode.anonymous], and with an account in the mode
  /// [AuthMode.required].
  ///
  /// It is computed from the session each time it is read, and its
  /// listeners are those of the session. So when the session changes, a
  /// listener finds this value and [hasAccount] both up to date, whichever
  /// of the two it listens to. A listener is also called for a change of
  /// the session that leaves this value as it was.
  late final ValueListenable<bool> allowsApp = _SessionFlag(
    this,
    (session) => mode != AuthMode.required || session is AccountSession,
  );

  /// Whether the user of an account is signed in, which an anonymous user
  /// is not. It follows the session as [allowsApp] does.
  late final ValueListenable<bool> hasAccount = _SessionFlag(
    this,
    (session) => session is AccountSession,
  );

  /// Starts the session with [service]: takes the user who is signed in on
  /// this device, and follows the changes that the service tells of.
  ///
  /// `initAuth()` calls it in `bootstrap()`, so the session is known before
  /// the first frame. In the mode [AuthMode.anonymous], an app without a
  /// user signs in anonymously here and waits for that for at most
  /// [anonymousWait]. When the sign-in fails or takes longer, the app
  /// starts without a user. A sign-in that takes longer still becomes the
  /// session when it comes, and the app tries again each time the user
  /// comes back to it.
  ///
  /// A call made before the first start waits for it: [signIn], [signUp],
  /// [signInWith], [sendPasswordReset], [signOut] and [deleteAccount]. Such
  /// calls run in
  /// their order once the start has the user, and the future of this start
  /// completes after them, but waits for no call that is made while it
  /// runs. The mocks of the tests of an app use this: a call of [signUp]
  /// made before `bootstrap()`, which nothing awaits, gives the app an
  /// account before its first frame. A test makes such a call outside the
  /// body of a test, as in a `setUpAll`: made in the body of a widget
  /// test, it waits in the fake time of that body, and a start that runs in
  /// real time never completes.
  ///
  /// It may be called again, with the service that the session has from
  /// then on: `initAuth()` does so in a test of the next launch of the app,
  /// and a test gives it a service of its own. Such a start takes its turn
  /// after the calls that are on their way.
  Future<void> start(AuthService service) async {
    // The calls that were made before this start. The first start lets
    // them run once it has the user, and a later one waits for them.
    final earlier = _lastCall;
    final first = !_started;
    if (!first) await earlier;
    unawaited(_userChanges?.cancel());
    _service = service;
    _userChanges = service.userChanges.listen(
      (_) => _sync(),
      onError: (Object error, StackTrace stackTrace) => _report(
        error,
        stackTrace,
        'while following the user of the provider of sign-in',
      ),
    );
    _sync();
    if (mode == AuthMode.anonymous) {
      if (_observer == null) {
        final observer = _observer = _ResumeObserver(_retry);
        WidgetsBinding.instance.addObserver(observer);
      }
      await _signInAnonymously();
    }
    if (!_started) {
      _started = true;
      _untilStarted?.complete();
    }
    if (first) await earlier;
  }

  /// Signs in to the account of [email] with [password].
  ///
  /// An anonymous user becomes the user of that account, and what the
  /// anonymous user had moves to the account as `takeGuestData` says.
  Future<void> signIn({required String email, required String password}) =>
      _call(
        (service) =>
            _toAccount(() => service.signIn(email: email, password: password)),
      );

  /// Creates an account for [email] with [password] and signs in to it.
  ///
  /// An anonymous user gets the account and keeps the id, so everything
  /// that the user had stays.
  Future<void> signUp({required String email, required String password}) =>
      _call(
        (service) => _session is AnonymousSession
            ? service.linkPassword(email: email, password: password)
            : service.signUp(email: email, password: password),
      );

  /// Signs in with [credential], which a way to sign in of
  /// `appSignInMethods` got from an identity provider.
  ///
  /// An anonymous user gets the identity of the credential and keeps the id,
  /// so everything that the user had stays. When that identity belongs to
  /// another user already, or its email address has an account that signs
  /// in in another way, the anonymous user signs in to that account
  /// instead, or the call fails with
  /// [AuthFailureReason.accountExistsWithOtherMethod], as the backend of the
  /// provider decides. What the anonymous user had moves to the account as
  /// `takeGuestData` says, as with [signIn].
  Future<void> signInWith(SignInCredential credential) => _call((
    service,
  ) async {
    if (_session is AnonymousSession) {
      try {
        await service.linkWith(credential);
        return;
      } on AuthFailure catch (failure) {
        if (failure.reason != AuthFailureReason.credentialInUse &&
            failure.reason != AuthFailureReason.accountExistsWithOtherMethod) {
          rethrow;
        }
      }
    }
    await _toAccount(() => service.signInWith(credential));
  });

  /// Sends the message with which the owner of the account of [email] sets
  /// a new password. It completes whether [email] has an account or not.
  Future<void> sendPasswordReset(String email) =>
      _call((service) => service.sendPasswordReset(email));

  /// Signs the user out. In the mode [AuthMode.anonymous], the app then
  /// signs in anonymously again, as when it starts.
  Future<void> signOut() =>
      _call((service) => service.signOut(), waitsForAnonymousUser: true);

  /// Deletes the user who is signed in. The app is then without a user, as
  /// after [signOut], and in the mode [AuthMode.anonymous] it signs in
  /// anonymously again.
  ///
  /// For an account that signs in with a way to sign in that
  /// `revokesOnDeletion` and is available on this platform, it first asks
  /// that way for a credential again, such as with the sheet of its
  /// identity provider, so that the provider of sign-in can revoke the
  /// tokens of the app. When the user closes the sheet, the call completes
  /// and deletes nothing, which is no failure.
  ///
  /// It may fail with [AuthFailureReason.recentSignInRequired]: the user
  /// then signs out, signs in again and repeats it.
  Future<void> deleteAccount() => _call((service) async {
    final revoking = _revokingMethod();
    if (revoking == null) {
      await service.deleteAccount();
      return;
    }
    final fresh = await revoking.credential();
    if (fresh != null) await service.deleteAccount(fresh: fresh);
  }, waitsForAnonymousUser: true);

  /// Stops following the service and the lifecycle of the app. A call that
  /// is on its way still ends as it would have, but tells no listener, and
  /// no anonymous sign-in follows it.
  @override
  void dispose() {
    _disposed = true;
    unawaited(_userChanges?.cancel());
    if (_observer case final observer?) {
      WidgetsBinding.instance.removeObserver(observer);
    }
    super.dispose();
  }

  /// The way to sign in of the account of the session that asks for a
  /// credential again before the account is deleted and is available on
  /// this platform, or `null` if it has none: the first of
  /// `appSignInMethods` that does.
  SignInMethod? _revokingMethod() => switch (_session) {
    AccountSession(:final issuers) =>
      appSignInMethods
          .where(
            (method) =>
                method.revokesOnDeletion &&
                method.isAvailable &&
                issuers.contains(method.issuer),
          )
          .firstOrNull,
    _ => null,
  };

  /// The user came back to the app. In the mode [AuthMode.anonymous], an
  /// app without a user then signs in anonymously again: as what follows
  /// every call, so this takes a turn among the calls with nothing else to
  /// do, and starts no anonymous sign-in next to a sign-in.
  void _retry() => unawaited(_call((service) async {}));

  /// Runs [call] with the service once the calls made before it are over,
  /// and not before the app has started for the first time.
  ///
  /// In the mode [AuthMode.anonymous], a call that leaves nobody signed in
  /// is followed by an anonymous sign-in. A call that
  /// [waitsForAnonymousUser], as a sign-out, completes once that sign-in is
  /// over or took too long, as the start does.
  Future<void> _call(
    Future<void> Function(AuthService service) call, {
    bool waitsForAnonymousUser = false,
  }) async {
    final earlier =
        _lastCall ??
        (_started ? null : (_untilStarted ??= Completer<void>()).future);
    final done = Completer<void>();
    final own = _lastCall = done.future;
    if (earlier != null) await earlier;
    try {
      await _guarded(call);
      final signIn = _signInAnonymously();
      if (waitsForAnonymousUser) await signIn;
    } finally {
      if (identical(_lastCall, own)) _lastCall = null;
      done.complete();
    }
  }

  /// Runs [call] with the service, once an anonymous sign-in that is on its
  /// way is over: of a call and a sign-in that run at the same time, the
  /// one that ended last would decide who the user is.
  ///
  /// Whatever [call] throws that is no [AuthFailure] becomes one, and the
  /// session has the user of the service when it is over, also when it
  /// failed. A call that failed does not wait for the anonymous sign-in
  /// that follows it, so that its failure is not late.
  Future<void> _guarded(Future<void> Function(AuthService service) call) async {
    final service = _service!;
    try {
      await _anonymousSignIns[service];
      await call(service);
    } on Object catch (error, stackTrace) {
      _sync();
      unawaited(_signInAnonymously());
      if (error is AuthFailure) rethrow;
      Error.throwWithStackTrace(
        AuthFailure(AuthFailureReason.unknown, developerHint: '$error'),
        stackTrace,
      );
    }
    _sync();
  }

  /// Signs in to an account with [signIn], in whichever way, and moves what
  /// an anonymous user had to that account, when it has another id.
  ///
  /// It takes the data before the sign-in, while the anonymous user is
  /// still signed in, and gives it once the user of another id has an
  /// account. If taking fails, the call fails and nothing has changed. If
  /// giving fails, the user is signed in already, so the call completes and
  /// the error is reported as an error of the app.
  Future<void> _toAccount(Future<void> Function() signIn) async {
    final guest = _session;
    final give = guest is AnonymousSession
        ? await takeGuestData(guest.uid)
        : null;
    await signIn();
    _sync();
    final account = _session;
    if (give == null ||
        account is! AccountSession ||
        account.uid == guest.uid) {
      return;
    }
    try {
      await give(account.uid);
    } on Object catch (error, stackTrace) {
      _report(
        error,
        stackTrace,

      FlutterError.reportError(
        FlutterErrorDetails(
          exception: error,
          stack: stackTrace,
          library: 'app session',
          context: ErrorDescription(during),
        ),
      );

  /// signed in, and waits for that for at most [anonymousWait].
  ///
  /// It never fails. A sign-in that takes longer goes on and becomes the
  /// session when it comes. One that fails leaves the app without a user
  /// until the next try, and in debug mode its error is printed.
  Future<void> _signInAnonymously() async {
    final service = _service!;
    if (_disposed ||
        mode != AuthMode.anonymous ||
        service.currentUser != null) {
      return;
    }
    final signIn = _anonymousSignIns[service] ??= _tryAnonymously(service)
        .whenComplete(() {
          _anonymousSignIns.remove(service);
          _sync();
        });
    await signIn.timeout(anonymousWait, onTimeout: () {});
  }

  Future<void> _tryAnonymously(AuthService service) async {
    try {
      await service.signInAnonymously();
    } on Object catch (error) {
      if (kDebugMode) {
        debugPrint(
          'The anonymous sign-in failed, so the app has no user: $error',
        );
      }
    }
  }

  /// Takes the user of the service as the session, and tells the listeners
  /// when that changes it, unless the session was disposed of.
  void _sync() {
    if (_disposed) return;
    final session = switch (_service!.currentUser) {
      null => const SignedOutSession(),
      AuthUser(isAnonymous: true, :final uid) => AnonymousSession(uid),
      AuthUser(:final uid, :final email, :final issuers) => AccountSession(
        uid,
        email: email,
        issuers: Set.unmodifiable(issuers),
      ),
    };
    if (session == _session) return;
    _session = session;
    notifyListeners();
  }

/// Why a call of sign-in failed.
enum AuthFailureReason {
  /// The email address and the password match no account. A wrong password
  /// and an address without an account are this one reason, so that nobody
  /// learns from the app which addresses have an account.
  ///
  /// It is also the reason of a [SignInCredential] that the provider
  /// refuses, such as one that expired or that was issued for another app,
  /// and of one of another user than the one whose account is deleted.
  invalidCredentials,

  /// The email address has an account already.
  emailInUse,

  /// The identity of a [SignInCredential] belongs to another user already,
  /// so [AuthService.linkWith] gives it to nobody else. The session then
  /// signs in to that user.
  credentialInUse,

  /// The email address of the identity of a [SignInCredential] has an
  /// account that signs in in another way, such as with a password. The
  /// user signs in that way.
  accountExistsWithOtherMethod,

  /// The provider takes no password as weak as this one.
  weakPassword,

  /// The text is no email address.
  invalidEmail,

  /// The account is disabled.
  userDisabled,

  /// Too many attempts: the provider takes no more for a while.
  tooManyAttempts,

  /// The device did not reach the provider.
  network,

  /// The call needs a user who signed in a short while ago, as the deletion
  /// of an account does: the user signs in again and repeats it.
  ///
  /// It is also the reason of a call for a user whose session has ended on
  /// the server. The service signs that user out on the device before it
  /// fails.
  recentSignInRequired,

  /// Sign-in is not set up at the provider, such as a way to sign in that
  /// is not enabled there. This is a mistake in the setup of the app, which
  /// [AuthFailure.developerHint] explains.
  notConfigured,

  /// Anything else. [AuthFailure.developerHint] has the error.
  unknown,
}

/// The accounts of the users of the app and the user of this device, as the
/// provider of sign-in keeps them.
///
/// The provider implements it. The code of the app does not call it: it
/// signs in through `appSession` of `app_session.dart`, which calls this
/// service and does what is the same with every provider.
///
/// Every implementation keeps to this, in every mode of the app, whatever
/// the provider generates for the mode:
/// - The service has [currentUser] from the moment it is created: the user
///   who was signed in on this device when the app last ran, without a
///   request to the server. The function that creates the service may be
///   called again, and the service that it returns then has the user who is
///   signed in now.
/// - When the future of a call completes, [currentUser] is the result of
///   the call. [userChanges] tells of every change of [currentUser], also
///   of one that no call here made, and when it tells of a user,
///   [currentUser] is that user.
/// - A call fails only with an [AuthFailure], and every call ends: when the
///   server does not answer, its future completes with
///   [AuthFailureReason.network].
/// - A call that fails leaves the user who is signed in as that user was:
///   an anonymous user stays signed in when [linkPassword] or [linkWith]
///   fails, and so does whoever is signed in when [signIn], [signUp] or
///   [signInWith] fails. The one exception is a call for a user whose
///   session has ended on the server.
/// - [linkPassword], [linkWith] and [deleteAccount] are calls for the user
///   who is signed in. Made when nobody is signed in, or when the session of
///   that user has ended on the server, such a call fails with
///   [AuthFailureReason.recentSignInRequired], and in the second case it
///   signs the user out on the device first.
/// - A [SignInCredential] whose identity provider the provider does not
///   take fails with [AuthFailureReason.notConfigured], with the issuer in
///   the [AuthFailure.developerHint].
abstract interface class AuthService {
  /// The user who is signed in on this device, or `null`.
  AuthUser? get currentUser;

  /// Tells of each change of [currentUser], once [currentUser] has changed:
  /// a broadcast stream. When it tells of a user, [currentUser] is that
  /// user. It may also tell of a user who has not changed.
  ///
  /// An error that it sends changes nothing: the session reports it as an
  /// error of the app and goes on listening.
  Stream<AuthUser?> get userChanges;

  /// Signs in to the account of [email] with [password].
  ///
  /// A wrong password and an address without an account both fail with
  /// [AuthFailureReason.invalidCredentials].
  ///

  /// user of another account: the user of this account then replaces that
  /// user on the device. When it fails, that user stays signed in.
  Future<void> signIn({required String email, required String password});

  /// Creates an account for [email] with [password] and signs in to it.
  ///
  /// For an address that has an account already, it fails with
  /// [AuthFailureReason.emailInUse] and changes nothing: that account keeps
  /// its password, and whoever is signed in stays signed in.
  ///
  /// It is also called while the user of another account is signed in, and
  /// the user of the new account then replaces that user on the device.
  /// For an anonymous user, the session calls [linkPassword] instead.
  Future<void> signUp({required String email, required String password});

  /// Gives the anonymous user who is signed in an account for [email] with
  /// [password]. The user keeps the [AuthUser.uid] and is no longer
  /// anonymous.
  ///
  /// For an address that has an account already, it fails with
  /// [AuthFailureReason.emailInUse] and changes nothing: the anonymous user
  /// stays signed in, with the same id.
  Future<void> linkPassword({required String email, required String password});

  /// Signs in with [credential], which a way to sign in got from an
  /// identity provider: to the user of its identity, whom it creates when
  /// the identity is new.
  ///
  /// It is also called while a user is signed in, an anonymous one or the
  /// user of another account: the user of the identity then replaces that
  /// user on the device. When it fails, that user stays signed in.
  ///
  /// It takes a credential that [linkWith] refused just before, with
  /// [AuthFailureReason.credentialInUse] or
  /// [AuthFailureReason.accountExistsWithOtherMethod]: the session passes
  /// the identical object. An identity provider may take a credential only
  /// once, so the service signs in with what its backend answered the
  /// refused link for that object, or with the credential itself when the
  /// backend gave nothing. For an identity whose email address has an
  /// account that signs in in another way, it fails with
  /// [AuthFailureReason.accountExistsWithOtherMethod] or signs in to that
  /// account, as the backend of the provider decides.
  Future<void> signInWith(SignInCredential credential);

  /// Gives the user who is signed in the identity of [credential]: the user

  ///

  /// [AuthFailureReason.credentialInUse], and when its email address has an
  /// account of another user, with

  /// nothing: the user stays signed in, with the same id.
  ///
  /// When it fails with either reason, it keeps what its backend answered
  /// for this credential object, such as a credential to sign in with,

  Future<void> linkWith(SignInCredential credential);

  /// Creates an anonymous user, with an id of its own, and signs in as that
  /// user.
  Future<void> signInAnonymously();

  /// Sends the message with which the owner of the account of [email] sets
  /// a new password.
  ///

  /// learns from the app which addresses have one.
  Future<void> sendPasswordReset(String email);

  /// Signs the user out on this device. It completes when nobody is signed

  Future<void> signOut();

  /// Deletes the user who is signed in, an anonymous one too, and signs

  ///

/// an email address and a password, as an anonymous user, and with the

/// [AuthFailureReason.weakPassword] in [signUp] and [linkPassword].
///
/// A credential of Google goes to Firebase with its ID token, and one of
/// Apple with its ID token, its raw nonce and the name of the user:
/// `GoogleAuthProvider` takes no nonce, and Firebase does not check the

/// provider fails with [AuthFailureReason.notConfigured] before Firebase is

/// on iOS and macOS, and has no call for it elsewhere. A revocation needs

final class FirebaseAuthService implements AuthService {

  FirebaseAuthService(this._auth);

  final FirebaseAuth _auth;

  /// carry the token that the platform gave, and is dropped once used. No

      throw const AuthFailure(AuthFailureReason.invalidCredentials);
    }
    if (code != null) await _revoke(code);
  }

  /// The authorization code with which the service revokes the tokens that
  /// Apple gave the app before it deletes the account, for a [fresh]
  /// credential of Apple on iOS and macOS, or `null`: Firebase has no call
  /// for the revocation on the other platforms. Apple takes a code once, so
  /// it is the code of the fresh credential, never that of a sign-in
  /// before.
  String? _codeToRevoke(SignInCredential fresh) {
    if (fresh case IdTokenCredential(issuer: _apple, :final authorizationCode)
        when defaultTargetPlatform == TargetPlatform.iOS ||
            defaultTargetPlatform == TargetPlatform.macOS) {
      return authorizationCode ??
          (throw const AuthFailure(
            AuthFailureReason.notConfigured,
            developerHint:
                'The credential of Apple has no authorization '
                'code, with which Firebase revokes the tokens that Apple '
                'gave the app before the account is deleted, so the account '
                'was not deleted. The way to sign in with Apple gives one '
                'with each credential.',
          ));
    }
    return null;
  }

  /// Revokes the tokens that Apple gave the app with the authorization
  /// [code]. A failure keeps the account: it is
  /// [AuthFailureReason.notConfigured], but for an answer of Firebase that
  /// is no matter of the setup ([_notOfSetup]), which gets its reason as
  /// that of any other call.
  Future<void> _revoke(String code) async {
    // Firebase never completes the call while nobody is signed in.
    if (_auth.currentUser == null) {
      throw const AuthFailure(AuthFailureReason.recentSignInRequired);
    }
    try {
      await _auth.revokeTokenWithAuthorizationCode(code);
    } on Object catch (error) {
      if (error is FirebaseAuthException && _notOfSetup.contains(error.code)) {
        rethrow;
      }
      final project = _auth.app.options.projectId;
      throw AuthFailure(
        AuthFailureReason.notConfigured,
        developerHint:
            'Firebase did not revoke the tokens that Apple gave '
            'the app (${_answerOf(error)}), so the account was not deleted. '
            'The revocation needs the Services ID and the OAuth code flow '
            'configuration, with the Apple team ID, the Key ID and the '
            'private key, of the Apple sign-in method of the Firebase '
            'project $project, in the Firebase console under '
            'Authentication > Sign-in method: ${_consoleOf(project)}. When '
            'they are set, the authorization code of Apple was older than '
            'five minutes or used before, and the next deletion asks Apple '
            'for a new one.',
      );
    }
  }

  /// The credential of Firebase Authentication for [credential]. One of
  /// Google has the ID token alone: `GoogleAuthProvider` takes no nonce, and
  /// Firebase does not check the nonce of a token of Google.
  ///
  /// It fails with [AuthFailureReason.notConfigured] for a credential of an
  /// identity provider that the service does not take, and for a credential
  /// of Apple without the raw nonce, which Firebase checks the token of
  /// Apple against.
  AuthCredential _firebaseOf(SignInCredential credential) =>
      switch (credential) {
        IdTokenCredential(issuer: _google, :final idToken) =>
          GoogleAuthProvider.credential(idToken: idToken),
        IdTokenCredential(
          issuer: _apple,
          :final idToken,
          :final rawNonce?,
          :final givenName,
          :final familyName,
        ) =>
          AppleAuthProvider.credentialWithIDToken(
            idToken,
            rawNonce,
            AppleFullPersonName(givenName: givenName, familyName: familyName),
          ),
        IdTokenCredential(issuer: _apple) => throw const AuthFailure(
          AuthFailureReason.notConfigured,
          developerHint:
              'The credential of Apple has no raw nonce, which '
              'Firebase checks the token of Apple against. The way to sign '
              'in with Apple gives the nonce of its request with each '
              'credential.',
        ),
        IdTokenCredential(:final issuer) => throw AuthFailure(
          AuthFailureReason.notConfigured,
          developerHint:
              'The app signs in to Firebase Authentication with '
              'the credentials of Google ($_google) and Apple ($_apple), '
              'and takes no credential of $issuer.',
        ),
      };

  /// Runs [call] for the user who is signed in, as [_run] runs a call.
  ///
  /// It fails with [AuthFailureReason.recentSignInRequired] when nobody is
  /// signed in, and when Firebase answers that the session of the user has
  /// ended: the user is then signed out on this device first.
  Future<void> _runForUser(
    Future<void> Function(User user) call, {
    SignInCredential? credential,
    Map<String, AuthFailureReason> reasons = const {},
  }) => _run(
    () async {
      final user = _auth.currentUser;
      if (user == null) {
        throw const AuthFailure(AuthFailureReason.recentSignInRequired);
      }
      try {
        await call(user);
      } on FirebaseAuthException catch (error) {
        if (!_endedSession.contains(error.code)) rethrow;
        await _auth.signOut();
        throw const AuthFailure(AuthFailureReason.recentSignInRequired);
      }
    },
    credential: credential,
    reasons: reasons,
  );

  /// Fails for an [email] that is empty with
  /// [AuthFailureReason.invalidEmail], and for a [password] that is empty
  /// with [withoutPassword], before Firebase is asked. Android refuses an
  /// empty text with a code that has no reason, and iOS answers an empty
  /// password as a wrong one, so the service decides for both.
  void _checkGiven(
    String email, [
    String? password,
    AuthFailureReason withoutPassword = AuthFailureReason.weakPassword,
  ]) {
    if (email.isEmpty) {
      throw const AuthFailure(AuthFailureReason.invalidEmail);
    }
    if (password != null && password.isEmpty) {
      throw AuthFailure(withoutPassword);
    }
  }

  /// Runs [call], which then fails only with an [AuthFailure], and tells
  /// of the user that it leaves, also when it failed.
  ///
  /// A code of Firebase gets its reason of [reasons], the reasons of the
  /// codes for this call, and otherwise that of [_failureOf]. [credential]
  /// is the credential that the call signs in with, whose way to sign in
  /// the hint of a failure names.
  Future<void> _run(
    Future<void> Function() call, {
    SignInCredential? credential,
    Map<String, AuthFailureReason> reasons = const {},
  }) async {
    try {
      await call();
    } on Object catch (error, stackTrace) {
      Error.throwWithStackTrace(
        _failureOf(error, credential, reasons),
        stackTrace,
      );
    } finally {
      _changes.add(null);
    }
  }

  /// The failure of a call that failed with [error]: the reason for the
  /// code of Firebase, from [reasons] first. A code that has no reason yet
  /// gets one here. The hint of a way to sign in that is not enabled names
  /// the way to sign in of [credential], or Email/Password and Anonymous.
  AuthFailure _failureOf(
    Object error,
    SignInCredential? credential,
    Map<String, AuthFailureReason> reasons,
  ) {
    if (error is AuthFailure) return error;
    if (error is! FirebaseAuthException) {
      return AuthFailure(AuthFailureReason.unknown, developerHint: '$error');
    }
    final reason =
        reasons[error.code] ??
        switch (error.code) {
          // Firebase answers a wrong password and an address without an
          // account alike, unless the project is without the protection
          // against the enumeration of email addresses. It also answers so
          // for a credential that it refuses, such as one that expired, and
          // for one whose nonce it took before.
          'invalid-credential' ||
          'invalid-login-credentials' ||
          'wrong-password' ||
          'user-not-found' ||
          'missing-or-invalid-nonce' ||
          // A fresh credential of another user than the one whose account
          // is deleted.
          'user-mismatch' => AuthFailureReason.invalidCredentials,
          'email-already-in-use' ||
          'credential-already-in-use' => AuthFailureReason.emailInUse,
          'account-exists-with-different-credential' =>
            AuthFailureReason.accountExistsWithOtherMethod,
          'weak-password' || 'password-does-not-meet-requirements' =>
            AuthFailureReason.weakPassword,
          'invalid-email' || 'missing-email' => AuthFailureReason.invalidEmail,
          'user-disabled' => AuthFailureReason.userDisabled,
          'too-many-requests' => AuthFailureReason.tooManyAttempts,
          'network-request-failed' => AuthFailureReason.network,
          'requires-recent-login' => AuthFailureReason.recentSignInRequired,
          _ => null,
        };
    if (reason != null) return AuthFailure(reason);
    final answer = _answerOf(error);
    final project = _auth.app.options.projectId;
    final console =
        'the Firebase console under Authentication > Sign-in '
        'method: ${_consoleOf(project)}';
    final method = switch (credential) {
      IdTokenCredential(:final issuer) => _providers[issuer]?.name,
      null => null,
    };
    const script =
        'run `dart tool/enable_firebase_sign_in.dart` in the '
        'directory of the app';
    // The way to sign in, after "sign-in", and what enables it: the script
    // of the app enables Email/Password, Anonymous and Google, and the
    // Firebase console every way to sign in.
    final (withMethod, enable) = switch (method) {
      null => (
        '',
        '$script, or enable Email/Password, and Anonymous for an app that '
            'signs in anonymous users, in $console',
      ),
      'Google' => (' with Google', '$script, or enable Google in $console'),
      _ => (' with $method', 'enable $method in $console'),
    };
    // A way to sign in that is not enabled, which Firebase tells by its
    // code, and a project in which Authentication was never set up, which
    // it tells only in its message.
    const noConfiguration = 'CONFIGURATION_NOT_FOUND';
    final notEnabled = switch (error.code) {
      'operation-not-allowed' || 'admin-restricted-operation' => error.code,
      _ when answer.contains(noConfiguration) =>
        '${error.code}, $noConfiguration',
      _ => null,
    };
    if (notEnabled != null) {
      return AuthFailure(
        AuthFailureReason.notConfigured,
        developerHint:
            'Sign-in$withMethod is not enabled in the Firebase '
            'project $project (Firebase answered $notEnabled). To fix it, '
            '$enable',
      );
    }
    // On iOS and macOS, Firebase may answer for such a project with an
    // internal error whose message says no more, which nothing tells from
    // another internal error.
    if (error.code == 'internal-error' &&
        (defaultTargetPlatform == TargetPlatform.iOS ||
            defaultTargetPlatform == TargetPlatform.macOS)) {
      return AuthFailure(
        AuthFailureReason.notConfigured,
        developerHint:
            'Firebase reported an internal error ($answer), which '
            'is also what it answers on iOS and macOS when sign-in$withMethod '
            'is not enabled in the Firebase project $project. If that is the '
            'cause, $enable',
      );
    }
    return AuthFailure(AuthFailureReason.unknown, developerHint: answer);
  }

  /// What Firebase answered with [error]: its code and its message on one
  /// line, since the message of iOS may be the description of an error over
  /// many lines, or the error itself when it is no error of Firebase.
  String _answerOf(Object error) {
    if (error is! FirebaseAuthException) return '$error';
    final message = (error.message ?? '')
        .replaceAll(RegExp(r'\s+'), ' ')
        .trim();
    return message.isEmpty ? error.code : '${error.code}: $message';
  }

  /// The page of the Firebase console with the sign-in methods of
  /// [project].
  String _consoleOf(String project) =>
      'https://console.firebase.google.com/project/$project/'
      'authentication/providers';

//
//     dart tool/configure_firebase.dart <flavor> --project=<id>
//
// In a terminal, without --project, flutterfire asks for the project. The
// other arguments go to flutterfire as they are, such as --account=<email>.
//
// flutterfire writes one iOS build configuration in a run, and the build of
// each needs its entry in firebase.json, so on macOS this script runs it once
// for each. Run it again at any time: it changes nothing but the ids of two
// build phases, or moves the flavor to another project.
//
// Then it formats the options that flutterfire wrote, and runs each Dart file
// of tool/firebase_configured by the order of their names, for what has to
// follow every run of flutterfire.

import 'dart:io';

/// for a platform that the app does not have, and its Xcode build
/// configurations.
typedef _Flavor = ({String? android, String? ios, List<String> configurations});

/// change them in the Android and Xcode projects, change them here too.
const Map<String, _Flavor> _flavors = {

    ios: 'com.example.my-app.dev',

    configurations: ['Debug-staging', 'Profile-staging', 'Release-staging'],

  'prod': (

    ios: 'com.example.my-app',
    configurations: ['Debug-prod', 'Profile-prod', 'Release-prod'],

/// Configures the flavor that [arguments] names in [app], and returns the exit
/// code of the script.
Future<int> _configure(Directory app, List<String> arguments) async {
  final flavor = arguments.isEmpty ? null : arguments.first;
  final ofFlavor = _flavors[flavor];
  if (flavor == null || ofFlavor == null) {
    throw _Stop(
      'Name a flavor: dart tool/configure_firebase.dart '
      '<${_flavors.keys.join('|')}> --project=<id>',
    );
  }
  final (named, rest) = _withoutProject(arguments.sublist(1));
  var project = named;
  final terminal = stdin.hasTerminal;
  if (project == null && !terminal) {
    throw _Stop(
      'Name the Firebase project: dart tool/configure_firebase.dart $flavor '
      '--project=<id>. Without a terminal, nobody can answer the question of '
      'flutterfire.',
    );
  }
  final platforms = _platformsIn(rest);
  final android = platforms.contains('android') ? ofFlavor.android : null;
  final ios = platforms.contains('ios') ? ofFlavor.ios : null;
  _checkIds(android, ios);

  // flutterfire changes the Xcode project only on macOS, so the runs differ
  // only there.
  final configurations = Platform.isMacOS && ios != null
      ? ofFlavor.configurations
      : ofFlavor.configurations.take(1);
  for (final configuration in configurations) {
    final process = await Process.start(
      Platform.resolvedExecutable,
      [
        'pub',
        'global',
        'run',
        'flutterfire_cli:flutterfire',
        'configure',
        if (project != null) '--project=$project',
        '--platforms=$_platforms',
        '--overwrite-firebase-options',
        '--out=lib/firebase_options_$flavor.dart',
        if (android != null) ...[
          '--android-package-name=$android',
          '--android-out=android/app/src/$flavor/google-services.json',
        ],
        if (ios != null) ...[
          '--ios-bundle-id=$ios',
          '--ios-out=ios/flavors/$flavor/GoogleService-Info.plist',
          '--ios-build-config=$configuration',
        ],
        ...rest,
      ],
      workingDirectory: app.path,
      // Without a terminal, flutterfire fails rather than wait for an answer.
      environment: terminal ? null : const {'CI': 'true'},
      mode: ProcessStartMode.inheritStdio,
    );
    final code = await process.exitCode;
    if (code != 0) {
      stderr.writeln(
        'flutterfire failed for the flavor $flavor (exit code $code). What it '
        'wrote stays, and running this script again does the rest. It needs '
        'the FlutterFire CLI, a login of the Firebase CLI and, on macOS, the '
        'Ruby gem xcodeproj: see the section Firebase of README.md.',
      );
      return code;
    }
    // The next runs need no answer.
    project ??= _projectOf(app, flavor);
  }

  await _format(app, flavor);
  for (final hook in _hooksOf(app)) {
    final process = await Process.start(
      Platform.resolvedExecutable,
      [hook.path],
      workingDirectory: app.path,
      mode: ProcessStartMode.inheritStdio,
    );
    final code = await process.exitCode;
    if (code != 0) {
      stderr.writeln(
        '${hook.path} failed (exit code $code). flutterfire configured the '
        'flavor $flavor, and running this script again runs it again.',
      );
      return code;
    }
  }
  stdout.writeln(
    'Configured the flavor $flavor for the Firebase project $project. Commit '
    'firebase.json and the files it names.',
  );
  return 0;
}

/// The project that [arguments] name, as flutterfire reads it, with the last
/// one counting, and the other arguments.
(String?, List<String>) _withoutProject(List<String> arguments) {
  String? project;
  final rest = <String>[];
  for (var index = 0; index < arguments.length; index++) {
    final argument = arguments[index];
    if (argument == '--project' || argument == '-p') {
      if (++index == arguments.length) {
        throw _Stop('$argument needs the id of a Firebase project.');
      }
      project = arguments[index];
    } else if (argument.startsWith('--project=')) {
      project = argument.substring('--project='.length);
    } else if (argument.startsWith('-p')) {
      project = argument.substring('-p'.length);
    } else {
      rest.add(argument);
    }
  }
  if (project != null && project.isEmpty) {
    throw _Stop('--project needs the id of a Firebase project.');
  }
  return (project, rest);
}

/// The platforms of this run: those of the app, unless [rest] names others.
/// [rest] comes last on the command line of flutterfire, which takes the last
/// value of an option.
List<String> _platformsIn(List<String> rest) {
  var platforms = _platforms;
  for (var index = 0; index < rest.length; index++) {
    if (rest[index].startsWith('--platforms=')) {
      platforms = rest[index].substring('--platforms='.length);
    } else if (rest[index] == '--platforms' && index + 1 < rest.length) {
      platforms = rest[index + 1];
    }
  }
  return platforms.split(',');
}

/// Stops at an id that flutterfire would refuse, with what to do about it.
void _checkIds(String? android, String? ios) {
  if (android != null && !_packageName.hasMatch(android)) {
    throw _Stop(
      'flutterfire takes no application id like $android (it allows no '
      'underscore in its first part): use another org.',
    );
  }
  if (ios != null && !_bundleId.hasMatch(ios)) {
    throw _Stop(
      'flutterfire takes no bundle id like $ios (it allows no hyphen at either '
      'end of a part, and at most 63 characters in one): use another org.',
    );
  }
}

/// The project of the options of [flavor], which flutterfire wrote into
/// `firebase.json` of [app].
///
/// It reads the entry of the options: the keys of the Android apps in that
/// file depend on the path of the app.
String _projectOf(Directory app, String flavor) {
  final file = File('${app.path}/firebase.json');
  final json = file.existsSync() ? jsonDecode(file.readAsStringSync()) : null;
  Object? entry = json;
  for (final key in [
    'flutter',
    'platforms',
    'dart',
    'lib/firebase_options_$flavor.dart',
    'projectId',
  ]) {
    entry = entry is Map ? entry[key] : null;
  }
  if (entry is! String) {
    throw _Stop(
      '${file.path} names no Firebase project for the flavor $flavor, though '
      'flutterfire succeeded. Run this script again with --project=<id>.',
    );
  }
  return entry;
}

/// Formats the options of [flavor], which flutterfire writes in a format of
/// its own, so that the check of the format of the app passes. They work
/// without it, so a failure only warns.
Future<void> _format(Directory app, String flavor) async {
  final options = 'lib/firebase_options_$flavor.dart';
  final result = await Process.run(Platform.resolvedExecutable, [
    'format',
    options,
  ], workingDirectory: app.path);
  if (result.exitCode != 0) {
    stderr.writeln(
      'Warning: dart format left $options as flutterfire wrote it (exit code '
      '${result.exitCode}): ${result.stderr}',
    );
  }
}

/// The Dart files of the hooks directory of [app], by the order of their
/// names. An app whose modules have nothing to do after flutterfire has no
/// such directory.
List<File> _hooksOf(Directory app) {
  final directory = Directory('${app.path}/$_hooks');
  if (!directory.existsSync()) return const [];
  return [
    for (final entity in directory.listSync())
      if (entity is File && entity.path.endsWith('.dart')) entity,
  ]..sort((a, b) => a.path.compareTo(b.path));
}

// Email/Password, and Anonymous when the app is in the mode `anonymous`,
// which the script reads from `authMode` of the app.
//
//     dart tool/enable_firebase_sign_in.dart

//

// nothing. It runs the Firebase CLI in a temporary directory, with a
// configuration of its own there, so no file of the app changes:
// `firebase.json` of the app stays as it is, and a `firebase deploy` of the
// app does not touch the sign-in methods. The Firebase CLI keeps its log in
// the directory that it runs in, so the log is not in the app either.
//
// The script removes the temporary directory when the Firebase CLI ends.
// After Ctrl+C it waits for the Firebase CLI to end, removes the directory
// and exits with the code 130. A script that is stopped in another way, as
// with `kill`, leaves the directory among the temporary files of the
// system, and so does Ctrl+C where the script cannot watch for it.
//

// the temporary directory: `--account <email>` names the account.

import 'dart:convert';
import 'dart:io';

/// The file of the app with `authMode`, the sign-in mode of the app.

/// Enables the sign-in methods that [app] needs in its Firebase project, or
/// in the one that [arguments] name, and returns the exit code of the
/// Firebase CLI, or 130 after Ctrl+C.
///
/// Throws a [_Stop] when it cannot tell the methods or the project, and
/// when the Firebase CLI of the machine cannot enable them.
Future<int> _enable(Directory app, List<String> arguments) async {
  final mode = _modeOf(app);
  final anonymous = mode == _anonymous;
  final (named, passedOn) = _withoutProject(arguments);
  if (named != null && !_projectId.hasMatch(named)) {
    throw _Stop(
      'The arguments name "$named" as the Firebase project, which is no id '
      'of a project.',
    );
  }
  final project = named ?? _configuredProject(app);

  // Every call of the Firebase CLI runs in this directory, also the one for
  // its version: the Firebase CLI keeps its log in the directory that it
  // runs in.
  final directory = Directory.systemTemp.createTempSync('firebase_sign_in_');
  Process? firebase;
  var interrupted = false;
  // Ctrl+C. In a terminal, the Firebase CLI gets the signal with the
  // script, and elsewhere the script passes it on, which Windows has no way
  // to do. Where the signal cannot be watched, Ctrl+C ends the script at
  // once, and the directory stays.
  final interrupts = ProcessSignal.sigint.watch().listen((_) {
    interrupted = true;
    if (!Platform.isWindows) firebase?.kill(ProcessSignal.sigint);
  }, onError: (Object _) {});
  Future<Process> start(List<String> arguments, ProcessStartMode mode) async =>
      firebase = await Process.start(
        'firebase',
        arguments,
        workingDirectory: directory.path,
        // Without its check for a newer version, which runs on as a process
        // of its own: on Windows, the directory of a process that runs
        // cannot be removed.
        environment: const {'NO_UPDATE_NOTIFIER': '1'},
        mode: mode,
        // On Windows, npm installs the Firebase CLI as `firebase.cmd`.
        runInShell: Platform.isWindows,
      );
  try {
    final int asked;
    final String version;
    final String errors;
    try {
      final process = await start(const ['--version'], ProcessStartMode.normal);
      final printed = process.stdout.transform(systemEncoding.decoder).join();
      final failed = process.stderr.transform(systemEncoding.decoder).join();
      asked = await process.exitCode;
      version = await printed;
      errors = (await failed).trim();
    } on ProcessException catch (error) {
      throw _Stop(_notRunning(error.message, project));
    }
    if (interrupted) return 130;
    if (asked != 0) {
      throw _Stop(
        _notRunning(
          'exit code $asked${errors.isEmpty ? '' : ': $errors'}',
          project,
        ),
      );
    }
    if (_olderCli(version) case final older?) {
      throw _Stop(
        'The Firebase CLI of this machine is $older, and enabling sign-in '
        'methods needs $_firstCli or later. Update it with "npm install -g '
        'firebase-tools" if npm installed it, or see '
        'https://firebase.google.com/docs/cli#update-cli\n'
        '${_inConsole(project)}',
      );
    }

    File('${directory.path}/firebase.json').writeAsStringSync(
      jsonEncode({
        'auth': {
          'providers': {
            'emailPassword': true,
            if (anonymous) 'anonymous': true,
          },
        },
      }),
    );
    stdout.writeln(
      'Enabling Email/Password${anonymous ? ' and Anonymous' : ''} in the '
      'Firebase project $project (the mode of the app is $mode).',
    );
    // What the Firebase CLI prints comes after this line.
    await stdout.flush();
    if (interrupted) return 130;
    final deploy = await start([
      'deploy',
      '--only',
      'auth',
      // The project that the line above names, and no other: the arguments
      // that are passed on name none.
      '--project=$project',
      '--non-interactive',
      ...passedOn,
    ], ProcessStartMode.inheritStdio);
    final code = await deploy.exitCode;
    if (interrupted) return 130;
    if (code != 0) stderr.writeln(_afterFailure(code, project, passedOn));
    return code;
  } finally {
    await interrupts.cancel();
    try {
      directory.deleteSync(recursive: true);
    } on FileSystemException catch (error) {
      stderr.writeln(
        'The temporary directory ${directory.path} of this script is left: '
        '${error.message}.',
      );
    }
  }
}

/// An id of a Firebase project, as the Firebase CLI takes it: lower-case
/// letters, digits and hyphens, after the domain of an organization, if it
/// has one.
final _projectId = RegExp(r'^(?:[a-z0-9][a-z0-9.-]*:)?[a-z0-9][a-z0-9-]*$');

/// How to enable the methods without the Firebase CLI: in the Firebase
/// console of [project], or of the project that the user picks there.
String _inConsole([String project = '_']) =>
    'The Firebase console enables the methods too, under Authentication > '
    'Sign-in method: https://console.firebase.google.com/project/$project/'
    'authentication/providers';

/// What the script tells when the Firebase CLI does not run, because of
/// [why].
String _notRunning(String why, String project) =>
    'The Firebase CLI did not run ($why). Install it, or put it on the '
    'PATH: https://firebase.google.com/docs/cli\n${_inConsole(project)}';

/// What the script tells after the Firebase CLI failed with the exit code
/// [code] for [project], with the arguments [passedOn]: which account it
/// may have run as, where its log was, and the other way to enable the
/// methods.
String _afterFailure(int code, String project, List<String> passedOn) {
  final options = passedOn.takeWhile((argument) => argument != '--').toList();
  // The last account that the options name is the one of the Firebase CLI.
  String? account;
  for (final (index, option) in options.indexed) {
    if (option.startsWith('--account=')) {
      account = option.substring('--account='.length);
    } else if (option == '--account' && index + 1 < options.length) {
      account = options[index + 1];
    }
  }
  return [
    'The Firebase CLI did not enable the sign-in methods (exit code $code).',
    if (account != null)
      '- The arguments name the account $account for it. "firebase '
          'login:list" shows the accounts that the Firebase CLI has.'
    else
      '- If it ran as the wrong account: this script runs the Firebase CLI '
          'in a temporary directory, where an account that "firebase '
          'login:use" chose for the directory of the app does not apply. To '
          'name the account, run: $_command --account <email>',
    if (!options.contains('--debug'))
      '- Its log, firebase-debug.log, was in that temporary directory, '
          'which this script removes. To see what the Firebase CLI did, '
          'run: $_command --debug',
    '- ${_inConsole(project)}',
  ].join('\n');
}

/// The text of [file], which is in UTF-8.
String _textOf(File file) {
  try {
    return file.readAsStringSync();
  } on FileSystemException catch (error) {
    throw _Stop(
      '${file.path} could not be read as a text in UTF-8 (${error.message}).',
    );
  }
}

/// The sign-in mode of [app], such as `required`, as `authMode` in
/// [_sessionFile] has it.
///
/// That file imports Flutter, so this script cannot import it, and reads
/// the declaration of the constant instead; see [_modeDeclaration].
String _modeOf(Directory app) {
  const cannotTell =
      'Cannot tell the sign-in mode of the app, by which this '
      'script enables Anonymous or leaves it out';
  final file = File('${app.path}/$_sessionFile');
  if (!file.existsSync()) {
    throw _Stop('$cannotTell: ${file.path} is missing.\n${_inConsole()}');
  }
  final modes = [
    for (final match in _modeDeclaration.allMatches(_textOf(file))) ?match[1],
  ];
  if (modes.length != 1) {
    throw _Stop(
      '$cannotTell: ${file.path} does not have one declaration such as '
      '"const AuthMode authMode = AuthMode.required;", which starts its line '
      'and has a mode of the app as its value.\n'
      '${_inConsole()}',
    );
  }
  return modes.single;
}

/// one, and the arguments without what names it.
///
/// The Firebase CLI takes the last `--project <id>`, `--project=<id>`,
/// `-P <id>` or `-P<id>` before `--`, so the script does too, and passes
/// none of them on: it gives the Firebase CLI the project itself. It stops
/// at short options in one argument that have `P` among them, such as
/// `-jP`, which the Firebase CLI may read as a project too.
(String?, List<String>) _withoutProject(List<String> arguments) {
  final end = arguments.indexOf('--');
  final options = end < 0 ? arguments : arguments.sublist(0, end);
  String? project;
  final others = <String>[];
  for (var index = 0; index < options.length; index++) {
    final option = options[index];
    if (option == '--project' || option == '-P') {
      if (++index == options.length) {
        throw _Stop('$option needs the id of a Firebase project after it.');
      }
      project = options[index];
    } else if (option.startsWith('--project=')) {
      project = option.substring('--project='.length);
    } else if (option.startsWith('-P')) {
      project = option.substring(2);
    } else if (RegExp(r'^-[A-Za-z]*P').hasMatch(option)) {
      throw _Stop(
        'Cannot tell whether "$option" names a Firebase project. Name the '
        'project with --project <id>, apart from the other options.',
      );
    } else {
      others.add(option);
    }
  }
  return (project, [...others, if (end >= 0) ...arguments.sublist(end)]);
}

/// The id of the Firebase project that `flutterfire configure` wrote into
/// `firebase.json` of [app]: under `flutter`, each platform of the app has
/// the id of its project.
String _configuredProject(Directory app) {
  final file = File('${app.path}/firebase.json');
  const orName = 'or name the project: $_command --project <id>';
  if (!file.existsSync()) {
    throw _Stop(
      '${file.path} is missing, so the app is not configured for Firebase '
      'yet. Run "flutterfire configure" first (see README.md), $orName',
    );
  }
  final Object? json;
  try {
    json = jsonDecode(_textOf(file));
  } on FormatException catch (error) {
    throw _Stop(
      '${file.path} is not JSON (${error.message}). Run "flutterfire '
      'configure" again (see README.md), $orName',
    );
  }
  final projects = <String>{};
  void collect(Object? node) {
    if (node is! Map) return;
    for (final MapEntry(:key, :value) in node.entries) {
      if (key == 'projectId' && value is String) {
        projects.add(value);
      } else {
        collect(value);
      }
    }
  }

  collect(json is Map ? json['flutter'] : null);
  if (projects.isEmpty) {
    throw _Stop(
      '${file.path} has no Firebase project of "flutterfire configure". Run '
      'it first (see README.md), $orName',
    );
  }
  if (projects.length > 1) {
    throw _Stop(
      '${file.path} has several Firebase projects (${projects.join(', ')}). '
      'Name one: $_command --project <id>',
    );
  }
  final project = projects.single;
  if (!_projectId.hasMatch(project)) {
    throw _Stop(
      '${file.path} has "$project" as its Firebase project, which is no id '
      'of a project. Run "flutterfire configure" again (see README.md), '
      '$orName',
    );
  }
  return project;
}

/// A version as `firebase --version` prints it on a line of its own: three
/// numbers, then a pre-release after `-` and a build after `+`, if any.
final _version = RegExp(r'^(\d+)\.(\d+)\.(\d+)(-[^+\s]+)?(\+\S+)?$');

/// The version of the Firebase CLI in [printed], what `firebase --version`
/// printed, if it comes before [_firstCli], or `null` if it does not.
///
/// The version is the last line that is one, since the Firebase CLI may
/// print more. A pre-release of [_firstCli] comes before it: it may lack
/// what the version has. A version that the script cannot read is none
/// before it: the Firebase CLI then tells itself what it cannot do.
String? _olderCli(String printed) {
  final version = [
    for (final line in printed.split('\n')) ?_version.firstMatch(line.trim()),
  ].lastOrNull;
  if (version == null) return null;
  final first = _firstCli.split('.').map(int.parse).toList();
  for (final (index, number) in first.indexed) {
    final found = int.tryParse(version[index + 1]!);
    if (found == null || found > number) return null;
    if (found < number) return version[0];
  }
  return version[4] == null ? null : version[0];
}
