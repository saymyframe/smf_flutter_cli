# AGENTS.md

This guide tells coding agents what the code of this Flutter app does not show. Setup that needs a person or an account is in [README.md](README.md). When you change what a section describes, change the section too.

## App entry

The app is plain Flutter code that nothing regenerates. Change it by hand, unless a section below says what writes a file.

- `main()` in `lib/main.dart` initializes the binding, awaits `bootstrap()` and calls `runApp()`, in this order. Start-up code goes into `bootstrap()`.
- `bootstrap()` in `lib/bootstrap.dart` runs before the first frame, in four phases: what must come before anything else, then the platform services, then the services of the app, then what needs them. Put a new statement into its phase, and import neither `package:flutter/material.dart` nor `package:flutter/cupertino.dart` there.
- Put code that features share into `lib/core/<concern>/`, one directory for each concern. Put a feature, with its screens and their state, into `lib/features/<feature>/`.
- The root of the app asks the system for the icons of the status bar that suit the theme, around every screen, with `StatusBarIcons` of `lib/core/app/status_bar_icons.dart`: dark icons on a light theme, light ones on a dark theme. A screen without an app bar needs no `AnnotatedRegion` for them. Add one only to a screen whose top has another brightness than the theme, such as a picture behind the status bar.
- The app has the flavors `dev`, `staging` and `prod`. A `flutter` command without `--flavor` builds `dev`, in release mode too, so a build for a store takes `--flavor prod`. Code reads the flavor from `appFlavor` of `package:flutter/services.dart`. The app has one entry: add no `main_<flavor>.dart`.

After a change, run:

```bash
dart format lib test
flutter analyze
flutter test
```

Format only `lib/` and `test/`: `dart format .` also formats what Flutter writes into `build/`. The app as generated is formatted, `flutter analyze` finds no issue in it and `flutter test` passes.

- `App` in `lib/app.dart` is the root widget of the app and creates its one `MaterialApp`. Create no other in `lib/`: every screen is below it.
- The `theme`, `darkTheme`, `themeMode`, `locale` and localizations of the app go into the arguments of that `MaterialApp`.
- Tests mirror `lib/`: the test of `lib/<path>.dart` is `test/<path>_test.dart`.
- The app has only an Android and an iOS project, in `android/` and `ios/`.
- The entitlements of the iOS app, such as Push Notifications or Sign in with Apple, are in `ios/Runner/Runner.entitlements`. Every build configuration of the Runner target signs with this file, even while it is empty. The Signing & Capabilities tab of Xcode edits the same file.
- Each flavor is in `productFlavors` of `android/app/build.gradle.kts`, and on iOS in `ios/Runner.xcodeproj/xcshareddata/xcschemes/<flavor>.xcscheme` and in the build configurations `Debug-<flavor>`, `Profile-<flavor>` and `Release-<flavor>` of `ios/Runner.xcodeproj/project.pbxproj`. Change both places together. A new setting of the Runner target goes into each of its twelve build configurations.

## Firebase

- `bootstrap()` initializes Firebase with `firebaseOptionsOfFlavor` of `lib/firebase_options_of_flavor.dart`, by the flavor of the build. `lib/firebase_options_dev.dart`, `lib/firebase_options_staging.dart` and `lib/firebase_options_prod.dart` are placeholders until `tool/configure_firebase.dart` writes them, and a build of such a flavor stops at start-up with an `UnsupportedError`. Do not write them by hand.
- `tool/configure_firebase.dart` needs a Firebase account and a project: run it only when asked, with the command of the section Firebase of `README.md`. Do not run `flutterfire configure`, which writes one configuration that every flavor then shares.
- A test that runs `main()` or `bootstrap()` starts Firebase with the options of the flavor of the test, `dev`, which needs a mock of its platform side. Prefer a test of a widget, which needs neither.

# my_app

A new Flutter project.

Generated with [Say My Frame](https://doc.saymyframe.com).

## Flavors

The app has three flavors, which install next to each other on a device, each under an id of its own:

| Flavor | Android application id | iOS bundle id |
| --- | --- | --- |
| `dev` | `com.example.my_app.dev` | `com.example.my-app.dev` |
| `staging` | `com.example.my_app.staging` | `com.example.my-app.staging` |
| `prod` | `com.example.my_app` | `com.example.my-app` |

A `flutter` command without `--flavor` builds `dev`, because `default-flavor` in `pubspec.yaml` says so. That holds in release mode too: `flutter build appbundle` and `flutter build ipa` build a release of `dev`, under its id. For a store, name the flavor:

```bash
flutter run --flavor staging
flutter build appbundle --flavor prod
flutter build ipa --flavor prod
```

Code reads the flavor from `appFlavor` of `package:flutter/services.dart`. A service that knows your app by its id, such as a store or a push provider, knows each flavor as an app of its own, so you repeat a step of its setup for each flavor that needs it.

## Flavors in the native projects

Each flavor is in two places, so change both when you rename, add or remove one:

- Android: `productFlavors` in `android/app/build.gradle.kts`, with its id suffix and its name on the device.
- iOS: `ios/Runner.xcodeproj/xcshareddata/xcschemes/<flavor>.xcscheme`, and the build configurations `Debug-<flavor>`, `Profile-<flavor>` and `Release-<flavor>` in each configuration list of `ios/Runner.xcodeproj/project.pbxproj`. The name of a flavor has no hyphen, since Flutter splits the name of a configuration on it.

In Xcode, select the scheme of a flavor, not `Runner`. The scheme of a flavor builds that flavor, with its id, its name and its `appFlavor`. `Runner` builds the id and the name of `prod`, and takes `appFlavor` from `ios/Flutter/Generated.xcconfig`, which the last `flutter` command wrote. `flutter build ios --config-only --flavor <flavor>` gives that file a flavor.

On Android, a release build is signed with the debug key until `android/app/build.gradle.kts` has a signing config of yours, and a store refuses such a build. [Sign the app](https://docs.flutter.dev/deployment/android#sign-the-app) tells how.

## Firebase

The app uses [Firebase](https://firebase.google.com/docs/flutter/setup) through `firebase_core`: `bootstrap()` initializes it with `firebaseOptionsOfFlavor` of `lib/firebase_options_of_flavor.dart`, which takes the options of the flavor of the build from `lib/firebase_options_<flavor>.dart`. A flavor may have a Firebase project of its own or share one. Until a flavor is configured, its options are a placeholder, and a build of it stops at start-up with an `UnsupportedError` that gives the command below.

`smf create` offers to configure `dev`, and otherwise leaves the command for later. To configure a flavor, or to configure it again, such as for another project or on another machine, run in the directory of the app:

```bash
dart pub global activate flutterfire_cli 1.4.1
firebase login
dart tool/configure_firebase.dart staging --project=<id>
```

Use this script rather than `flutterfire configure`, which writes one configuration that every flavor then shares: `ios/Runner/GoogleService-Info.plist` goes into the resources of every flavor, and `android/app/google-services.json` is what the Google services plugin takes for any variant without a file of its own. It registers the Android and iOS apps of the flavor in the project and writes its options, `android/app/src/<flavor>/google-services.json`, `firebase.json` and, on macOS, `ios/flavors/<flavor>/GoogleService-Info.plist`. Commit them. Elsewhere the script leaves the Xcode project and that file as they were, so run it again on a Mac for iOS. In a terminal you may leave `--project` out, and flutterfire then asks. Other arguments, such as `--account=<email>`, go to flutterfire. The ids of each flavor are at the top of the script: if you change them in the projects, change them there too.

Once one flavor is configured, a build of a flavor that is not fails on Android, with `File google-services.json is missing`. On iOS it builds and stops at start-up, unless a build phase that flutterfire adds for a Firebase package fails the build there first.

In Xcode, select the scheme of a flavor. It builds that flavor, whatever `ios/Flutter/Generated.xcconfig` says. The scheme `Runner` takes the flavor from that file, which has none after a fresh `flutter pub get`, so `appFlavor` is `null` there and `firebaseOptionsOfFlavor` throws an `UnsupportedError`. `flutter build ios --config-only --flavor <flavor>` gives the file a flavor.

The script changes the Xcode project only on macOS, and adds a build phase that runs `flutterfire` from `~/.pub-cache/bin`. So every Mac that builds the app for iOS needs the FlutterFire CLI activated, flutterfire_cli 1.4.1 or a later 1.x; if `dart pub global list` shows one already, skip its activation above. flutterfire needs the [Firebase CLI](https://firebase.google.com/docs/cli).

// Configures Firebase for one flavor of the app, with the FlutterFire CLI:
//
//     dart tool/configure_firebase.dart <flavor> --project=<id>
//
// In a terminal, without --project, flutterfire asks for the project. The
// other arguments go to flutterfire as they are, such as --account=<email>.
//
// flutterfire writes one iOS build configuration in a run, and the build of
// each needs its entry in firebase.json, so on macOS this script runs it once
// for each. Run it again at any time: it changes nothing but the ids of the
// build phases that flutterfire added, or moves the flavor to another project.
//
// Then it formats the options that flutterfire wrote, and runs each Dart file
// of tool/firebase_configured by the order of their names, for what has to
// follow every run of flutterfire.

import 'dart:convert';
import 'dart:io';

/// The Android application id and the iOS bundle id of a flavor, each `null`
/// for a platform that the app does not have, and its Xcode build
/// configurations.
typedef _Flavor = ({String? android, String? ios, List<String> configurations});

/// The flavors of the app. SMF wrote their ids from the ids of the app: if you
/// change them in the Android and Xcode projects, change them here too.
const Map<String, _Flavor> _flavors = {
  'dev': (
    android: 'com.example.my_app.dev',
    ios: 'com.example.my-app.dev',
    configurations: ['Debug-dev', 'Profile-dev', 'Release-dev'],
  ),
  'staging': (
    android: 'com.example.my_app.staging',
    ios: 'com.example.my-app.staging',
    configurations: ['Debug-staging', 'Profile-staging', 'Release-staging'],
  ),
  'prod': (
    android: 'com.example.my_app',
    ios: 'com.example.my-app',
    configurations: ['Debug-prod', 'Profile-prod', 'Release-prod'],
  ),
};

/// The platforms of the app.
const _platforms = 'android,ios';

/// The directory of what has to follow every run of flutterfire.
const _hooks = 'tool/firebase_configured';

/// What flutterfire_cli 1.4.1 takes with `--android-package-name`, as
/// `validateAndroidPackageName` of its `lib/src/common/utils.dart` checks it.
final _packageName = RegExp(
  r'^[a-zA-Z][a-zA-Z0-9]*(\.[a-zA-Z_][a-zA-Z0-9_]*)+$',
);

/// What flutterfire_cli 1.4.1 takes with `--ios-bundle-id`, as
/// `validateAppBundleId` of the same file checks it.
final _bundleId = RegExp(
  r'^([a-zA-Z0-9]([a-zA-Z0-9\-]{0,61}[a-zA-Z0-9])?|([a-zA-Z0-9]([a-zA-Z0-9\-]{0,61}[a-zA-Z0-9])?(\.[a-zA-Z0-9]([a-zA-Z0-9\-]{0,61}[a-zA-Z0-9])?)+))$',
);

Future<void> main(List<String> arguments) async {
  final script = File.fromUri(Platform.script).resolveSymbolicLinksSync();
  try {
    exitCode = await _configure(File(script).parent.parent, arguments);
  } on _Stop catch (stop) {
    stderr.writeln(stop.why);
    exitCode = 1;
  }
}

/// Why the script stops before flutterfire.
final class _Stop implements Exception {
  const _Stop(this.why);

  final String why;
}

/// Configures the flavor that [arguments] names in [app], and returns the exit
/// code of the script.
Future<int> _configure(Directory app, List<String> arguments) async {
  final (named, others) = _withoutProject(arguments);
  // The word that names a flavor, which may come after another option.
  final flavors = others.where(_flavors.containsKey).toList();
  if (flavors.length != 1) {
    throw _Stop(
      'Name a flavor: dart tool/configure_firebase.dart '
      '<${_flavors.keys.join('|')}> --project=<id>',
    );
  }
  final flavor = flavors.single;
  final ofFlavor = _flavors[flavor]!;
  final rest = [...others]..remove(flavor);
  var project = named;
  final terminal = _hasTerminal();
  if (project == null && !terminal) {
    throw _Stop(
      'Name the Firebase project: dart tool/configure_firebase.dart $flavor '
      '--project=<id>. Without a terminal, nobody can answer the question of '
      'flutterfire.',
    );
  }
  final platforms = _platformsIn(rest);
  final android = platforms.contains('android') ? ofFlavor.android : null;
  final ios = platforms.contains('ios') ? ofFlavor.ios : null;
  _checkIds(android, ios);

  // flutterfire changes the Xcode project only on macOS, so the runs differ
  // only there.
  final configurations = Platform.isMacOS && ios != null
      ? ofFlavor.configurations
      : ofFlavor.configurations.take(1);
  for (final configuration in configurations) {
    final process = await Process.start(
      Platform.resolvedExecutable,
      [
        'pub',
        'global',
        'run',
        'flutterfire_cli:flutterfire',
        'configure',
        if (project != null) '--project=$project',
        '--platforms=$_platforms',
        '--overwrite-firebase-options',
        '--out=lib/firebase_options_$flavor.dart',
        if (android != null) ...[
          '--android-package-name=$android',
          '--android-out=android/app/src/$flavor/google-services.json',
        ],
        if (ios != null) ...[
          '--ios-bundle-id=$ios',
          '--ios-out=ios/flavors/$flavor/GoogleService-Info.plist',
          '--ios-build-config=$configuration',
        ],
        ...rest,
      ],
      workingDirectory: app.path,
      // Without a terminal, flutterfire fails rather than wait for an answer.
      environment: terminal ? null : const {'CI': 'true'},
      mode: ProcessStartMode.inheritStdio,
    );
    final code = await process.exitCode;
    if (code != 0) {
      stderr.writeln(
        'flutterfire failed for the flavor $flavor (exit code $code). What it '
        'wrote stays, and running this script again does the rest. It needs '
        'the FlutterFire CLI, a login of the Firebase CLI and, on macOS, the '
        'Ruby gem xcodeproj: see the section Firebase of README.md.',
      );
      return code;
    }
    // The next runs need no answer.
    project ??= _projectOf(app, flavor);
  }

  await _format(app, flavor);
  for (final hook in _hooksOf(app)) {
    final process = await Process.start(
      Platform.resolvedExecutable,
      [hook.path],
      workingDirectory: app.path,
      mode: ProcessStartMode.inheritStdio,
    );
    final code = await process.exitCode;
    if (code != 0) {
      stderr.writeln(
        '${hook.path} failed (exit code $code). flutterfire configured the '
        'flavor $flavor, and running this script again runs it again.',
      );
      return code;
    }
  }
  stdout.writeln(
    'Configured the flavor $flavor for the Firebase project $project. Commit '
    'firebase.json and the files it names.',
  );
  if (ios != null && !Platform.isMacOS) {
    stdout.writeln(
      'flutterfire changes the Xcode project only on macOS, so this run left '
      'it and ios/flavors/$flavor/GoogleService-Info.plist as they were. Run '
      'dart tool/configure_firebase.dart $flavor again on a Mac for the iOS '
      'app.',
    );
  }
  return 0;
}

/// Whether someone can answer a question of flutterfire.
///
/// `stdin.hasTerminal` also holds for any other character device, such as the
/// `/dev/null` of cron, `nohup`, `ssh -n` or Docker without `-i`, where
/// flutterfire would wait forever. Only a terminal has an echo mode to read.
bool _hasTerminal() {
  try {
    stdin.echoMode;
    return true;
  } on StdinException {
    return false;
  }
}

/// The project that [arguments] name, as flutterfire reads it, with the last
/// one counting, and the other arguments.
(String?, List<String>) _withoutProject(List<String> arguments) {
  String? project;
  final rest = <String>[];
  for (var index = 0; index < arguments.length; index++) {
    final argument = arguments[index];
    if (argument == '--project' || argument == '-p') {
      // Another option is no id, and flutterfire would take it for one.
      if (++index == arguments.length || arguments[index].startsWith('-')) {
        throw _Stop('$argument needs the id of a Firebase project.');
      }
      project = arguments[index];
    } else if (argument.startsWith('--project=')) {
      project = argument.substring('--project='.length);
    } else if (argument.startsWith('-p')) {
      project = argument.substring('-p'.length);
    } else {
      rest.add(argument);
    }
  }
  if (project != null && project.isEmpty) {
    throw _Stop('--project needs the id of a Firebase project.');
  }
  return (project, rest);
}

/// The platforms of this run: those of the app, unless [rest] names others.
/// [rest] comes last on the command line of flutterfire, which takes the last
/// value of an option.
List<String> _platformsIn(List<String> rest) {
  var platforms = _platforms;
  for (var index = 0; index < rest.length; index++) {
    if (rest[index].startsWith('--platforms=')) {
      platforms = rest[index].substring('--platforms='.length);
    } else if (rest[index] == '--platforms' && index + 1 < rest.length) {
      platforms = rest[index + 1];
    }
  }
  return platforms.split(',');
}

/// Stops at an id that flutterfire would refuse, with what to do about it.
void _checkIds(String? android, String? ios) {
  if (android != null && !_packageName.hasMatch(android)) {
    throw _Stop(
      'flutterfire takes no application id like $android (it allows no '
      'underscore in its first part): use another org.',
    );
  }
  if (ios != null && !_bundleId.hasMatch(ios)) {
    throw _Stop(
      'flutterfire takes no bundle id like $ios (it allows no hyphen at either '
      'end of a part, and at most 63 characters in one): use another org.',
    );
  }
}

/// The project of the options of [flavor], which flutterfire wrote into
/// `firebase.json` of [app].
///
/// It reads the entry of the options: the keys of the Android apps in that
/// file depend on the path of the app.
String _projectOf(Directory app, String flavor) {
  final file = File('${app.path}/firebase.json');
  final json = file.existsSync() ? jsonDecode(file.readAsStringSync()) : null;
  Object? entry = json;
  for (final key in [
    'flutter',
    'platforms',
    'dart',
    'lib/firebase_options_$flavor.dart',
    'projectId',
  ]) {
    entry = entry is Map ? entry[key] : null;
  }
  if (entry is! String) {
    throw _Stop(
      '${file.path} names no Firebase project for the flavor $flavor, though '
      'flutterfire succeeded. Run this script again with --project=<id>.',
    );
  }
  return entry;
}

/// Formats the options of [flavor], which flutterfire writes in a format of
/// its own, so that the check of the format of the app passes. They work
/// without it, so a failure only warns.
Future<void> _format(Directory app, String flavor) async {
  final options = 'lib/firebase_options_$flavor.dart';
  final result = await Process.run(Platform.resolvedExecutable, [
    'format',
    options,
  ], workingDirectory: app.path);
  if (result.exitCode != 0) {
    stderr.writeln(
      'Warning: dart format left $options as flutterfire wrote it (exit code '
      '${result.exitCode}): ${result.stderr}',
    );
  }
}

/// The Dart files of the hooks directory of [app], by the order of their
/// names. An app whose modules have nothing to do after flutterfire has no
/// such directory.
List<File> _hooksOf(Directory app) {
  final directory = Directory('${app.path}/$_hooks');
  if (!directory.existsSync()) return const [];
  return [
    for (final entity in directory.listSync())
      if (entity is File && entity.path.endsWith('.dart')) entity,
  ]..sort((a, b) => a.path.compareTo(b.path));
}
