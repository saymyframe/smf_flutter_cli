# AGENTS.md

This guide tells coding agents what the code of this Flutter app does not show. Setup that needs a person or an account is in [README.md](README.md). When you change what a section describes, change the section too.

## App entry

The app is plain Flutter code that nothing regenerates. Change it by hand, unless a section below says what writes a file.

- `main()` in `lib/main.dart` initializes the binding, awaits `bootstrap()` and calls `runApp()`, in this order. Start-up code goes into `bootstrap()`.
- `bootstrap()` in `lib/bootstrap.dart` runs before the first frame, in four phases: what must come before anything else, then the platform services, then the services of the app, then what needs them. Put a new statement into its phase, and import neither `package:flutter/material.dart` nor `package:flutter/cupertino.dart` there.
- Put code that features share into `lib/core/<concern>/`, one directory for each concern. Put a feature, with its screens and their state, into `lib/features/<feature>/`.
- The root of the app asks the system for the icons of the status bar that suit the theme, around every screen, with `StatusBarIcons` of `lib/core/app/status_bar_icons.dart`: dark icons on a light theme, light ones on a dark theme. A screen without an app bar needs no `AnnotatedRegion` for them. Add one only to a screen whose top has another brightness than the theme, such as a picture behind the status bar.
- The app has the flavors `dev`, `staging` and `prod`. A `flutter` command without `--flavor` builds `dev`, in release mode too, so a build for a store takes `--flavor prod`. Code reads the flavor from `appFlavor` of `package:flutter/services.dart`. The app has one entry: add no `main_<flavor>.dart`.

- The section "Finish the setup" of the README lists the steps of the setup that no command can do, such as a step in the web console of a service that the app uses. Only the developer of the app does them: when a task depends on one of them, point the developer to that section, and do not try to do the step yourself.

After a change, run:

```bash
dart format lib test
flutter analyze
flutter test
```

Format only `lib/` and `test/`: `dart format .` also formats what Flutter writes into `build/`. The app as generated is formatted, `flutter analyze` finds no issue in it and `flutter test` passes.

- `App` in `lib/app.dart` is the root widget of the app and creates its one `MaterialApp`. Create no other in `lib/`: every screen is below it.
- The `theme`, `darkTheme`, `themeMode`, `locale` and localizations of the app go into the arguments of that `MaterialApp`.
- Tests mirror `lib/`: the test of `lib/<path>.dart` is `test/<path>_test.dart`.
- The app has only an Android and an iOS project, in `android/` and `ios/`.
- The entitlements of the iOS app, such as Push Notifications or Sign in with Apple, are in `ios/Runner/Runner.entitlements`. Every build configuration of the Runner target signs with this file, even while it is empty. The Signing & Capabilities tab of Xcode edits the same file.
- Each flavor is in `productFlavors` of `android/app/build.gradle.kts`, and on iOS in `ios/Runner.xcodeproj/xcshareddata/xcschemes/<flavor>.xcscheme` and in the build configurations `Debug-<flavor>`, `Profile-<flavor>` and `Release-<flavor>` of `ios/Runner.xcodeproj/project.pbxproj`. Change both places together. A new setting of the Runner target goes into each of its twelve build configurations.

## Firebase

- `bootstrap()` initializes Firebase with `DefaultFirebaseOptions` of `lib/firebase_options.dart`. That file is a placeholder until `flutterfire configure` writes it, and the app stops at start-up with an `UnsupportedError` until then. Do not write it by hand.
- `flutterfire configure` needs a Firebase account and someone to choose the project: run it only when asked, with the command of the section Firebase of `README.md`.
- A test that runs `main()` or `bootstrap()` starts Firebase, which needs the options of `flutterfire configure` and a mock of its platform side. Prefer a test of a widget, which needs neither.

## Notifications

- `appNotifications` in `lib/core/notifications/app_notifications.dart` shows the notifications of the app. `show()` shows one now, `schedule(notification, at: time)` at about that time, not to the minute, even if the app is closed by then. `cancel()` and `cancelAll()` remove them, and `scheduled()` lists those still to come, those of an owner too. A notification is an `AppNotification` with an `id`, a `title`, a `body` and `data`, and one with the id of a notification that is shown or scheduled takes its place. Give it an id from 0 up: a negative id is for a notification with an owner, which names it under `notificationOwnerKey` in its `data`, and whose taps go to `tapsOf(owner)` and `launchTapOf(owner)`.
- `appNotifications.permission` is `granted`, `denied` or `notAsked`. Ask with `appNotifications.request()` where the user turns on something that notifies, so that the question explains itself. Where the system has no question to show, as on Android before 13, the request opens its settings instead. After `denied` the system may not ask again (iOS asks only once, and Android stops after a second no), so open its settings with `appNotifications.openSettings()`. The app remembers that it asked under `notifications.asked`, so write nothing under that key.
- A tap on a notification reaches `appNotifications.taps` with the `data` of the notification, and the tap that launched the app is `appNotifications.launchTap`. Handle both once the first screen is shown, and navigate as the rest of the app does. A notification runs no code of the app when it shows.
- On Android a notification shows `android/app/src/main/res/drawable/ic_notification.xml` as its small icon. Change the drawing there and keep the name of the file.
- A new provider implements `NotificationsService` of `lib/core/notifications/notifications_service.dart`, and only the files of that implementation import it. The code of the app imports `lib/core/notifications/app_notifications.dart`, which exports `AppNotification` and `NotificationTap`, and calls neither `initNotifications()` nor `createNotificationsService()` nor `appNotifications.start()`.

- Nothing in this app asks for the permission yet: call `appNotifications.request()` where the user turns on something that notifies.

With `flutter_local_notifications`:

- `LocalNotificationsService` in `lib/core/notifications/local_notifications_service.dart` implements `NotificationsService` on `FlutterLocalNotificationsPlugin`. In `lib/`, only that file imports the package: other code shows notifications through `appNotifications`.
- Every notification goes to the channel `notificationChannelId` with the details in `_details` of that file. For another channel, such as one with another sound, create it with `createNotificationChannel()` of `AndroidFlutterLocalNotificationsPlugin` in `openLocalNotifications()`, and show a notification in it with details of its own.
- A scheduled notification uses an inexact alarm (`AndroidScheduleMode.inexactAllowWhileIdle`). Exact alarms need the permission `SCHEDULE_EXACT_ALARM`, which Google Play allows only for an app whose main feature needs them: change the mode only when asked.
- `android/app/src/main/AndroidManifest.xml` declares the receivers of the package, `android/app/build.gradle.kts` turns on core library desugaring, and `ios/Runner/AppDelegate.swift` sets the delegate of the notification center. Keep them: scheduled notifications, the Android build and the taps on iOS need them.
- The package has no platform side for tests. A test that runs `bootstrap()` answers the method channel `dexterous.com/flutter/local_notifications` itself, with `setMockMethodCallHandler` of `TestDefaultBinaryMessengerBinding.instance.defaultBinaryMessenger`, after `AndroidFlutterLocalNotificationsPlugin.registerWith()`.

## Preferences

- `AppPreferences` in `lib/core/preferences/app_preferences.dart` remembers the settings of the app between its launches, such as the theme mode. It is not encrypted: never save a token, a password, an API key or an encryption key in it.
- To remember a setting, write a function that takes the `AppPreferences` and add it to `_restorers` in that file. In it, read the setting, put it into the state that the widgets listen to, and keep the preferences in that state for its writes. The function awaits nothing, and keeps the current value when nothing is saved.
- Name a key `<owner id>.<setting>`, such as `theme.mode`, where the owner is the feature or the concern whose code keeps the setting.
- In the code of the app, do not call `createAppPreferences()` or `initPreferences()`. `bootstrap()` opens the preferences, and code gets them as the argument of its function in `_restorers`, or, with a DI container in the app, from the container. Widgets use the state and do not touch the preferences. A test may call both: `initPreferences()` opens the preferences again, as the next launch of the app does, and `createAppPreferences()` returns them.

With `shared_preferences`:

- In `lib/`, only `lib/core/preferences/shared_app_preferences.dart` imports the package. Other code uses `AppPreferences`.
- A number is read only as the type that it was saved as: `getDouble()` returns `null` for a key with an `int`, and `getInt()` for a key with a `double`.
- In a test that runs `bootstrap()`, first set `SharedPreferencesAsyncPlatform.instance = InMemorySharedPreferencesAsync.empty()`. Without it, opening the preferences throws. Both names are from the package `shared_preferences_platform_interface`: add it as a dev dependency.
- `pubspec.yaml` keeps `shared_preferences_android` at 2.5.2 or later. With 2.5.0 and 2.5.1, a release build fails to open the preferences on Android, because R8 renames Kotlin classes that the package looks up by name. Before you change the constraint, check that a release build of the app starts on Android.

## Push messages

- `appPush` in `lib/core/push/app_push.dart` receives the push messages of the app. A message is a `PushMessage` with `data`, and with an `id`, a `title` and a `body` when it has them.
- `appPush.address` is the address of this device for the backend that sends the messages. It is `null` until the platform gives one. Listen to it and send each new address to the backend: it may come late, and it may change. Never wait for it before the first frame.
- `appPush.messages` tells of each message that arrives while the app is in the foreground. A message with a title or a body also shows as a notification there, which needs the permission of the notifications of the app. `appNotifications.request()` asks for it.
- A tap on a message reaches `appPush.taps`, and the message whose tap launched the app is `appPush.launchMessage`. Handle both once the first screen is shown, and navigate as the rest of the app does. Such a tap does not reach `appNotifications.taps`.
- A message with data and no title or body reaches the app only while it is in the foreground.
- A new provider implements `PushService` of `lib/core/push/push_service.dart`, and only the files of that implementation import it. The code of the app imports `lib/core/push/app_push.dart`, which exports `PushMessage`, and calls neither `initPush()` nor `createPushService()` nor `appPush.start()`.

With `firebase_messaging`:

- `FirebasePushService` in `lib/core/push/firebase_push_service.dart` implements `PushService` on `FirebaseMessaging`. In `lib/`, only that file imports the package: other code receives push messages through `appPush`.
- The address of the device is its registration token of Firebase Cloud Messaging, from `getToken()`, and a new token comes on `onTokenRefresh`. On iOS there is none until the token of the Apple Push Notification service comes, and the package tells the app nothing when it comes. So while something listens to `addressChanges`, the service reads that token with `getAPNSToken()` now and then, for at most two minutes, and then tells of the registration token. Keep that wait.
- On iOS, `createFirebasePushService()` calls `setForegroundNotificationPresentationOptions()` with an alert, a badge and a sound. Keep it: the package answers iOS for every notification in the foreground, those of `appNotifications` too, and without these options iOS shows none of them.
- Never call `requestPermission()` of the package: the permission to show notifications belongs to `appNotifications.request()`.
- `android/app/src/main/AndroidManifest.xml` names the channel and the icon with which Android shows a message that arrives in the background, those of the notifications of the app. Change them together.
- The section Firebase Cloud Messaging of the README tells how to upload the key of the Apple Push Notification service and how to send this device a test message.
- The package has no platform side for tests. A test that runs `bootstrap()` answers the method channel `plugins.flutter.io/firebase_messaging` itself, with `setMockMethodCallHandler` of `TestDefaultBinaryMessengerBinding.instance.defaultBinaryMessenger`.

## Flavors

The app has three flavors, which install next to each other on a device, each under an id of its own:

| Flavor | Android application id | iOS bundle id |
| --- | --- | --- |
| `dev` | `com.example.my_app.dev` | `com.example.my-app.dev` |
| `staging` | `com.example.my_app.staging` | `com.example.my-app.staging` |
| `prod` | `com.example.my_app` | `com.example.my-app` |

A `flutter` command without `--flavor` builds `dev`, because `default-flavor` in `pubspec.yaml` says so. That holds in release mode too: `flutter build appbundle` and `flutter build ipa` build a release of `dev`, under its id. For a store, name the flavor:

```bash
flutter run --flavor staging
flutter build appbundle --flavor prod
flutter build ipa --flavor prod
```

Code reads the flavor from `appFlavor` of `package:flutter/services.dart`. A service that knows your app by its id, such as a store or a push provider, knows each flavor as an app of its own, so a step of its setup is repeated for each flavor that needs it.

## Flavors in the native projects

Each flavor is in two places, so change both when you rename, add or remove one:

- Android: `productFlavors` in `android/app/build.gradle.kts`, with its id suffix and its name on the device.
- iOS: `ios/Runner.xcodeproj/xcshareddata/xcschemes/<flavor>.xcscheme`, and the build configurations `Debug-<flavor>`, `Profile-<flavor>` and `Release-<flavor>` in each configuration list of `ios/Runner.xcodeproj/project.pbxproj`. The name of a flavor has no hyphen, since Flutter splits the name of a configuration on it.

In Xcode, select the scheme of a flavor, not `Runner`. That scheme builds the id and the name of `prod` with whichever flavor the last `flutter` command left in `ios/Flutter/Generated.xcconfig`.

## Firebase

The app uses [Firebase](https://firebase.google.com/docs/flutter/setup) through `firebase_core`: `bootstrap()` initializes it with the options of `DefaultFirebaseOptions` in `lib/firebase_options.dart`. `flutterfire configure` of the FlutterFire CLI writes these options when it registers the app in a Firebase project, together with `android/app/google-services.json`, `firebase.json` and, on macOS, `ios/Runner/GoogleService-Info.plist`. Until then, the options are a placeholder, and the app stops at start-up with an `UnsupportedError`.

To configure the app, or to configure it again, such as for another Firebase project or on another machine, run in its directory:

```bash
dart pub global activate flutterfire_cli 1.4.1
firebase login
flutterfire configure --platforms=android,ios --overwrite-firebase-options --ios-bundle-id=com.example.my-app --android-package-name=com.example.my_app
```

The command gives flutterfire the ids of the Android and iOS apps that SMF generated; if you change them, change them in the command too. `flutterfire configure` needs the [Firebase CLI](https://firebase.google.com/docs/cli), and changes the Xcode project only on macOS. The build phases that it adds to the Xcode project for some Firebase packages run `flutterfire` from `~/.pub-cache/bin`, so every machine that builds such an app for iOS needs the FlutterFire CLI activated too.

Configure the app with flutterfire_cli 1.4.1 or a later 1.x; if `dart pub global list` shows one already, skip its activation above.

## flutter_local_notifications

The app shows its notifications with [flutter_local_notifications](https://pub.dev/packages/flutter_local_notifications): `lib/core/notifications/local_notifications_service.dart` implements the notifications service of the app on it (see the section Notifications).

The module set up what the package needs in the native projects:

- `android/app/build.gradle.kts` turns on core library desugaring with `desugar_jdk_libs` 2.1.4, without which the Android build fails.
- `android/app/src/main/AndroidManifest.xml` declares the receivers of the package that show a scheduled notification at its time and set the scheduled ones again after a restart of the device or an update of the app, and the permission `android.permission.RECEIVE_BOOT_COMPLETED` for the restart.
- `ios/Runner/AppDelegate.swift` makes the app delegate the delegate of the notification center of iOS, so that a notification shows while the app is in the foreground and a tap reaches the app, also the tap that launched it.

Every notification goes to the channel `default`, with a high importance, which the service creates when the app starts. A scheduled notification uses an inexact alarm on Android, which needs no permission: Android may show it a few minutes late. To show notifications to the minute, declare `android.permission.SCHEDULE_EXACT_ALARM` in the manifest, ask for it with `requestExactAlarmsPermission()` of `AndroidFlutterLocalNotificationsPlugin`, and schedule with `AndroidScheduleMode.exactAllowWhileIdle`. Google Play allows exact alarms only for apps whose main feature needs them, such as an alarm clock or a calendar.

The app does not set up the actions of a notification, its buttons. They need the receiver `ActionBroadcastReceiver` on Android and, on iOS, a callback that registers the plugins for the isolate in which an action runs: see the README of the package.

## Notifications

The app shows notifications through `appNotifications` in `lib/core/notifications/app_notifications.dart`. `show()` shows one now and `schedule()` at a time to come, `cancel()` and `cancelAll()` remove them, and `scheduled()` lists those still to come. A scheduled notification shows at about its time, not to the minute, even if the app is closed by then, and after the device restarts. A tap on a notification reaches `appNotifications.taps` with the `data` of the notification, and `appNotifications.launchTap` is the tap that launched the app.

The app needs the permission of the user to show notifications. `appNotifications.permission` is `granted`, `denied` once the user said no or turned them off, or `notAsked`, and `appNotifications.request()` asks. Where the system has no question to show, as on Android before 13, the request opens the settings of the system for the notifications of the app instead. Nothing in this app asks yet. Call `appNotifications.request()` where the user turns on something that notifies, so that the question of the system explains itself. After `denied` the system may not ask again: iOS asks only once, and Android stops asking after a second no. `appNotifications.openSettings()` opens the settings of the system, where the user turns the notifications on.

On Android a notification shows `android/app/src/main/res/drawable/ic_notification.xml` as its small icon. Replace the bell there with the icon of the app, a shape on a transparent background, and keep the name of the file: `android/app/src/main/res/raw/notifications_keep.xml` keeps the icon in a release build. In the settings of the system, the channel of the notifications has the name of the app.

## Firebase Cloud Messaging

The app receives its push messages with [firebase_messaging](https://pub.dev/packages/firebase_messaging): `lib/core/push/firebase_push_service.dart` implements the push service of the app on it (see the section Push messages). The address of this device is its registration token of Firebase Cloud Messaging.

Firebase sends messages to iOS through the Apple Push Notification service (APNs), with an APNs key of your team, which you upload by hand once for the project:

1. In your Apple Developer account, under Certificates, Identifiers & Profiles, create a key under Keys with the Apple Push Notifications service (APNs) enabled. Download its `.p8` file, and note its Key ID and your Team ID.
2. In the Firebase console, open the settings of the project, then Cloud Messaging, and upload the key under the configuration of the Apple app, with its Key ID and your Team ID.

A key sends only to the apps of its team, so register the bundle id of the app as an App ID in that team, with Push Notifications. The key matters only for sending: the iOS app gets its address without it, but Firebase cannot send to that address. The section Finish the setup lists the upload among the steps that you do by hand.

To send this device a test message, run the app in debug mode and copy the address that it prints. In the Firebase console, open Messaging, create a notification campaign, choose Send test message and paste the address. A server sends a message with the HTTP v1 API of Firebase Cloud Messaging: `POST https://fcm.googleapis.com/v1/projects/<project-id>/messages:send`, with an OAuth token of a service account of the project and the address as the `token` of the message.

`android/app/src/main/AndroidManifest.xml` names the channel `default` of the notifications of the app (`com.google.firebase.messaging.default_notification_channel_id`) and their small icon `@drawable/ic_notification` (`com.google.firebase.messaging.default_notification_icon`). Android shows a message that arrives in the background with them.

On iOS, firebase_messaging answers the system for every notification that arrives while the app is in the foreground, the notifications that the app shows itself too. So the service sets its presentation options to an alert, a badge and a sound when the app starts (`setForegroundNotificationPresentationOptions()`): without them, iOS would show none of these notifications in the foreground.

The app runs no code for a message that arrives in the background. To handle one, register a top-level function with `FirebaseMessaging.onBackgroundMessage()` in `main()`. It runs in an isolate of its own, without what `bootstrap()` sets up.

## Push messages

The app receives push messages through `appPush` in `lib/core/push/app_push.dart`.

`appPush.address` is the address of this device. The backend of the app sends its messages there. It is `null` until the platform gives one, and the app works without it. Send each new address to the backend: it may come late, and it may change. In debug mode the app prints it, so you can send this device a message by hand.

On iOS the address needs a token of the Apple Push Notification service (APNs). iOS gives one only to a build signed with the entitlement `aps-environment`, which `ios/Runner/Runner.entitlements` has. The iOS simulator on a Mac gets a token. One on a macOS virtual machine, such as a hosted CI runner, never does. On an iPhone, signing with the entitlement needs a team of the paid Apple Developer Program. With a free personal team, Xcode cannot sign the app: to run it on an iPhone, remove the key `aps-environment` from `ios/Runner/Runner.entitlements`, and the app runs there without an address. The simulator needs no change. The value `development` suits the builds that you run from Xcode. When Xcode exports the app for distribution, it takes the value of the provisioning profile (production for a distribution profile).

A message that arrives while the app is in the foreground reaches `appPush.messages`. One with a title or a body also shows as a notification, as it does in the background. Where the system does not show it, the app shows it with `appNotifications`. Either way the user has to allow the notifications of the app, as the section Notifications tells. In the background the system shows the message, on Android in the channel of the notifications of the app.

`appPush.taps` tells of each tap on a message while the app runs, and `appPush.launchMessage` is the message whose tap launched the app. Read both once the first screen is shown, and navigate as the rest of the app does. A tap on a message does not reach `appNotifications.taps`, so the code of the app sees each tap once.

A message with data and no title or body reaches the app only while it is in the foreground. In the background, or when the app is closed, it runs no code of the app. Images in a message do not show on iOS, which needs an extension of the app for them.

/// Whether the app may show notifications.
enum NotificationPermission {
  /// The user allowed it.
  granted,

  /// The app asked, and the user did not allow it or turned the
  /// notifications of the app off later. The system may ask no more: iOS
  /// asks once, and Android after a second no. So the app opens its
  /// settings, where the user turns the notifications on:
  /// [NotificationsController.openSettings].
  denied,

  /// The app may not show notifications, and has not asked yet.
  notAsked,
}

/// The key under which a notification with an owner names its owner in its
/// [AppNotification.data], such as a push message that the app shows itself.
///
/// [NotificationsController.taps] and [NotificationsController.launchTap]
/// leave out the taps on such a notification, which
/// [NotificationsController.tapsOf] and
/// [NotificationsController.launchTapOf] give to the owner. A notification
/// with an owner has a negative id, so that it never takes the place of a
/// notification of the app.
const String notificationOwnerKey = 'notifications.owner';

/// The notifications of the app: the permission to show them, the
/// notifications that the app shows now or at a time to come, and the taps
/// of the user on them.
final appNotifications = NotificationsController._();

/// Shows the notifications of the app through the service of the provider
/// of notifications, keeps the permission to show them up to date, and
/// tells of the taps on them. The app has one, [appNotifications].
///
/// A call made before the app started the service waits for it, and fails
/// with the error of that start if it fails.
///
/// What the service throws reaches the code that called. An error of the
/// service when the user comes back to the app, or one that its taps send,
/// has no caller, so it reaches the handlers of the uncaught errors of the
/// app, and the controller goes on.
final class NotificationsController {
  NotificationsController._();

  /// The key under which the preferences remember that the app asked for
  /// the permission.
  static const _askedKey = 'notifications.asked';

  /// The smallest and the largest id of a notification: the platforms keep
  /// it in 32 bits.
  static const _smallestId = -0x80000000;
  static const _largestId = 0x7FFFFFFF;

  NotificationsService? _service;
  StreamSubscription<NotificationTap>? _serviceTaps;
  NotificationTap? _launchTap;

  /// Whether the app has started for the first time, also when that start
  /// failed.
  bool _started = false;

  /// What the calls made before the first start wait for, each created by
  /// its call. The first start completes them, with its error if it failed,
  /// each in the zone of its call: created with the controller, they would
  /// complete in a microtask of the zone that read [appNotifications]
  /// first, which may run none any more, as the fake time of a widget test
  /// that is over before a later test starts the app in real time.
  final List<Completer<void>> _untilStarted = [];

  /// The preferences that remember that the app asked, once the app opened
  /// them.
  AppPreferences? _preferences;

  /// Whether the app asked for the permission.
  bool _asked = false;

  /// Whether the service last said that the app may show notifications.
  bool _enabled = false;

  /// The request for the permission that is on its way, if any.
  Future<NotificationPermission>? _request;

  /// Tells when the user comes back to the app.
  _ResumeObserver? _observer;

  final StreamController<NotificationTap> _taps =
      StreamController<NotificationTap>.broadcast();

  final ValueNotifier<NotificationPermission> _permission = ValueNotifier(
    NotificationPermission.notAsked,
  );

  /// Whether the app may show notifications. It follows what the user
  /// answers, and what the user changed in the settings of the system once
  /// the user comes back to the app. A widget follows it with a
  /// `ValueListenableBuilder`.
  ValueListenable<NotificationPermission> get permission => _permission;

  /// The tap on a notification of the app that launched the app, or `null`
  /// if the app was launched in another way: known once `bootstrap()` is
  /// over. The tap is not among the [taps]. It is `null` for a tap on a
  /// notification of an owner, as [taps] leaves those out.
  NotificationTap? get launchTap => switch (_launchTap) {
    final tap? when _isOfApp(tap) => tap,
    _ => null,
  };

  /// Tells of each tap on a notification of the app while the app runs,
  /// with the data of the notification: a broadcast stream, the same for
  /// the life of the app. It leaves out the taps on the notifications of an
  /// owner, which [tapsOf] gives, and those with a negative id: the
  /// notification of an owner whose data the provider could not read.
  late final Stream<NotificationTap> taps = _taps.stream.where(_isOfApp);

  /// Tells of each tap on a notification whose owner is [owner], as it is
  /// under [notificationOwnerKey] in its data: a broadcast stream.
  Stream<NotificationTap> tapsOf(String owner) =>
      _taps.stream.where((tap) => _ownerOf(tap) == owner);

  /// The tap on a notification whose owner is [owner] that launched the
  /// app, or `null`.
  NotificationTap? launchTapOf(String owner) => switch (_launchTap) {
    final tap? when _ownerOf(tap) == owner => tap,
    _ => null,
  };

  /// Starts with [service]: takes the tap that launched the app, follows
  /// the taps, and asks whether the app may show notifications.
  ///
  /// `initNotifications()` calls it in `bootstrap()`, so [permission] and
  /// [launchTap] are known before the first frame. It may be called again,
  /// with the service that the app has from then on: `initNotifications()`
  /// does so in a test of the next launch of the app, and a test gives it a
  /// service of its own.
  ///
  /// If the service fails to tell whether the app may show notifications,
  /// the future fails with its error, and so do the calls that waited for
  /// the first start. A call after that goes to the service.
  Future<void> start(NotificationsService service) async {
    unawaited(_serviceTaps?.cancel());
    _service = service;
    _launchTap = service.launchTap;
    // An error of the taps has no caller: it reaches the handlers of the
    // uncaught errors of the app, and the taps go on.
    _serviceTaps = service.taps.listen(_taps.add);
    if (_observer == null) {
      final observer = _observer = _ResumeObserver(() => unawaited(_refresh()));
      WidgetsBinding.instance.addObserver(observer);
    }
    try {
      await _refresh();
    } on Object catch (error, stackTrace) {
      _firstStarted(error, stackTrace);
      rethrow;
    }
    _firstStarted();
  }

  /// has it, and completes with the permission once the user answered.
  ///
  /// Ask where the user turns on something that notifies, so that the
  /// question explains itself. Where the platform has no question, the
  /// service opens the settings of the system instead. After
  /// [NotificationPermission.denied] the system may ask no more: iOS asks
  /// once, and Android after a second no. So open its settings then:
  /// [openSettings].
  ///
  /// A request while another is on its way completes with that one. If the
  /// preferences fail to save that the app asked, the future completes with
  /// their error: [permission] is up to date by then, but the next launch
  /// of the app takes it that the app has not asked.
  Future<NotificationPermission> request() =>
      _request ??= _ask().whenComplete(() => _request = null);

  /// Opens the settings of the system for the notifications of the app.
  Future<void> openSettings() async => (await _ready()).openSettings();

  /// Shows [notification] now.
  ///
  /// Its id is a 32-bit integer, 0 or more unless the notification has an
  /// owner under [notificationOwnerKey] in its data, which takes a negative
  /// id. Its future fails with an [ArgumentError] for another id.
  Future<void> show(AppNotification notification) async {
    _check(notification);
    await (await _ready()).show(notification);
  }

  /// Shows [notification] at about [at], not to the minute, also when the
  /// app is closed then. Its future fails with an [ArgumentError] when [at]
  /// is not in the future, and for an id that [show] does not take.
  Future<void> schedule(
    AppNotification notification, {
    required DateTime at,
  }) async {
    _check(notification);
    if (!at.isAfter(DateTime.now())) {
      throw ArgumentError.value(at, 'at', 'The time is not in the future');

    await (await _ready()).schedule(notification, at);
  }

  Future<void> cancel(int id) async => (await _ready()).cancel(id);

  /// Removes every notification of the app, shown or scheduled, those of an
  /// owner too.
  Future<void> cancelAll() async => (await _ready()).cancelAll();

  /// The notifications that are scheduled and not shown yet, those of an

  Future<List<AppNotification>> scheduled() async =>

  Future<NotificationsService> _ready() async {
    if (!_started) {
      final untilStarted = Completer<void>();
      _untilStarted.add(untilStarted);
      await untilStarted.future;
    }
    return _service!;
  }

  /// Takes it that the app has started for the first time, unless it had,
  /// and lets the calls that waited for that go on, or fail with [error] of
  /// the start. Nothing but these calls reports that error, which the start
  /// throws itself.
  void _firstStarted([Object? error, StackTrace? stackTrace]) {
    if (_started) return;
    _started = true;
    for (final untilStarted in _untilStarted) {
      if (error == null) {
        untilStarted.complete();
      } else {
        untilStarted.completeError(error, stackTrace);
      }
    }
    _untilStarted.clear();
  }

  Future<NotificationPermission> _ask() async {
    final service = await _ready();
    if (await service.areEnabled()) {
      _enabled = true;
      _update();
      return _permission.value;
    }
    await service.request();
    _asked = true;
    _enabled = await service.areEnabled();
    _update();
    await _preferences?.setBool(_askedKey, true);
    return _permission.value;
  }

  /// Asks the service whether the app may show notifications.
  Future<void> _refresh() async {
    _enabled = await _service!.areEnabled();
    _update();
  }

  /// Takes that the app asked from [preferences], and keeps it as it is when
  /// they have nothing saved. It keeps [preferences] for the next request.
  void _restore(AppPreferences preferences) {
    _preferences = preferences;
    _asked = preferences.getBool(_askedKey) ?? _asked;
    _update();
  }

  void _update() => _permission.value = _enabled
      ? NotificationPermission.granted
      : _asked
      ? NotificationPermission.denied
      : NotificationPermission.notAsked;

  static String? _ownerOf(NotificationTap tap) =>
      tap.data[notificationOwnerKey];

  /// Whether [tap] is on a notification of the app: one without an owner,
  /// whose id is not negative.
  static bool _isOfApp(NotificationTap tap) =>
      tap.id >= 0 && _ownerOf(tap) == null;

  /// Throws an [ArgumentError] for an id of [notification] that the app
  /// does not take; see [show].
  static void _check(AppNotification notification) {

    if (id < _smallestId || id > _largestId) {

            'under notificationOwnerKey in its data',

    }
    if (id >= 0 && owned) {
      throw ArgumentError.value(
        id,
        'id',
        'A notification with an owner has a negative id',
      );
    }
  }
}

  Future<void> request() async {

    WidgetsBinding.instance.addObserver(question);
    final bool allowed;
    try {
      allowed = await _ask();
    } finally {
      WidgetsBinding.instance.removeObserver(question);
    }
    if (!allowed && !question.shown) await openSettings();

      badge: true,
      sound: true,
    );

  }

  @override
  Future<void> show(AppNotification notification) async {
    // Android keeps the alarm of a scheduled notification when one with its
    // id is shown, so it would show again later.
    final pending = await _plugin.pendingNotificationRequests();

      id: notification.id,
      title: notification.title,
      body: notification.body,
      notificationDetails: _details,
      payload: jsonEncode(notification.data),
    );

        title: notification.title,

      );

  Future<void> cancel(int id) => _plugin.cancel(id: id);

  @override
  Future<void> cancelAll() => _plugin.cancelAll();

      AppNotification(
        id: request.id,
        title: request.title ?? '',
        body: request.body,
        data: _dataOf(request.payload),
      ),
  ];
}

/// provider of push messages. The app has one, [appPush].
///
/// It shows a message with a title or a body that arrives while the app is
/// in the foreground as a notification of the app, through
/// [appNotifications], where the platform does not show it itself. Such a
/// notification has [appPush] as its owner, so a tap on it reaches [taps]
/// and not [NotificationsController.taps].
///
/// An error of the service on its streams, of a notification that the
/// controller shows, of an address that it asks for, or of the message that
/// launched the app, has no caller, so it reaches the handlers of the
/// uncaught errors of the app, and the controller goes on.
final class AppPushController {
  AppPushController._();

  /// The owner of the notifications that show the messages, under
  /// [notificationOwnerKey] in their data.
  static const _owner = 'push';

  /// The key under which such a notification keeps its message in its data.
  static const _messageKey = 'push.message';

  PushService? _service;
  StreamSubscription<PushMessage>? _serviceMessages;
  StreamSubscription<PushMessage>? _serviceTaps;
  StreamSubscription<String>? _serviceAddresses;
  StreamSubscription<NotificationTap>? _notificationTaps;
  PushMessage? _launchMessage;

  /// The service whose address the controller is asking for, if any.
  PushService? _asking;

  /// Tells when the user comes back to the app.
  _ResumeObserver? _observer;

      StreamController<PushMessage>.broadcast();

  final StreamController<PushMessage> _taps =
      StreamController<PushMessage>.broadcast();

  /// The address of the device, to which the backend of the app sends the
  /// messages for it, or `null` while the platform gives none. Send each new
  /// one to the backend: it may come late, such as on iOS, and it may
  /// change. A widget follows it with a `ValueListenableBuilder`.
  ///
  /// The controller asks for it when it starts, without waiting for it, and
  /// again each time the user comes back to the app while it has none.
  ValueListenable<String?> get address => _address;

  /// The message whose tap launched the app, or `null` if the app was
  /// launched in another way: known once `bootstrap()` is over. The message
  /// is not among the [taps].
  PushMessage? get launchMessage => _launchMessage;

  /// Tells of each message that arrives while the app is in the foreground:
  /// a broadcast stream, the same for the life of the app.
  late final Stream<PushMessage> messages = _messages.stream;

  /// Tells of each tap of the user on a message while the app runs, whether
  /// the platform or the app showed it: a broadcast stream, the same for the
  /// life of the app.
  late final Stream<PushMessage> taps = _taps.stream;

  /// Starts with [service]: follows its messages, its taps and its address,
  /// asks for the address without waiting for it, and takes the message
  /// whose tap launched the app.
  ///
  /// `initPush()` calls it in `bootstrap()`, after the notifications of the
  /// app started, so [launchMessage] is known before the first frame. It may
  /// be called again, with the service that the app has from then on:
  /// `initPush()` does so in a test of the next launch of the app, and a
  /// test gives it a service of its own. The address is then that of the
  /// new service, and `null` until it gives one.
  ///
  /// If the service fails to give the message that launched the app, the
  /// app still starts: the error reaches the handlers of the uncaught errors
  /// of the app, and [launchMessage] is the message of a notification that
  /// the app showed, if its tap launched the app, or `null`.
  Future<void> start(PushService service) async {
    unawaited(_serviceMessages?.cancel());
    unawaited(_serviceTaps?.cancel());
    unawaited(_serviceAddresses?.cancel());
    _service = service;
    _launchMessage = null;
    _address.value = null;
    // An error of these streams has no caller: it reaches the handlers of
    // the uncaught errors of the app, and the streams go on.
    _serviceMessages = service.messages.listen(_onMessage);
    _serviceTaps = service.taps.listen(_taps.add);
    _serviceAddresses = service.addressChanges.listen(_setAddress);
    _notificationTaps ??= appNotifications
        .tapsOf(_owner)
        .listen((tap) => _taps.add(_messageIn(tap.data)));
    if (_observer == null) {
      final observer = _observer = _ResumeObserver(_askForAddress);
      WidgetsBinding.instance.addObserver(observer);
    }
    _askForAddress();
    PushMessage? launched;
    try {
      launched = await service.launchMessage();
    } on Object catch (error, stackTrace) {
      // A provider that fails here would otherwise keep the app from
      // starting.
      Zone.current.handleUncaughtError(error, stackTrace);
    }
    final tap = appNotifications.launchTapOf(_owner);
    _launchMessage = launched ?? (tap == null ? null : _messageIn(tap.data));
  }

  /// Asks the service for the address while the controller has none, unless
  /// it is asking already.
  void _askForAddress() {
    final service = _service!;
    if (_address.value != null || identical(_asking, service)) return;
    _asking = service;
    unawaited(_answer(service));
  }

  Future<void> _answer(PushService service) async {
    try {
      final address = await service.address();
      // An answer of a service that the controller no longer has, or one
      // after the service told of an address, changes nothing.
      if (address != null &&
          identical(service, _service) &&
          _address.value == null) {
        _setAddress(address);
      }
    } finally {
      if (identical(_asking, service)) _asking = null;
    }
  }

  void _setAddress(String address) {
    if (address == _address.value) return;
    _address.value = address;
    if (kDebugMode) {
      debugPrint('The address of this device for push messages: $address');
    }
  }

  /// Tells of [message], and shows it as a notification of the app if the
  /// platform does not show it and it has a title or a body. An empty title
  /// or body counts as none.
  void _onMessage(PushMessage message) {
    _messages.add(message);
    final title = _textOf(message.title);
    final body = _textOf(message.body);
    final text = title ?? body;
    if (text == null || _service!.platformShowsInForeground) return;
    final json = jsonEncode({
      'id': message.id,
      'title': message.title,
      'body': message.body,
      'data': message.data,
    });
    unawaited(
      appNotifications.show(
        AppNotification(
          // An equal message takes the same id, so its notification takes
          // the place of the one that showed it before rather than adding
          // another, and a negative one, so it never takes the place of a
          // notification of the app.
          id: -1 - (json.hashCode & 0x7FFFFFFF),
          // A message with a body alone shows it as its title.
          title: text,
          body: title == null ? null : body,
          data: {
            ...message.data,
            notificationOwnerKey: _owner,
            _messageKey: json,
          },
        ),
      ),
    );
  }

  /// [text], or `null` if it is empty.
  static String? _textOf(String? text) =>
      text == null || text.isEmpty ? null : text;

  /// The message that [data], the data of a notification that showed a
  /// message, keeps under [_messageKey], or a message with the rest of the
  /// data if the notification lost it.
  static PushMessage _messageIn(Map<String, String> data) =>
      switch (_decoded(data[_messageKey])) {
        {
          'id': final String? id,
          'title': final String? title,
          'body': final String? body,
          'data': final Map<String, Object?> values,
        }
            when values.values.every((value) => value is String) =>
          PushMessage(
            id: id,
            title: title,
            body: body,
            data: Map<String, String>.from(values),
          ),
        _ => PushMessage(
          data: {
            for (final MapEntry(:key, :value) in data.entries)
              if (key != notificationOwnerKey && key != _messageKey) key: value,
          },
        ),
      };

  /// What the JSON [text] holds, or `null` for no text or one that is no
  /// JSON.
  static Object? _decoded(String? text) {
    if (text == null) return null;
    try {
      return jsonDecode(text);
    } on FormatException {
      return null;
    }
  }

  /// Creates the service on [messaging].
  ///

  /// plugin, so that the messages and the taps that the platform tells of
  /// from then on reach the streams of the service.

  final Stream<String> _tokens;

  /// service, since [address] failed for want of it.
  bool _awaitingApnsToken = false;

  Timer? _nextCheck;

  /// has waited for that token so far.

  Duration _waited = Duration.zero;

  bool get platformShowsInForeground =>

  );

  final Stream<PushMessage> taps = FirebaseMessaging.onMessageOpenedApp.map(

  );

      return await _messaging.getToken();
    } on FirebaseException catch (error) {

      // The plugin gives no token on iOS before the device has the token of
      // the Apple Push Notification service.
      if (error.code == 'apns-token-not-set') _awaitApnsToken();
      return null;
    } on Object catch (error) {
      // Android has no token without Google Play services or a network.
      _printWithoutAddress(error);
      return null;
    }
  }

    try {
      final message = await _messaging.getInitialMessage();
      return message == null ? null : _messageOf(message);
    } on Object catch (error) {

        debugPrint('Firebase Cloud Messaging has no launch message: $error');
      }
      return null;
    }

    if (kDebugMode) {
      debugPrint('Firebase Cloud Messaging has no address yet: $error');
    }
  }

    _tokenSubscription = _tokens.listen(_tellAddress);
    if (_awaitingApnsToken) _scheduleCheck();

  /// No timer of the service outlives the last listener.
  Future<void> _stopListening() async {
    _nextCheck?.cancel();
    _nextCheck = null;
    await _tokenSubscription?.cancel();
    _tokenSubscription = null;
  }

  void _tellAddress(String address) {
    _awaitingApnsToken = false;
    _nextCheck?.cancel();

  void _awaitApnsToken() {
    if (_awaitingApnsToken) return;
    _awaitingApnsToken = true;
    _wait = _firstWait;
    _waited = Duration.zero;
    if (_addresses.hasListener) _scheduleCheck();

  void _scheduleCheck() {
    if (_nextCheck != null) return;
    if (_waited >= _longestWatch) {
      _awaitingApnsToken = false;
      return;

    final wait = _wait;
    _waited += wait;
    _wait = wait * 2 > _longestWait ? _longestWait : wait * 2;
    _nextCheck = Timer(wait, () => unawaited(_checkApnsToken()));
  }

  /// Asks iOS for the token of the Apple Push Notification service, and
  /// once it has one, Firebase for the registration token, which it tells
  /// of.
  Future<void> _checkApnsToken() async {
    _nextCheck = null;
    String? apnsToken;
    try {
      apnsToken = await _messaging.getAPNSToken();
    } on Object {
      apnsToken = null;
    }
    if (!_awaitingApnsToken || !_addresses.hasListener) return;
    if (apnsToken == null) return _scheduleCheck();
    _awaitingApnsToken = false;
    try {
      final address = await _messaging.getToken();
      if (address != null && _addresses.hasListener) _addresses.add(address);
    } on Object catch (error) {
      _printWithoutAddress(error);
    }
  }

/// The push messages of the platform, which the provider of push messages
/// implements: the address of the device, the messages that arrive while
/// the app is in the foreground, and the taps of the user on the messages
/// that the platform shows.
///
/// The code of the app does not use it: it uses `appPush` of
/// `app_push.dart`, which calls this service, shows a message in the
/// foreground where the platform does not, and tells of the taps on the
/// messages that it showed.
///
/// Every implementation keeps to this:
/// - The function that creates the service asks the user nothing. It may be
///   called again, and the service that it returns then has the address
///   that the device kept.
/// - The service never asks for the permission to show notifications, which
///   the notifications of the app ask for, and never keeps the notifications
///   of the app from showing while the app is in the foreground.
/// - [address] completes with the address of the device, or with `null`
///   while the platform gives none, and does not throw. It needs no
///   permission. The address stays the same from one launch of the app to
///   the next, unless the platform gives the device another, which
///   [addressChanges] tells of.
/// - [addressChanges] tells of each new address, and of the first address
///   that the device gets after [address] completed with `null`, such as
///   one that comes late on iOS.
/// - [messages] tells of each message that arrives while the app is in the
///   foreground, once.
/// - A value of the data of a message that the platform gives as something
///   other than a string becomes its JSON, as `jsonEncode` writes it.
/// - A message with a title or a body that arrives while the app is in the
///   background, or closed, is shown by the platform, on Android in the
///   channel of the notifications of the app. [taps] tells of each tap on
///   such a message while the app runs, and [launchMessage] is the message
///   whose tap launched the app, which is not among the [taps].
/// - In the foreground, the platform or the provider shows such a message
///   where [platformShowsInForeground] is true, and [taps] then tells of a
///   tap on it too. Where it is false, the service shows nothing of the
///   message, and the app shows it as a notification of its own.
/// - [launchMessage] completes without the network, and does not throw.
abstract interface class PushService {
  /// Whether the platform or the provider shows a message with a title or a
  /// body that arrives while the app is in the foreground. The app shows it
  /// otherwise.
  bool get platformShowsInForeground;

  /// The address of the device, to which a server sends the messages for
  /// this app, or `null` while the platform gives none.
  Future<String?> address();

  /// Tells of each new address of the device, and of the first one after
  /// [address] gave none: a broadcast stream.
  Stream<String> get addressChanges;

  /// Tells of each message that arrives while the app is in the foreground:
  /// a broadcast stream.
  Stream<PushMessage> get messages;

  /// Tells of each tap of the user on a message that the platform showed,
  /// while the app runs: a broadcast stream. The tap that launched the app
  /// is not among them.
  Stream<PushMessage> get taps;

  /// The message whose tap launched the app, or `null` if the app was
  /// launched in another way.
  Future<PushMessage?> launchMessage();
}

/// What the widget asks the system for on a screen in [theme].
Future<SystemUiOverlayStyle> _styleIn(
  WidgetTester tester,
  ThemeData theme,
) async {
  await tester.pumpWidget(
    MaterialApp(
      theme: theme,
      home: const StatusBarIcons(child: Text('A screen')),
    ),
  );
  return tester
      .widget<AnnotatedRegion<SystemUiOverlayStyle>>(
        find.descendant(
          of: find.byType(StatusBarIcons),
          matching: find.byType(AnnotatedRegion<SystemUiOverlayStyle>),
        ),
      )
      .value;
}
