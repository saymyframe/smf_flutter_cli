# AGENTS.md

This guide tells coding agents what the code of this Flutter app does not show. Setup that needs a person or an account is in [README.md](README.md). When you change what a section describes, change the section too.

## App entry

The app is plain Flutter code that nothing regenerates. Change it by hand, unless a section below says what writes a file.

- `main()` in `lib/main.dart` initializes the binding, awaits `bootstrap()` and calls `runApp()`, in this order. Start-up code goes into `bootstrap()`.
- `bootstrap()` in `lib/bootstrap.dart` runs before the first frame, in four phases: what must come before anything else, then the platform services, then the services of the app, then what needs them. Put a new statement into its phase, and import neither `package:flutter/material.dart` nor `package:flutter/cupertino.dart` there.
- Put code that features share into `lib/core/<concern>/`, one directory for each concern. Put a feature, with its screens and their state, into `lib/features/<feature>/`.

After a change, run:

```bash
dart format lib test
flutter analyze
flutter test
```

Format only `lib/` and `test/`: `dart format .` also formats what Flutter writes into `build/`. The app as generated is formatted, `flutter analyze` finds no issue in it and `flutter test` passes.

- `App` in `lib/app.dart` is the root widget of the app and creates its one `MaterialApp`. Create no other in `lib/`: every screen is below it.
- The `theme`, `darkTheme`, `themeMode`, `locale` and localizations of the app go into the arguments of that `MaterialApp`.
- Tests mirror `lib/`: the test of `lib/<path>.dart` is `test/<path>_test.dart`.
- The app has only an Android and an iOS project, in `android/` and `ios/`.

## Localization

- Show the user no text from a string literal. Read each text as `context.l10n.<name>`, with `lib/core/l10n/l10n.dart` imported, where `context` is a `BuildContext` below the root of the app. Such an expression is no constant, so the widget around it cannot be `const`.
- `appLocales` in `lib/core/l10n/app_locale.dart` lists the languages of the app. The app is in the one that the device prefers among them, and in the first of the list when the device asks for none of them.
- `appLocale` in that file holds the language that the user chose, or `null` while the app follows the device. Set `appLocale.value` to one of `appLocales`, or to `null`, and the root of the app rebuilds in that language. Pass no `locale` and no `supportedLocales` to the root `MaterialApp` anywhere else.
- Every delegate among the `localizationsDelegates` of the root has to support each language of `appLocales`. A new language, one in which Flutter has the texts of its own widgets, goes into that list, into `CFBundleLocalizations` in the Info.plist of the iOS app, and into the texts of the app.

With `gen-l10n` of Flutter:

- The texts of the app are in the ARB files of `lib/l10n`. `lib/l10n/app_en.arb` has every text in English, and `lib/l10n/app_<code>.arb` the translations into another language. A text that such a file lacks reads in English there.
- To add a text, add it to `lib/l10n/app_en.arb` under a name in lowerCamelCase, and its translations under the same name to the other files. Then run `flutter pub get`, which generates `context.l10n.<name>`.
- Do not edit `lib/l10n/app_localizations*.dart`: `gen-l10n` writes those files from the ARB files, as `l10n.yaml` says. After adding the ARB file of a new language, run `flutter gen-l10n`, because `flutter pub get` does not notice a new file.
- Write an apostrophe in a text once: `l10n.yaml` turns the escapes of `gen-l10n` off (`use-escaping: false`).

# my_app

A new Flutter project.

## Texts

The texts of the app are in the ARB files of `lib/l10n`, one for each language. `lib/l10n/app_en.arb` has every text in English, and the file of another language, such as `app_uk.arb`, has the translations into it. [gen-l10n](https://docs.flutter.dev/ui/internationalization) of Flutter generates the `AppLocalizations` class from these files, as `l10n.yaml` says, and writes it into `app_localizations.dart` and a file for each language in the same directory. `flutter pub get` runs it when one of the ARB files changed or the files it writes are missing, so you can commit those files or leave them out of the repository. Code reads a text as `context.l10n.<name>` with `lib/core/l10n/l10n.dart` imported, where `context` is a `BuildContext` below the root of the app.

To add a text, add it to `lib/l10n/app_en.arb` under a name of its own, and its translations under the same name to the files of the other languages. A text without a translation into a language reads in English there.

The texts of a new language, such as German, go into a file of their own:

1. Add `lib/l10n/app_de.arb` with `"@@locale": "de"` and the translations.
2. Run `flutter gen-l10n`, because `flutter pub get` does not notice a new ARB file.

The section "Languages" tells where else the new language goes.

## Languages

The app is in the languages of `appLocales` in `lib/core/l10n/app_locale.dart`. It shows its texts in the language that the device prefers among them, and in the first of the list when the device asks for none of them.

To add a language in which Flutter has the texts of its own widgets, such as German, add the texts of the app in German, and then:

1. Add `Locale('de')` to `appLocales`.
2. Add `de` to `CFBundleLocalizations` in `ios/Runner/Info.plist`, which tells iOS the languages of the app.

=== lib/core/l10n/app_locale.dart (role:localization) ===
import 'package:flutter/widgets.dart';

/// The languages of the app. The app shows its texts in the language that
/// the device prefers among them, and in the first of the list when the
/// device asks for none of them.
const appLocales = <Locale>[Locale('en')];

/// The language that the user chose for the app, or `null` while the app
/// follows the languages of the device.
///
/// Set its value to one of [appLocales], or to `null`, to change the
/// language: the root of the app, which reads it through [AppLocaleScope],
/// rebuilds in the new language.
final appLocale = ValueNotifier<Locale?>(null);

/// Gives the root of the app the language that the user chose, and rebuilds
/// the root when the choice changes.
class AppLocaleScope extends InheritedNotifier<ValueNotifier<Locale?>> {
  /// Creates the scope of [notifier] around [child].
  const AppLocaleScope({
    required ValueNotifier<Locale?> super.notifier,
    required super.child,
    super.key,
  });

  /// The language that the user chose, or `null` to follow the device; the
  /// widget of [context] rebuilds when the choice changes.
  static Locale? of(BuildContext context) => context
      .dependOnInheritedWidgetOfExactType<AppLocaleScope>()!
      .notifier!
      .value;
}
