# AGENTS.md

This guide tells coding agents what the code of this Flutter app does not show. Setup that needs a person or an account is in [README.md](README.md). When you change what a section describes, change the section too.

## App entry

The app is plain Flutter code that nothing regenerates. Change it by hand, unless a section below says what writes a file.

- `main()` in `lib/main.dart` initializes the binding, awaits `bootstrap()` and calls `runApp()`, in this order. When `bootstrap()` throws, `main()` calls `showFailedStart()` of `lib/core/app/failed_start.dart` and returns: the app shows `FailedStartApp`, with the error in a debug build, and the error reaches `FlutterError.onError`. Keep the `try` around `await bootstrap()` in `main()`. Start-up code goes into `bootstrap()`. Do not catch an error there just to let the app start: fix what the error names, such as a step of the setup that has not run.
- `bootstrap()` in `lib/bootstrap.dart` runs before the first frame, in four phases: what must come before anything else, then the platform services, then the services of the app, then what needs them. Put a new statement into its phase, and import neither `package:flutter/material.dart` nor `package:flutter/cupertino.dart` there.
- Put code that features share into `lib/core/<concern>/`, one directory for each concern. Put a feature, with its screens and their state, into `lib/features/<feature>/`.
- The root of the app asks the system for the icons of the status bar that suit the theme, around every screen, with `StatusBarIcons` of `lib/core/app/status_bar_icons.dart`: dark icons on a light theme, light ones on a dark theme. A screen without an app bar needs no `AnnotatedRegion` for them. Add one only to a screen whose top has another brightness than the theme, such as a picture behind the status bar.
- The app has the flavors `dev`, `staging` and `prod`. A `flutter` command without `--flavor` builds `dev`, in release mode too, so a build for a store takes `--flavor prod`. Code reads the flavor from `appFlavor` of `package:flutter/services.dart`. The app has one entry: add no `main_<flavor>.dart`.

- The section "Finish the setup" of the README lists the steps of the setup that no command can do, such as a step in the web console of a service that the app uses. Only the developer of the app does them: when a task depends on one of them, point the developer to that section, and do not try to do the step yourself.

After a change, run:

```bash
dart format lib test
flutter analyze
flutter test
```

Format only `lib/` and `test/`: `dart format .` also formats what Flutter writes into `build/`. The app as generated is formatted, `flutter analyze` finds no issue in it and `flutter test` passes.

- `App` in `lib/app.dart` is the root widget of the app and creates its one `MaterialApp`. Every screen is below it, so create no other `MaterialApp` in `lib/`. The only other one is in `FailedStartApp`, which `main()` runs in its place when the start-up fails.
- The `theme`, `darkTheme`, `themeMode`, `locale` and localizations of the app go into the arguments of that `MaterialApp`.
- Tests mirror `lib/`: the test of `lib/<path>.dart` is `test/<path>_test.dart`.
- The app has only an Android and an iOS project, in `android/` and `ios/`.
- The entitlements of the iOS app, such as Push Notifications or Sign in with Apple, are in `ios/Runner/Runner.entitlements`. Every build configuration of the Runner target signs with this file, even while it is empty. The Signing & Capabilities tab of Xcode edits the same file.
- Each flavor is in `productFlavors` of `android/app/build.gradle.kts`, and on iOS in `ios/Runner.xcodeproj/xcshareddata/xcschemes/<flavor>.xcscheme` and in the build configurations `Debug-<flavor>`, `Profile-<flavor>` and `Release-<flavor>` of `ios/Runner.xcodeproj/project.pbxproj`. Change both places together. A new setting of the Runner target goes into each of its twelve build configurations.

## Localization

- Show the user no text but the name of the app from a string literal. Read each text as `context.l10n.<name>`, with `lib/core/l10n/l10n.dart` imported, where `context` is a `BuildContext` below the root of the app. Such an expression is no constant, so the widget around it cannot be `const`.
- `lib/core/l10n/app_locale.dart` has `appLocales`, the languages of the app, and `appLocale`, the one that the user chose. Change the language only with `appLocale.choose(locale)`, which also saves the choice in the preferences, and write nothing under the key `localization.locale` yourself. The root `MaterialApp` gets its `locale` and its `supportedLocales` from that file: leave both as they are.
- Every delegate among the `localizationsDelegates` of the root has to support each language of `appLocales`. A new language, one in which Flutter has the texts of its own widgets, goes into `appLocales`, into `CFBundleLocalizations` in the Info.plist of the iOS app, and into the texts of the app.

- A new language also needs its name in `_names` in `lib/core/l10n/language_setting.dart`: the setting of the language on the settings screen shows a language by that name, and by its code without one. Each name there is a string literal, the name of the language in that language, which is the same whatever language the app is in.

With `gen-l10n` of Flutter:

- The texts of the app are in the ARB files of `lib/l10n`. `lib/l10n/app_en.arb` has every text in English, and `lib/l10n/app_<code>.arb` the translations into another language. A text that such a file lacks reads in English there.
- To add a text, add it to `lib/l10n/app_en.arb` under a name in lowerCamelCase, and its translations under the same name to the other files.
- After every change of the ARB files, a new file included, run `flutter gen-l10n`, which generates `context.l10n.<name>`. Do not edit `lib/l10n/app_localizations*.dart`: `gen-l10n` writes those files from the ARB files, as `l10n.yaml` says.
- Write an apostrophe in a text once: `l10n.yaml` turns the escapes of `gen-l10n` off (`use-escaping: false`).

## Preferences

- `AppPreferences` in `lib/core/preferences/app_preferences.dart` remembers the settings of the app between its launches, such as the theme mode. It is not encrypted: never save a token, a password, an API key or an encryption key in it.
- To remember a setting, write a function that takes the `AppPreferences` and add it to `_restorers` in that file. In it, read the setting, put it into the state that the widgets listen to, and keep the preferences in that state for its writes. The function awaits nothing, and keeps the current value when nothing is saved.
- Name a key `<owner id>.<setting>`, such as `theme.mode`, where the owner is the feature or the concern whose code keeps the setting.
- In the code of the app, do not call `createAppPreferences()` or `initPreferences()`. `bootstrap()` opens the preferences, and code gets them as the argument of its function in `_restorers`, or, with a DI container in the app, from the container. Widgets use the state and do not touch the preferences. A test may call both: `initPreferences()` opens the preferences again, as the next launch of the app does, and `createAppPreferences()` returns them.

With `shared_preferences`:

- In `lib/`, only `lib/core/preferences/shared_app_preferences.dart` imports the package. Other code uses `AppPreferences`.
- A number is read only as the type that it was saved as: `getDouble()` returns `null` for a key with an `int`, and `getInt()` for a key with a `double`.
- In a test that runs `bootstrap()`, first set `SharedPreferencesAsyncPlatform.instance = InMemorySharedPreferencesAsync.empty()`. Without it, opening the preferences throws. Both names are from the package `shared_preferences_platform_interface`: add it as a dev dependency.
- `pubspec.yaml` keeps `shared_preferences_android` at 2.5.2 or later. With 2.5.0 and 2.5.1, a release build fails to open the preferences on Android, because R8 renames Kotlin classes that the package looks up by name. Before you change the constraint, check that a release build of the app starts on Android.

## Router

- Navigate with `context.nav.<feature>.<route>(...)`, never with the package of the router. It returns a `NavLink`, whose `go()`, `push<T>()` and `replace()` show the location. In `context.nav` both names are in lowerCamelCase; elsewhere `<feature>` is the id of the feature.
- A route is in three places, which agree on its name, `<feature>.<route>`, and on its path, which starts with `/<feature>`:
  1. its screen, a widget in `lib/features/<feature>/` whose `const` constructor takes each value of the route as a named parameter;
  2. `lib/core/router/navigation.dart`: its location class, which extends the sealed `AppLocation` with its `routeName`, its `path` and, below another route, its `parent`, and a method that returns its `NavLink` in the class of the routes of its feature. `AppNav` returns that class from a getter with the name of the feature, and both classes pass on the `BuildContext` that `NavLink` takes;
  3. the route itself, where the provider of the router declares its routes.
- A value of a route is a `String`, an `int`, a `double` or a `bool`, from a `:<name>` segment of its path or from the query.
- `appRouter` of `lib/core/router/app_router.dart` is the one router of the app: create no other.
- `NotFoundScreen` in `lib/core/router/not_found_screen.dart` is the page that the router shows for a location that it cannot show, such as a link to a page that the app does not have. Change its look there, and keep its `const` constructor without arguments. `appRouter.navigatorOf(context).goToStart()` shows the screen that the app starts on, as `go()` shows a location.

With `go_router`:

- `lib/core/router/app_router_factory.dart` has the one `GoRouter` of the app. A route is a `GoRoute` in its `routes`, or in the `routes` of its parent: `path` is the full path of a top-level route and the path from its parent otherwise, and `name` is `<feature>.<route>`. The values of a route come from `state.pathParameters` and `state.uri.queryParameters`. Parse one that is not a `String` with `tryParse`, and throw a `GoException` in the `redirect` of the route when a required value is missing or does not parse, so that the router shows its error screen.
- The app opens at `initialLocation`, and the route `/` leads to the same screen: change both together.
- To follow the screen that the user sees, add a function to `_screenListeners`.

## Settings screen

- The settings screen is a list with an entry for each setting of the app. An entry is a widget in a file of the code that owns the setting, such as one in `lib/core/<concern>/` or `lib/features/<feature>/`, and not in the file of the screen. It reads and changes its setting itself.
- To add a setting, write such a widget with a `const` constructor that requires no arguments. Create it in the list of the screen, and import its file there with a prefix that no other import there has, because two entries may have the same class name.
- The screen puts each entry on a `Material`, sets its width and puts no limit on its height, so an entry can be a `ListTile` or a `Column` of them. Pass an entry no arguments: it gets its state from its owner.

- `SettingsScreen` in `lib/features/settings/settings_screen.dart`, the route `settings.settings` at `/settings`, is the settings screen. Below its title it shows the entries in one group, and the file imports the files of the entries as `entry0`, `entry1` and so on. An entry may show only at times, such as one that hides on a platform: the screen asks it each time it builds. While no module of the app has a setting, or while none of its entries shows, the screen shows a note for the developer of the app in place of the group: the first entry that shows replaces that note.
- With a main navigation in the app, the screen is one of its destinations.
- Without a main navigation, no screen leads to the settings screen: open it with `context.nav.settings.settings().push<void>()`, which shows it on top of the current screen, so that its back button leads back. `go()` would replace the stack with the screen alone, and nothing would lead back.

## Store reviews

- `appReview` in `lib/core/review/app_review.dart` asks for the review dialog of the App Store or Google Play only where the code of the app calls `appReview.requestIfDue()`. Call it at a natural break, such as after the user has finished a task: `unawaited(appReview.requestIfDue());`. It asks only when `ReviewPolicy` says that a review is due: never on the first launch, in the flow of a guard of the routes, twice in a version or twice in 14 days. It returns nothing, since the store tells nothing.
- Never call it from a button or after a question of your own, and show nothing around the dialog. Nothing in the app may depend on whether the app asked.
- `appReview.openStorePage()` opens the page of the app in its store, and `appReview.openStorePage(review: true)` the page for a review. `appReview.hasStorePage` tells whether there is one: on iOS only once `REVIEW_APP_STORE_ID` in `.env` has the App Store ID. The Google Play page is that of `googlePlayId`, the id of the flavor for a release, also from a build of another flavor.
- A new provider implements `ReviewService` of `lib/core/review/review_service.dart`, and only the files of that implementation import it. The code of the app calls neither `initReview()`, `createReviewService()` nor `appReview.start()`, and writes nothing under the keys `review.*`.

- `ReviewSetting` in `lib/core/review/review_setting.dart`, an entry of the settings screen, opens the page of the app in its store for a review. It shows only where the app has a store page, and it never asks for the review dialog.

With `in_app_review`:

- `InAppReviewService` in `lib/core/review/in_app_review_service.dart` implements `ReviewService` of `lib/core/review/review_service.dart`: it asks for the review dialog with `InAppReview.instance.requestReview()`, opens the page of the app in its store with `launchUrl` of url_launcher, and reads the version of the app with `PackageInfo.fromPlatform()` of package_info_plus. In `lib/`, only that file imports in_app_review.
- Keep `openStoreListing()` of in_app_review out of the app: on Android it opens the page of the id of the build that runs, such as that of the flavor `dev`, which has no page in Google Play. `appReview.openStorePage()` opens the right page.
- The app asks for the dialog only where its code calls `appReview.requestIfDue()`. Google Play shows the dialog only in an app that it installed, such as from an internal test track, and the README of the app tells how to see it there. Never send a review while testing: Google Play shows no dialog to an account that has reviewed the app.
- Through the dialog, Google Play collects the rating and the text of a review. Both stores require a link to a privacy policy in the listing of the app and inside the app.

## Values in .env

- Read a value of `.env` only through a static getter of `AppEnv` in `lib/core/env/app_env.dart`. The getter is the key in lowerCamelCase: `AppEnv.myServiceKey` for the key `MY_SERVICE_KEY`. It returns a `String?` that is `null` while the value is empty or missing, so handle `null`. Never read `.env` or `.env.example` from code.
- Every value ends up in the app, where anyone can read it. Never put a secret into `.env`, such as the secret key of a server, a password or a private key.
- `.env` stays out of git. A new key goes into both `.env.example` and `.env`, in UPPER_SNAKE_CASE with a comment line above it, and `AppEnv` gets a getter for it.
- A release build of an app with keys stops with an error unless its command gives the app the values of `.env`; the note of the provider names the arguments. Never remove or work around the check in `lib/core/env/env_check.dart`, which `bootstrap()` calls in its first phase: give the build the arguments. `AppEnv.supplied` tells whether a build has the values.

In Android Studio, a test gets none of these arguments.

With `--dart-define-from-file`:

- Every command of the `flutter` tool that builds, runs or tests the app takes `--dart-define-from-file=.env`, such as `flutter run --dart-define-from-file=.env`, `flutter test` and `flutter build`. Without it, every getter of `AppEnv` is `null`, and a release build stops with an error.

- The getter of a new key in `lib/core/env/app_env.dart` reads `const String.fromEnvironment('MY_SERVICE_KEY')`, with the key in place of `MY_SERVICE_KEY`, and returns `null` for an empty value, as the other getters do.

## Flavors

The app has three flavors, which install next to each other on a device, each under an id of its own:

| Flavor | Android application id | iOS bundle id |
| --- | --- | --- |
| `dev` | `com.example.my_app.dev` | `com.example.my-app.dev` |
| `staging` | `com.example.my_app.staging` | `com.example.my-app.staging` |
| `prod` | `com.example.my_app` | `com.example.my-app` |

A `flutter` command without `--flavor` builds `dev`, because `default-flavor` in `pubspec.yaml` says so. That holds in release mode too: `flutter build appbundle` and `flutter build ipa` build a release of `dev`, under its id. For a store, name the flavor:

```bash
flutter run --flavor staging
flutter build appbundle --flavor prod
flutter build ipa --flavor prod
```

Code reads the flavor from `appFlavor` of `package:flutter/services.dart`. A service that knows your app by its id, such as a store or a push provider, knows each flavor as an app of its own, so you repeat a step of its setup for each flavor that needs it.

## Flavors in the native projects

Each flavor is in two places, so change both when you rename, add or remove one:

- Android: `productFlavors` in `android/app/build.gradle.kts`, with its id suffix and its name on the device.
- iOS: `ios/Runner.xcodeproj/xcshareddata/xcschemes/<flavor>.xcscheme`, and the build configurations `Debug-<flavor>`, `Profile-<flavor>` and `Release-<flavor>` in each configuration list of `ios/Runner.xcodeproj/project.pbxproj`. The name of a flavor has no hyphen, since Flutter splits the name of a configuration on it.

In Xcode, select the scheme of a flavor, not `Runner`. The scheme of a flavor builds that flavor, with its id, its name and its `appFlavor`. `Runner` builds the id and the name of `prod`, and takes `appFlavor` from `ios/Flutter/Generated.xcconfig`, which has one only after a `flutter` command that builds or runs the iOS app with a flavor. `flutter build ios --config-only --flavor <flavor>` gives that file a flavor.

On Android, a release build is signed with the debug key until `android/app/build.gradle.kts` has a signing config of yours, and a store refuses such a build. [Sign the app](https://docs.flutter.dev/deployment/android#sign-the-app) tells how.

## When the start-up fails

`bootstrap()` in `lib/bootstrap.dart` runs before the first frame. When it throws, `main()` shows `FailedStartApp` of `lib/core/app/failed_start.dart` in place of the splash screen, which would otherwise stay. A debug build shows the error and its stack trace there and prints them to the console. Any other build only says that the app could not start.

The error also reaches `FlutterError.onError`, so crash reporting that the start-up set up before the error reports it. An error before that reaches no crash reporter, so reproduce it in a debug build. The error usually says what to do, such as a command to run.

The texts of the screen are in English, since the texts of the app need the start-up that failed. Change them in that file.

## Run, test and build with .env

`AppEnv` in `lib/core/env/app_env.dart` reads each value of `.env` with `String.fromEnvironment`. The `flutter` tool reads `.env` when a command that builds, runs or tests the app starts, given `--dart-define-from-file=.env`, and compiles each value into the app. Without the argument, a debug or profile build has every getter of `AppEnv` `null` and says so, and a release build stops with an error that names the argument, so give it to each such command:

```bash
flutter run --dart-define-from-file=.env
flutter test --dart-define-from-file=.env
flutter build apk --flavor prod --dart-define-from-file=.env
flutter build appbundle --flavor prod --dart-define-from-file=.env
flutter build ipa --flavor prod --dart-define-from-file=.env
```

A build without `--flavor` is a release of `dev`, under its id, so a build for a store names its flavor. The section "Flavors" tells more.

Xcode takes the values from `ios/Flutter/Generated.xcconfig`. Only a `flutter` command that builds or runs the iOS app writes them there, and in a fresh app the file has no values. So before Product > Archive, run `flutter build ios --config-only --flavor prod --dart-define-from-file=.env`, or archive with `flutter build ipa` as above.

A command reads the values only when it starts: after you change `.env`, stop `flutter run` and start it again. Hot reload and hot restart keep the values that the app was built with.

`AppEnv.supplied` is `true` once the command declared one of the keys that it names, so a key of your own needs no change there. An app without keys has `true` there, since nothing can tell. With the first key of your own, make it `bool.hasEnvironment('MY_SERVICE_KEY')` with that key, so that a release build without the argument stops.

To read a key of your own, give `AppEnv` a getter for it, as for the other keys:

```dart
static String? get myServiceKey {
  const value = String.fromEnvironment('MY_SERVICE_KEY');
  return value.isEmpty ? null : value;
}
```

The section "Values in .env" tells what goes into `.env`, lists the keys of the app and names the run configurations that pass the argument.

## Texts

The texts of the app are in the ARB files of `lib/l10n`, one for each language. `lib/l10n/app_en.arb` has every text in English, and the file of another language, such as `app_uk.arb`, has the translations into it. [gen-l10n](https://docs.flutter.dev/ui/internationalization) of Flutter generates the `AppLocalizations` class from these files, as `l10n.yaml` says, and writes it into `app_localizations.dart` and a file for each language in the same directory. Run `flutter gen-l10n` after every change of the ARB files. In a fresh clone of the app, `flutter pub get` generates those files, so you can commit them or leave them out of the repository. Code reads a text as `context.l10n.<name>` with `lib/core/l10n/l10n.dart` imported, where `context` is a `BuildContext` below the root of the app.

To add a text, add it to `lib/l10n/app_en.arb` under a name of its own, and its translations under the same name to the files of the other languages. Then run `flutter gen-l10n`. A text without a translation into a language reads in English there.

The texts of a new language, such as German, go into a file of their own:

1. Add `lib/l10n/app_de.arb` with `"@@locale": "de"` and the translations.
2. Run `flutter gen-l10n`.

The section "Languages" tells where else the new language goes.

## Values in .env

`.env` at the root of the app holds the values you fill in after generating the app, such as the public key of a service. Code reads each value as a static getter of `AppEnv` in `lib/core/env/app_env.dart`. The getter is `null` while the value is empty or missing, so the app builds and starts before you fill anything in.

A release build needs `.env`: `flutter build` of a release, and an archive in Xcode, stop with an error unless the command has `--dart-define-from-file=.env` and `.env` has a line of a key of the app, also with an empty value. So a build for a store never goes out by mistake from a command that did not give it `.env`. A debug or profile build without it starts with every getter `null` and says so in the console. `lib/core/env/env_check.dart` holds the check, which `bootstrap()` calls in its first phase, and `AppEnv.supplied` tells whether a build has the values.

`.gitignore` lists `.env`, so it stays out of git. `.env.example` is in git and has the same keys without values: after a clone, run `cp .env.example .env` and fill in `.env`. Every value ends up in the app, where anyone can read it, so never put a secret there, such as the secret key of a server, a password or a private key.

`.env` is not tied to a flavor: a build of any flavor takes what `.env` has when its command runs. Keep one file and change its values by hand, or have CI write the file for its job.

The keys of the app:

- `REVIEW_APP_STORE_ID`, read as `AppEnv.reviewAppStoreId`, from the store reviews role: The App Store ID of the app, its Apple ID in App Store Connect, such as 1234567890

To add a key of your own, put it into `.env.example` and `.env` and give `AppEnv` a getter for it. The section of the module that provides the values tells how they get into the app.

Each flavor has a run configuration, which passes the flavor and the arguments that the values need:

- In VS Code, they are in `.vscode/launch.json`. Run and Debug (F5) starts the one that you select in the Run and Debug view. The Run and Debug links above `main()` and above a test, and the Testing view, always use the configuration of `dev`, the only one that is a template of those launches (`templateFor`).
- In Android Studio, each is a file of its own, `.run/<flavor>.run.xml`. A test that you run there gets none of these arguments.

## in_app_review

The app asks for the review dialog of its store with [in_app_review](https://pub.dev/packages/in_app_review): `lib/core/review/in_app_review_service.dart` implements the reviews of the app on it, as the section "Store reviews" tells. On iOS the dialog is that of StoreKit, and on Android that of the In-App Review API of Google Play. The page of the app in its store opens with [url_launcher](https://pub.dev/packages/url_launcher), and the version of the app, in which the app asks at most once, comes from [package_info_plus](https://pub.dev/packages/package_info_plus).

The app asks only where its code calls `appReview.requestIfDue()`, and nothing asks on its own.

Google Play shows the dialog only in an app that it installed. To see it before the app is published ([Test in-app reviews](https://developer.android.com/guide/playcore/in-app-review/test)):

1. Upload a build of the flavor `prod` to the internal test track in Play Console.
2. Add a Gmail account to the testers of that track. It is the primary account of the Play Store on the device: an account of Google Workspace does not work.
3. Install the app once from the internal test track with that account. From then on, local builds of the flavor `prod` may show the dialog on that device: uninstall the copy from Google Play first, since a local build has another signature. Google Play does not limit how often it shows the dialog to an app from the internal test track.
4. Never send the review of a test, or delete it in the Play Store: Google Play shows no dialog to an account that has reviewed the app.

An app from internal app sharing shows the dialog too, but its review cannot be sent. On a device without the review service of Google Play, such as an emulator without the Play Store, the store cannot take the request, the app records nothing, and the next call of `appReview.requestIfDue()` asks again. On a device with the Play Store, for a build that Google Play did not install, such as a local build of the flavor `dev`, the request completes and shows nothing, and the app counts it as a request, so it does not ask again in that version of the app.

Through the dialog, Google Play collects the rating and the text of the review, which become a public review on Google Play, or which only you see for an app on a closed test track: see the section "Data Safety" of [the In-App Review API](https://developer.android.com/guide/playcore/in-app-review). The privacy manifest of in_app_review on iOS declares no data that it collects.

Both stores require a link to a privacy policy in the listing of the app and inside the app.

## Languages

The app is in the languages of `appLocales` in `lib/core/l10n/app_locale.dart`. It shows its texts in the language that the device prefers among them, and in the first of the list when the device asks for none of them. `appLocale.choose()` puts the app into another of its languages, whatever the device prefers, and the app remembers that choice between its launches. `appLocale.choose(null)` follows the device again. The entry `LanguageSetting` of the settings screen, in `lib/core/l10n/language_setting.dart`, lets the user choose.

To add a language in which Flutter has the texts of its own widgets, such as German, add the texts of the app in German, and then:

1. Add `Locale('de')` to `appLocales`, one locale for each language, since the app tells its languages apart by their codes.
2. Add `de` to `CFBundleLocalizations` in `ios/Runner/Info.plist`, which tells iOS the languages of the app.
3. Add `'de': 'Deutsch'` to `_names` in `lib/core/l10n/language_setting.dart`, the name that the setting shows for the language. Without it, the setting shows `de`.

## Store reviews

The app asks for a review only where its code calls `appReview.requestIfDue()` of `lib/core/review/app_review.dart`. Call it at a natural break, such as when the user has finished a task:

```dart
await saveNote(note);
unawaited(appReview.requestIfDue());
```

When a review is due, the call asks the App Store or Google Play for its own review dialog, and the app shows nothing around it. It returns nothing: the store tells no app whether the dialog showed or what the user did, so nothing in the app may depend on it. Never call it from a button, and never after a question of your own, such as "Do you like the app?": Google Play forbids both, and the App Store allows no prompt but its own.

A review is due as `ReviewPolicy` in that file says: from the third launch of the app (`ReviewPolicy.launches`), three days after its first launch (`ReviewPolicy.sinceFirstLaunch`), and at most once a version of the app and once in 14 days (`ReviewPolicy.between`). Change the numbers there. The app counts its launches and remembers its last request in the preferences, under the keys `review.*`, so write nothing there.

The store decides whether the dialog shows. iOS shows it in a debug build each time, never in TestFlight, and at most three times in 365 days. Google Play shows it only in an app that it installed, such as from an internal test track. On a device without the review service of Google Play, such as an emulator without the Play Store, the store cannot take the request and the app records nothing, so the next call of `appReview.requestIfDue()` asks again, also in the same launch. On a device with the Play Store, for an app that Google Play did not install, such as a local build, the request completes and shows nothing, and the app counts it as a request, so it does not ask again in that version of the app.

`appReview.openStorePage()` opens the page of the app in its store, and `appReview.openStorePage(review: true)` the page where the user writes a review. On Android that is the Google Play page of `com.example.my_app` (`googlePlayId`), the id of the flavor for a release, also from a build of another flavor. On iOS it is the App Store page of `REVIEW_APP_STORE_ID` in `.env`, the Apple ID of the app in App Store Connect. While that key is empty, the app has no App Store page, and `appReview.hasStorePage` is `false` on iOS.

The entry `ReviewSetting` of the settings screen, in `lib/core/review/review_setting.dart`, opens the page for a review, and shows only where the app has a store page. It never asks for the review dialog.

  );

/// Keeps the language that the user chose for the app, and saves each
/// choice in the preferences of the app.
final class AppLocaleController extends ChangeNotifier
    implements ValueListenable<Locale?> {
  AppLocaleController._();

  Locale? _locale;

  /// The preferences of the app, once it opened them.
  AppPreferences? _preferences;

  /// The language that the user chose, one of [appLocales], or `null` while
  /// the app follows the languages of the device.
  @override
  Locale? get value => _locale;

  /// Chooses the language of [locale] as the language of the app, or with
  /// `null` lets the app follow the languages of the device again.
  ///
  /// The choice is the one of [appLocales] with the language of [locale],
  /// so `Locale('uk', 'UA')` chooses `Locale('uk')`. A locale of a language
  /// that the app is not in is refused: the future completes with an
  /// [ArgumentError], and nothing changes.
  ///
  /// The language of the app changes at once, and the choice is then saved
  /// in the preferences once the app opened them: before that, it changes
  /// only memory. When saving fails, the future completes with the error of
  /// the preferences. The app stays in the new language while it runs, and
  /// its next launch starts with what was saved before; choosing the
  /// language again saves it again.
  Future<void> choose(Locale? locale) async {
    final chosen = locale == null ? null : _ofApp(locale.languageCode);
    if (locale != null && chosen == null) {
      throw ArgumentError.value(
        '$locale',
        'locale',
        'The app is not in the language of this locale',
      );
    }
    _set(chosen);
    final preferences = _preferences;
    if (preferences == null) return;
    if (chosen == null) {
      await preferences.remove(_key);
    } else {
      await preferences.setString(_key, chosen.languageCode);
    }
  }

  void _set(Locale? locale) {
    if (locale == _locale) return;
    _locale = locale;
    notifyListeners();
  }
}

/// The one of [appLocales] with the language of the code [code], or `null`.
Locale? _ofApp(String? code) {
  for (final locale in appLocales) {
    if (locale.languageCode == code) return locale;
  }
  return null;
}

  int? getInt(String key);

/// The settings of the app that are no secret, with the shared_preferences
/// package, which keeps them in DataStore on Android and in `UserDefaults`
/// on iOS.
///
/// Neither is encrypted, and a backup of the device carries them: never
/// store a token, a password, an API key or an encryption key in the
/// preferences.
///
/// A number is read only as the type that it was saved as: `getDouble`
/// returns `null` for a key with an `int`, and `getInt` for a key with a
/// `double`, a whole number too.
///
/// A write puts its value into memory before it saves it. If the platform
/// refuses the save, as Android does for a text that starts with the prefix
/// that shared_preferences marks a list with, the write fails, and the
/// reads of this run return the value all the same. The next launch reads
/// what was saved before the write, or nothing if the key had no value.
final class SharedAppPreferences implements AppPreferences {
  /// Creates the preferences on [SharedPreferencesWithCache], which has
  /// read what is saved.
  SharedAppPreferences(this._preferences);

  final SharedPreferencesWithCache _preferences;

  @override
  String? getString(String key) => _read<String>(key);

  @override
  bool? getBool(String key) => _read<bool>(key);

  @override
  int? getInt(String key) => _read<int>(key);

  @override
  double? getDouble(String key) => _read<double>(key);

  @override
  List<String>? getStringList(String key) => switch (_preferences.get(key)) {
    final List<Object?> list => _textsOf(list),
    _ => null,
  };

  @override
  Future<void> setString(String key, String value) =>
      _preferences.setString(key, value);

  @override
  Future<void> setBool(String key, bool value) =>
      _preferences.setBool(key, value);

  @override
  Future<void> setInt(String key, int value) => _preferences.setInt(key, value);

  @override
  Future<void> setDouble(String key, double value) =>
      _preferences.setDouble(key, value);

  /// shared_preferences keeps the list that it is given, so it gets a copy.
  @override
  Future<void> setStringList(String key, List<String> value) =>
      _preferences.setStringList(key, List.of(value));

  @override
  Future<void> remove(String key) => _preferences.remove(key);

  /// The value of [key] if it is a [T], or `null`. The reads of
  /// shared_preferences cast the value instead, and throw on a value of
  /// another type.
  T? _read<T>(String key) => switch (_preferences.get(key)) {
    final T value => value,
    _ => null,
  };

  /// A copy of [list] as a list of texts, or `null` if an item of it is no
  /// text.
  ///
  /// When the preferences are opened, the platform returns a list in a form
  /// of its own: a list of objects on iOS, and on Android a list that casts
  /// each item to a text as it is read, and so throws on an item that is
  /// none. Cast to objects, either gives its items as they are.
  static List<String>? _textsOf(List<Object?> list) {
    final items = list.cast<Object?>();
    return items.every((item) => item is String)
        ? List<String>.from(items)
        : null;
  }

/// When a review is due. The stores ask an app not to ask on its first
/// launch, nor too often, and to ask once the user has used it. Change the
/// numbers here.
abstract final class ReviewPolicy {
  /// How many launches of the app, this one included, there are at least
  /// once a review is due. At least 2, so that the app never asks on its
  /// first launch.
  static const int launches = 3;

  /// How long after the first launch of the app a review is due.
  static const Duration sinceFirstLaunch = Duration(days: 3);

  /// How long after a request the next review is due, also in a new
  /// version of the app. The app asks at most once a version.
  static const Duration between = Duration(days: 14);
}

/// The application id of the app in Google Play: that of the flavor for a
/// release, also in a build of another flavor, whose own id has no page
/// there. Change it here if you change the application id of the app.
const String googlePlayId = 'com.example.my_app';

/// The reviews of the app in its store: the review dialog, which the app
/// asks for when a review is due, and the page of the app in its store.
final AppReviewController appReview = AppReviewController();

/// Asks the store of the platform for its review dialog when a review is
/// due, and opens the page of the app in its store. The app has one,
/// [appReview].
///
/// It counts the launches of the app and remembers its last request in the
/// preferences of the app. It asks for nothing on its own: only a call of
/// [requestIfDue] asks.
final class AppReviewController {
  /// Creates the controller, which reads the time from [now] and the App
  /// Store ID of the app from [appStoreId], by default the value of
  /// `REVIEW_APP_STORE_ID` in `.env`. A test creates one with a clock and
  /// an ID of its own, gives it the preferences with [restore], and starts
  /// it with a service of its own.
  AppReviewController({
    this._now = DateTime.now,
    this._appStoreId = _appStoreIdOfEnv,
  });

  /// The keys under which the preferences keep what the controller
  /// remembers: the launches of the app, the time of its first launch, and
  /// the time and the version of its last request.
  static const _launchesKey = 'review.launches';
  static const _firstLaunchKey = 'review.first_launch';
  static const _askedAtKey = 'review.asked_at';
  static const _askedVersionKey = 'review.asked_version';

  /// An App Store ID: digits, and nothing else.
  static final RegExp _appStoreIdPattern = RegExp(r'^[0-9]+$');

  final DateTime Function() _now;
  final String? Function() _appStoreId;

  /// The service of the provider, once the controller has started.
  ReviewService? _service;

  /// The preferences that keep what the controller remembers, once the app
  /// opened them.
  AppPreferences? _preferences;

  /// The launches of the app, this one included.
  int _launches = 0;

  /// The time of the first launch of the app.
  DateTime? _firstLaunch;

  /// The time of the last request, if the app asked.
  DateTime? _askedAt;

  /// The version of the app in which it last asked, if it asked.
  String? _askedVersion;

  /// The request that is on its way, if any.
  Future<void>? _request;

  /// Whether the controller told in debug mode that the app has no App
  /// Store ID, or that its version is unknown.
  bool _toldOfStoreId = false;
  bool _toldOfVersion = false;

  /// Whether the app has a page in the store of the platform: on Android
  /// always, and on iOS once `REVIEW_APP_STORE_ID` in `.env` has the App
  /// Store ID of the app.
  bool get hasStorePage => storePage() != null;

  /// The page of the app in the store of the platform, or `null` where it
  /// has none: on Android the Google Play page of [googlePlayId], on iOS
  /// the App Store page of the App Store ID, which is all digits, and none
  /// on any other platform. With [review], the page on which the user
  /// writes a review, which only the App Store has apart.
  Uri? storePage({bool review = false}) => switch (defaultTargetPlatform) {
    TargetPlatform.android => Uri.https(
      'play.google.com',
      '/store/apps/details',
      {'id': googlePlayId},
    ),
    TargetPlatform.iOS => switch (_appStoreId()) {
      final id? when _appStoreIdPattern.hasMatch(id) => Uri.https(
        'apps.apple.com',
        '/app/id$id',
        review ? {'action': 'write-review'} : null,
      ),
      _ => null,
    },
    _ => null,
  };

  /// Opens the page of the app in its store, outside the app, or with
  /// [review] the page on which the user writes a review (see
  /// [storePage]), and returns whether an app of the device opened it:
  /// `false` where the app has no store page, and before the app started.
  /// Never throws.
  Future<bool> openStorePage({bool review = false}) async {
    final page = storePage(review: review);
    final service = _service;
    if (page == null || service == null) return false;
    try {
      return await service.openStorePage(page);
    } on Object catch (error) {
      _tell('The page of the app in its store did not open: $error');
      return false;
    }
  }

  /// Asks the store for its review dialog when a review is due, and does
  /// nothing otherwise. Call it at a natural break of the app, such as when
  /// the user has finished a task:
  ///
  /// ```dart
  /// await saveNote(note);
  /// unawaited(appReview.requestIfDue());
  /// ```
  ///
  /// Never call it from a button, nor after a question of your own, such
  /// as whether the user likes the app: the stores forbid both. The app
  /// shows nothing around the dialog.
  ///
  /// A review is due once the app has had [ReviewPolicy.launches] launches,
  /// this one included, [ReviewPolicy.sinceFirstLaunch] has passed since
  /// its first launch and [ReviewPolicy.between] since its last request, and
  /// it did not ask in this version of the app, while the store of the
  /// device can show the dialog and the user is in no flow of a guard of the
  /// routes, such as the onboarding or a sign-in.
  ///
  /// It completes once the store took the request, and the app then
  /// remembers it. It returns nothing, since the store tells no app whether
  /// the dialog showed, so nothing may depend on it. It never throws: an
  /// error of the store counts as no dialog, and a later call asks again. A
  /// call while a request is on its way gets that request.
  Future<void> requestIfDue() =>
      _request ??= _askIfDue().whenComplete(() => _request = null);

  /// Takes what the controller remembers from [preferences], and keeps it
  /// as it is for a key that has nothing saved. It keeps [preferences] for
  /// the writes of the controller.
  void restore(AppPreferences preferences) {
    _preferences = preferences;
    _launches = preferences.getInt(_launchesKey) ?? _launches;
    _firstLaunch = _timeOf(preferences.getInt(_firstLaunchKey)) ?? _firstLaunch;
    _askedAt = _timeOf(preferences.getInt(_askedAtKey)) ?? _askedAt;
    _askedVersion = preferences.getString(_askedVersionKey) ?? _askedVersion;
  }

  /// Starts with [service]: counts this launch of the app, and the time of
  /// its first launch if it has none, and saves them.
  ///
  /// `initReview()` calls it in `bootstrap()`. It may be called again, with
  /// the service that the app has from then on: `initReview()` does so in a
  /// test of the next launch of the app, and a test gives it a service of
  /// its own. A failed save is told in debug mode and stops nothing.
  Future<void> start(ReviewService service) async {
    _service = service;
    _launches++;
    final saved = _firstLaunch;
    final firstLaunch = _firstLaunch ??= _now().toUtc();
    try {
      await _preferences?.setInt(_launchesKey, _launches);
      if (saved == null) {
        await _preferences?.setInt(
          _firstLaunchKey,
          firstLaunch.millisecondsSinceEpoch,
        );
      }
    } on Object catch (error) {
      _tell('The launch of the app was not saved for the reviews: $error');
    }
    if (!_toldOfStoreId &&
        defaultTargetPlatform == TargetPlatform.iOS &&
        !hasStorePage) {
      _toldOfStoreId = true;
      _tell(
        'REVIEW_APP_STORE_ID in .env has no App Store ID, so the app has no '
        'App Store page: appReview.hasStorePage is false on iOS, and '
        'appReview.openStorePage() opens nothing there. Put the Apple ID of '
        'the app in App Store Connect there.',
      );
    }
  }

  /// Asks the store for its dialog if a review is due, and remembers the
  /// request once the store took it. Never throws.
  Future<void> _askIfDue() async {
    try {
      final service = _service;
      if (service == null || !_dueByTime() || _inAGuardFlow()) return;
      final version = await _versionOf(service);
      if (version == null || version == _askedVersion) return;
      if (!await _isAvailable(service) || _inAGuardFlow()) return;
      try {
        await service.requestReview();
      } on Object catch (error) {
        _tell('The store did not take the request for a review: $error');
        return;
      }
      final askedAt = _askedAt = _now().toUtc();
      _askedVersion = version;
      try {
        await _preferences?.setInt(_askedAtKey, askedAt.millisecondsSinceEpoch);
        await _preferences?.setString(_askedVersionKey, version);
      } on Object catch (error) {
        _tell('The request for a review was not saved: $error');
      }
    } on Object catch (error) {
      _tell('The request for a review failed: $error');
    }
  }

  /// Whether a review is due by the launches and the times that the
  /// controller remembers. A request whose time is to come, as after the
  /// clock of the device went back, counts as recent.
  bool _dueByTime() {
    final firstLaunch = _firstLaunch;
    if (_launches < ReviewPolicy.launches || firstLaunch == null) return false;
    final now = _now();
    if (now.difference(firstLaunch) < ReviewPolicy.sinceFirstLaunch) {
      return false;
    }
    final askedAt = _askedAt;
    if (askedAt == null) return true;
    final since = now.difference(askedAt);
    return !since.isNegative && since >= ReviewPolicy.between;
  }

  /// The version of the app that [service] gives, or `null` if it is
  /// unknown, which makes no review due.
  Future<String?> _versionOf(ReviewService service) async {
    String? version;
    try {
      version = (await service.appVersion())?.trim();
    } on Object catch (error) {
      _tell('The version of the app is unknown: $error');
    }
    if (version != null && version.isNotEmpty) return version;
    if (!_toldOfVersion) {
      _toldOfVersion = true;
      _tell(
        'The version of the app is unknown, so the app asks for no review.',
      );
    }
    return null;
  }

  /// Whether the store of the device can show the review dialog, as
  /// [service] tells: `false` if it fails to tell.
  Future<bool> _isAvailable(ReviewService service) async {
    try {
      return await service.isAvailable();
    } on Object {
      return false;
    }
  }

  /// Prints [message] in debug mode, for the developer of the app.
  static void _tell(String message) {
    if (kDebugMode) debugPrint(message);
  }

  /// The time of [milliseconds] since the epoch, in UTC, or `null`.
  static DateTime? _timeOf(int? milliseconds) => milliseconds == null
      ? null
      : DateTime.fromMillisecondsSinceEpoch(milliseconds, isUtc: true);
}

/// A text that keeps its words whole: it breaks between its words and never
/// inside one. A space, a tab or a line break parts two words, and a
/// no-break space keeps the two words around it together as one.
///
/// It grows with the text size of the device. Where its longest word would
/// still not fit the width that the text has, as on a narrow phone with a
/// large text size, the text is as large as that word allows.
class _WholeWords extends StatelessWidget {
  const _WholeWords(this.text);

  /// The text.
  final String text;

  @override
  Widget build(BuildContext context) {
    // The style in which a Text paints: that of the text around it, and
    // bold for a user who asks for bold text.
    var style = DefaultTextStyle.of(context).style;
    if (MediaQuery.boldTextOf(context)) {
      style = style.merge(const TextStyle(fontWeight: FontWeight.bold));
    }
    final scaler = MediaQuery.textScalerOf(context);
    return LayoutBuilder(
      builder: (context, constraints) {
        final room = constraints.maxWidth;
        final painter = TextPainter(
          textDirection: Directionality.of(context),
          textScaler: scaler,
          maxLines: 1,
        );
        // The words of the text, between its white spaces, where a line may
        // break: every one but a no-break space, which keeps the words
        // around it together.
        final words = text.split(RegExp(r'[^\S\u00A0\u2007\u202F]+'));
        // How wide the longest word is in a font of [size].
        double widestAt(double size) {
          var widest = 0.0;
          for (final word in words) {
            painter
              ..text = TextSpan(
                text: word,
                style: style.copyWith(fontSize: size),
              )
              ..layout();
            if (painter.width > widest) widest = painter.width;
          }
          return widest;
        }

        // The size of a text of Flutter whose style gives none.
        var size = style.fontSize ?? 14;
        var widest = widestAt(size);
        // In a few steps: the text size of a device may grow a small font
        // by more than a large one.
        for (var step = 0; step < 4 && widest > room && room > 0; step++) {
          // A little smaller than the width allows, so that the rounding of
          // the layout breaks no word.
          size *= room / widest * 0.98;
          widest = widestAt(size);
        }
        painter.dispose();
        return Text(
          text,
          style: style.copyWith(fontSize: size),
          textScaler: scaler,
        );
      },
    );
  }
}

/// The router of the app: its configuration for `MaterialApp.router` and the
/// navigation that screens use through `context.nav`.
abstract interface class AppRouter {
  /// The configuration that `MaterialApp.router` takes as `routerConfig`.
  RouterConfig<Object> get config;

  /// The navigator that [context] navigates with.
  AppNavigator navigatorOf(BuildContext context);
}

/// Moves between the locations of the app.
abstract interface class AppNavigator {
  /// Shows [location] with the chain of its parents below it as the stack.
  ///
  /// In the main navigation, it selects the branch of [location] and makes
  /// the chain its stack; for a location outside the main navigation, the
  /// chain replaces the whole stack, main navigation included.
  void go(AppLocation location);

  /// Shows [location] on top of the current stack and completes with the
  /// value the page returns when it closes.
  ///
  /// In the main navigation, the current stack is that of the selected
  /// branch, whichever branch [location] belongs to, and the selected
  /// destination stays; a location outside the main navigation is shown
  /// over it. A location in the main navigation goes only on top of the
  /// main navigation itself: from a page shown over it, this throws a
  /// [StateError] and leaves the stack as it is, so [go] to the location
  /// instead. From a page with no main navigation below it, the main
  /// navigation comes on top with the location.
  Future<T?> push<T extends Object?>(AppLocation location);

  /// Replaces the top of the current stack with [location].
  ///
  /// As with [push], a location in the main navigation cannot replace a
  /// page shown over the main navigation: this throws a [StateError] and
  /// leaves the stack as it is, so [go] to the location instead.
  void replace(AppLocation location);

  /// Shows the screen that the app starts on, as [go] shows a location: the
  /// route that the app starts on, or the fallback start screen of the app
  /// entry in an app that no route starts.
  ///
  /// The guards of the routes are asked about it as [go] asks about a
  /// location: while a gate does not allow, its target shows instead.
  void goToStart();
}

      config.routerDelegate.currentConfiguration.matches.isEmpty;

  /// Follows the pages of go_router, whose delegate notifies its listeners
  /// of each change of them: keeps each push completing with the value of
  /// its page, and tells the listeners of the screen about the page on top.
  void _pagesChanged() {
    _keepPushes();
    _showScreen();
  }

  /// Lets each push complete with the value that its page returns when it
  /// closes, whatever completer go_router gives the page.
  ///
  /// go_router completes a push with the completer that it gives the page
  /// it pushed, which the page completes when it closes. When go_router
  /// shows its pages anew from their encoded form, as on [GoRouter.refresh],
  /// such as when its `refreshListenable` notifies, it gives each pushed
  /// page a new completer, though the page keeps its key and its location,
  /// so the push would never complete
  /// (https://github.com/flutter/flutter/issues/128122). So when a page
  /// comes back at its location with another completer, the router passes
  /// on the value of that completer to that of the push. A branch of the
  /// main navigation that is not selected keeps its pages as they were, so
  /// a page that comes back with its branch passes on its value as before.
  /// Once go_router keeps the completers of its pages, this does nothing
  /// and can go.
  void _keepPushes() {
    final pushed = {
      for (final page in _pushedPages(
        config.routerDelegate.currentConfiguration.matches,
      ))
        page.pageKey: page,
    };
    for (final page in pushed.values) {
      final before = _pushed[page.pageKey];
      if (before == null ||
          before.completer == page.completer ||
          before.matches.uri != page.matches.uri) {
        continue;
      }
      final push = _pushes[before.completer] ?? before.completer;
      _pushes[page.completer] = push;
      unawaited(
        page.completer.future.then((value) {
          if (!push.isCompleted) push.complete(value);
        }),
      );
    }
    _pushed = pushed;
  }

  /// The pages that pushes showed among [matches], in the stacks of the
  /// main navigation too.
  static Iterable<ImperativeRouteMatch> _pushedPages(
    List<RouteMatchBase> matches,
  ) sync* {
    for (final match in matches) {
      if (match is ImperativeRouteMatch) yield match;
      if (match is ShellRouteMatch) yield* _pushedPages(match.matches);
    }
  }

  /// Tells the listeners of the screen about the page on top when another
  /// page comes on top, or the page on top shows another location.
  ///
  /// The delegate of go_router notifies its listeners once for each change
  /// of its configuration, a switch of branches included, and may do so
  /// again without a change of the page on top, which the listeners of the
  /// screen do not hear of twice. The location of a pushed page is its own,
  /// as that of the configuration leaves pushed pages out. The error screen
  /// of go_router has no route match, or, for a location pushed in error, a
  /// route without a name.
  void _showScreen() {
    final configuration = config.routerDelegate.currentConfiguration;
    final top = configuration.lastOrNull;
    final location = switch (top) {
      ImperativeRouteMatch(:final matches) => matches.uri.toString(),
      _ => configuration.uri.toString(),
    };
    final screen = (top?.pageKey, location);
    if (screen == _screen) return;
    _screen = screen;
    for (final listener in _screenListeners) {
      _callAlone(listener, top?.route.name, location);
    }
  }
}

/// The dispatcher of the back button of the system for go_router, which
/// asks go_router to close the route on top only while go_router has a page
/// of a route.
///
/// go_router shows its error screen in place of the whole stack, for a
/// location that no route matches or that the redirect of a route refuses:
/// it then has no page of a route. Asked to close the route on top, its
/// delegate looks for the last of those pages and throws a [StateError]
/// (https://github.com/flutter/flutter/issues/187616). So on that screen
/// the dispatcher asks the root navigator, the only one there, itself: a
/// route that is shown over the error screen, such as a dialog, closes, and
/// with no route to close the button is left to the system, as on the
/// first page of the app. An error screen that a push showed over a page is
/// a page of go_router, which closes it. Once the delegate of go_router
/// answers without a page, this can go.
final class _BackButton extends RootBackButtonDispatcher {
  /// Creates the dispatcher of the back button of [_router].
  _BackButton(this._router);

  final GoRouter _router;

  /// For each callback that the dispatcher was given, the one that it
  /// calls in its place.
  final Map<ValueGetter<Future<bool>>, ValueGetter<Future<bool>>> _asked = {};

  /// Takes [callback], with which the `Router` of Flutter asks the delegate
  /// of go_router to close the route on top, and calls it only while
  /// go_router has a page. A `BackButtonListener` below the router still
  /// hears of the button first, on the error screen too.
  @override
  void addCallback(ValueGetter<Future<bool>> callback) => super.addCallback(
    _asked[callback] = () {
      final delegate = _router.routerDelegate;
      if (delegate.currentConfiguration.matches.isNotEmpty) return callback();
      return delegate.navigatorKey.currentState?.maybePop() ??
          Future.value(false);
    },
  );

  @override
  void removeCallback(ValueGetter<Future<bool>> callback) =>
      super.removeCallback(_asked.remove(callback) ?? callback);
}

/// Paints a dashed edge around the box that it is given, in [color].
class _DashedEdge extends CustomPainter {
  const _DashedEdge(this.color);

  final Color color;

  @override
  void paint(Canvas canvas, Size size) {
    const dash = 6.0;
    const gap = 4.0;
    final paint = Paint()
      ..color = color
      ..strokeWidth = 1.5;
    final edge = (Offset.zero & size).deflate(0.75);
    for (final (from, to) in [
      (edge.topLeft, edge.topRight),
      (edge.topRight, edge.bottomRight),
      (edge.bottomRight, edge.bottomLeft),
      (edge.bottomLeft, edge.topLeft),
    ]) {
      final length = (to - from).distance;
      final along = (to - from) / length;
      for (var start = 0.0; start < length; start += dash + gap) {
        canvas.drawLine(
          from + along * start,
          from + along * math.min(start + dash, length),
          paint,
        );
      }
    }
  }

  @override
  bool shouldRepaint(_DashedEdge oldDelegate) => oldDelegate.color != color;
}

/// What the widget asks the system for on a screen in [theme].
Future<SystemUiOverlayStyle> _styleIn(
  WidgetTester tester,
  ThemeData theme,
) async {
  await tester.pumpWidget(
    MaterialApp(
      theme: theme,
      home: const StatusBarIcons(child: Text('A screen')),
    ),
  );
  return tester
      .widget<AnnotatedRegion<SystemUiOverlayStyle>>(
        find.descendant(
          of: find.byType(StatusBarIcons),
          matching: find.byType(AnnotatedRegion<SystemUiOverlayStyle>),
        ),
      )
      .value;
}
