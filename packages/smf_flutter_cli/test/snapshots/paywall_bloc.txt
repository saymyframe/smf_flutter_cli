## App entry

The app is plain Flutter code that nothing regenerates. Change it by hand, unless a section below says what writes a file.

- `bootstrap()` in `lib/bootstrap.dart` runs before the first frame, in four phases: what must come before anything else, then the platform services, then the services of the app, then what needs them. Put a new statement into its phase, and import neither `package:flutter/material.dart` nor `package:flutter/cupertino.dart` there.
- Put code that features share into `lib/core/<concern>/`, one directory for each concern. Put a feature, with its screens and their state, into `lib/features/<feature>/`.
- The root of the app asks the system for the icons of the status bar that suit the theme, around every screen, with `StatusBarIcons` of `lib/core/app/status_bar_icons.dart`: dark icons on a light theme, light ones on a dark theme. A screen without an app bar needs no `AnnotatedRegion` for them. Add one only to a screen whose top has another brightness than the theme, such as a picture behind the status bar.

Format only `lib/` and `test/`: `dart format .` also formats what Flutter writes into `build/`. The app as generated is formatted, `flutter analyze` finds no issue in it and `flutter test` passes.

## Router

- Navigate with `context.nav.<feature>.<route>(...)`, never with the package of the router. It returns a `NavLink`, whose `go()`, `push<T>()` and `replace()` show the location. In `context.nav` both names are in lowerCamelCase; elsewhere `<feature>` is the id of the feature.
- A route is in three places, which agree on its name, `<feature>.<route>`, and on its path, which starts with `/<feature>`:
  1. its screen, a widget in `lib/features/<feature>/` whose `const` constructor takes each value of the route as a named parameter;
  2. `lib/core/router/navigation.dart`: its location class, which extends the sealed `AppLocation` with its `routeName`, its `path` and, below another route, its `parent`, and a method that returns its `NavLink` in the class of the routes of its feature. `AppNav` returns that class from a getter with the name of the feature, and both classes pass on the `BuildContext` that `NavLink` takes;
  3. the route itself, where the provider of the router declares its routes.
- A value of a route is a `String`, an `int`, a `double` or a `bool`, from a `:<name>` segment of its path or from the query.
- `appRouter` of `lib/core/router/app_router.dart` is the one router of the app: create no other.

- `routeGuards` in `lib/core/router/app_router.dart` lists the guards of the routes, each a `RouteGuard`, in the order the router asks them. A guard without `routes` is a gate over the whole app. The gates come first, and the first one whose `allows` is `false` decides: the router asks no guard after it. A guard with `routes` keeps the user only from the routes that it names there, each as `<feature>.<route>`, and comes after the gates.
- To keep the user from the rest of the app, add a gate to that list, never a redirect to the files of the router. Put it at the place among the gates where its screen comes on a first launch: a guard of the first launch goes before one that asks who the user is. Make its `redirectTo` a top-level route outside the main navigation. To keep the user from some routes only, add their names to the `routes` of the guard that stands for what they need, or add such a guard after the gates. Add the name of each route below such a route too: a route does not ask because the route above it does. The `routes` are outside the main navigation and outside every `flow`, and the screen that the app starts on is none of them.
- A feature changes the value of `allows` of its guard, and the router navigates when it does. While the `allows` of a gate is `false`, the router shows its `redirectTo` in place of the whole stack, whichever location was asked for. Once the gates allow, the router shows the location that was asked for in the meantime, such as a link, or else brings the user back to where they were. A gate with `resumes: false` does not bring the user back. When the `allows` of a guard with `resumes: false` turns `false`, the router forgets where the user was and what was asked for before, even while the `redirectTo` of another guard is shown. Once the gates allow, the user comes to a location that was asked for since then, or else to the screen that the app starts on. So after a sign-out the next user does not come to the screen of the last one.
- While the `allows` of a guard with `routes` is `false`, `go()`, `push()` or `replace()` of one of those routes opens its `redirectTo` over the page that the user is on, and the request waits. Back returns to that page, and a `push()` that waited completes with `null`. Once the value is `true`, the router closes the pages of the `flow` and does what was asked: `push()` shows the route over the page that the user was on and completes with the value of its page, `go()` shows it in place of the stack, and `replace()` in place of that page. When the value turns `false`, the router closes the pages of the `routes` with the pages over them. The user is then on the page below them, or on the screen that the app starts on when no page is below, as after `go()` to one of the `routes`.
- A screen neither closes itself nor navigates after it changed the value of `allows` of a guard: the router has done both by then. This goes for a screen of a `flow` that turned the value `true`, as after a sign-in, and for a screen of the `routes` that turned it `false`, as a screen with a sign-out button. A `pop()` after the change closes the page that is on top by then: the page that the user asked for, or the page below the one that the router closed, which may be the main navigation of the app.
- The `flow` of a guard is its `redirectTo` and the routes below it. These routes show only while a guard with that `flow` does not allow. At any other time the router shows the screen that the app starts on in their place, or the `redirectTo` of a gate whose `allows` is `false`. So no code navigates into the `flow` of a gate, and no screen of a `flow` navigates out of it once its guard allows: the router does. The first does not hold for a guard with `routes`. While it does not allow and every gate does, its `redirectTo` shows like any route, so a screen may open it with `push()`. `go()` to it from a screen takes the place of the stack, with no way back. A link to a route of its `flow` opens that route over the screen that the app starts on, so back leads into the app. Such a link is lost while a gate with another `flow` does not allow: once the gate allows, the user is on the screen that the app starts on. Inside a `flow`, navigate with `push()` or `replace()`. `go()` takes the place of the pages below the `flow`, and the request that waits is lost with them.

With `go_router`:

- `lib/core/router/app_router_factory.dart` has the one `GoRouter` of the app. A route is a `GoRoute` in its `routes`, or in the `routes` of its parent: `path` is the full path of a top-level route and the path from its parent otherwise, and `name` is `<feature>.<route>`. The values of a route come from `state.pathParameters` and `state.uri.queryParameters`. Parse one that is not a `String` with `tryParse`, and throw a `GoException` in the `redirect` of the route when a required value is missing or does not parse, so that the router shows its error screen.
- The app opens at `initialLocation`, and the route `/` leads to the same screen: change both together.
- To follow the screen that the user sees, add a function to `_screenListeners`.

## State management

With `flutter_bloc`:

- The state of a screen is a `Cubit` in the directory of its feature. The screen provides it with a `BlocProvider` around its content. In a `BlocBuilder` there, it passes the state on to its view as plain values, and the methods of the `Cubit` as callbacks.
- The view is a widget in a file of its own that imports no `flutter_bloc`, so the look of a screen does not depend on what manages its state.
- When a screen is gone, its `BlocProvider` closes the `Cubit` that it created. For state that several screens read, put a `BlocProvider` around the root widget in `runApp()`, in `lib/main.dart`. A widget reads that `Cubit` with `context.watch`.
- After an `await`, a `Cubit` checks `isClosed` before it calls `emit()`. The user may have left the screen while the call was on its way, and `emit()` throws in a `Cubit` that is closed.
- A widget talks only to a `Cubit`, never to a service or a DI container. A `Cubit` takes what it needs through its constructor.

## RevenueCat

The app sells its premium access with [RevenueCat](https://www.revenuecat.com) and [purchases_flutter](https://pub.dev/packages/purchases_flutter): `lib/core/purchases/revenuecat_purchases_service.dart` implements the purchases service of the app on it (see the section Purchases). The premium access is the entitlement `premium` in RevenueCat, and the plans of the app are the packages of the default offering, which the SDK calls the current offering. Every package of that offering unlocks the same access, so attach each of its products to `premium`.

To buy a plan right after generating the app, with no account in a store:

1. Create a project in RevenueCat. A new project has a Test Store with products.
2. Create an entitlement with the identifier `premium` and attach the products to it.
3. Add the packages of those products to an offering, and make that offering the default one.
4. Copy the public API key of the Test Store, which starts with `test_`, into `REVENUECAT_TEST_KEY` in `.env`.
5. Run a debug build as the section Values in .env says, and buy a plan. The Test Store shows a dialog of its own, where "Test valid purchase" completes the purchase.

For a release, add the App Store app and the Play Store app to the project in RevenueCat. Give RevenueCat the In-App Purchase key of App Store Connect and a service account of Google Play, so that it checks the purchases in the stores. Create the products in the stores, attach them to `premium` and add their packages to the offering. Then copy the public API keys of the two apps into `REVENUECAT_APPLE_KEY` (`appl_`) and `REVENUECAT_GOOGLE_KEY` (`goog_`). The section Finish the setup lists these steps.

A debug build takes `REVENUECAT_TEST_KEY` when it is filled in, and the key of the store of the platform otherwise. A profile or release build never takes it: RevenueCat stops such a build that is configured with a key of the Test Store, on purpose. So to try the sandbox of a store in a debug build, leave `REVENUECAT_TEST_KEY` empty.

These keys are the public API keys of RevenueCat, which go into the app, where anyone can read them. A secret API key of RevenueCat, which starts with `sk_`, never goes into `.env`, and the app refuses one. While the key that a build takes has no value, the app runs without purchases: it never calls RevenueCat, every call of `appPurchases` fails with the reason `notConfigured`, and a debug build prints which key to fill in.

## Purchases

The app sells premium access through `appPurchases` in `lib/core/purchases/app_purchases.dart`. Every plan of the current offer gives the same access, whether it renews or the user pays once.

`appPurchases.value` is `NoAccess` or `PremiumAccess`, and `appPurchases.hasPremium` tells which. The app knows it before the first frame, from what the device keeps. `PremiumAccess` tells when the access ends (`expiresAt`, `null` for an access that never ends), whether the plan `renews`, whether the access is a free trial (`inTrial`), and `manageUrl`, the page of the store where the user manages or cancels the plan. `appPurchases.plans()` gives the plans to sell, `appPurchases.purchase(plan)` buys one and returns `false` when the user cancels, and `appPurchases.restore()` gives the user what the store account bought. A call fails only with a `PurchasesFailure`: show a text of the app for its `reason`, and its `developerHint` in debug mode only.

A screen that sells a plan shows what the App Store and Google Play ask of it:
- the name of the plan, how long a period lasts and what the user gets;
- the full price that the store charges for each period, shown more clearly than any other price on the screen, and for a yearly plan never mainly as a price per month;
- for a free trial or a lower price at first, how long it lasts and the price after it;
- that the plan renews until the user cancels, and how to cancel it in the store;
- a way to restore purchases;
- links to the terms of use and the privacy policy of the app;
- a visible way to close the screen without buying.

A screen that only users with premium access may see stands behind a guard of the routes that reads `appPurchases.hasPremium`. Without such a guard, every user gets to it.

The purchases belong to this installation of the app. On another device, or after the app was installed again, the user restores them. This app has no settings screen, so the screen that sells has to offer the restore itself.

Until the provider of purchases has what it needs, such as its keys, the app runs without purchases: `appPurchases.value` stays `NoAccess`, every call fails with the reason `notConfigured`, whose `developerHint` names what is missing, and in debug mode the app prints that hint once.

## Paywall

The paywall is at `/paywall`, in `lib/features/paywall/`. It shows the plans of the current offer of the purchases of the app (see the section Purchases): a card for each plan, with the price that the store gives, how often the plan renews and its free trial or lower price at first. A yearly plan that costs less than twelve months of a monthly plan in the same currency is the best value. The button buys the selected plan, and the paywall restores purchases and links to your terms of use and your privacy policy.

The screen of the subscription, at `/paywall/subscription`, is only for a user with premium access. It shows the plan, when it renews or ends, and a button to the page of the store where the user manages or cancels it. A request for it from a user without the access opens the paywall over the page first. In an app with a settings screen, its entry Subscription leads there. In an app without one, open it from a screen of yours with `context.nav.paywall.subscription().push<void>()`, so that the user finds where to cancel.

No screen of the paywall closes itself or navigates after a purchase. The route `/paywall/subscription` asks for premium access, and the guard `paywall.hasPremium` stands for it: once the user has the access, the router closes the paywall and shows the route. To sell from a button of yours, navigate to a route that needs premium access, as above. To keep a screen of your own for users with the access, list `PurchasesRole.premium` in the `conditions` of its route in a module, or add its full name to the `routes` of `paywall.hasPremium` in `routeGuards`. Do not navigate to `/paywall` itself for a user with premium access: the router shows the screen that the app starts on then.

The paywall shows what the App Store and Google Play ask of a screen that sells a plan: the full price of each plan most clearly, the length of a free trial and the price after it right below the button, that the plan renews until the user cancels it in the store, a way to restore purchases, the links to the terms of use and the privacy policy, and a close button that stays in sight. A plan paid once says that it is no subscription.

A text of the app has no parameters, so the paywall names the periods and the lengths of intro offers that the stores have: a plan that renews every week, every 1, 2, 3 or 6 months, or every year, and an intro offer of 3 days, 1 or 2 weeks, 1, 2, 3 or 6 months, or 1 year. A plan of another period shows the title of its product in the store, and an intro offer of another length is a free trial or an introductory price without its length. `lib/features/paywall/paywall_texts.dart` puts these texts together.

The benefits on the paywall are texts of the module, `benefitAll`, `benefitNew` and `benefitSupport`. Change them to what premium access gives in your app. In an app with localization, they are texts of the app, which `lib/features/paywall/paywall_view.dart` reads as `context.l10n.paywallBenefitAll`, `paywallBenefitNew` and `paywallBenefitSupport`: change them where the provider of the localization keeps the texts of the app, in each language. In an app without it, they are the English texts in that file.

Put the addresses of your terms of use and of your privacy policy into `PAYWALL_TERMS_URL` and `PAYWALL_PRIVACY_URL` in `.env` (see the section Values in .env). The App Store asks a paywall to link to both. While a value is empty or is no web address, the paywall leaves its link out, but on iOS the terms of use then lead to the standard license agreement of Apple. A debug build shows a note for you at the bottom of the paywall, which names the keys that are empty and what the provider of purchases says is missing, such as its key.

In an app with an onboarding, the onboarding offers premium access on a page of its own, after the pages that ask for permissions, while the user has none. Its button shows the paywall over the onboarding, and the onboarding goes on once the user closes the paywall or buys a plan. Not now goes on without the paywall. The page shows no price: the prices are on the paywall. Its texts are texts of the module too, and you change them the way you change the benefits.

In an app with sign-in, a user may buy before signing in. A sign-up keeps the purchase in the new account, while a sign-in to an account that exists already leaves the purchase with the user of the device until the user restores it.

/// before the first frame, the plans that the app sells, and the way to buy

///

final appPurchases = AppPurchasesController();

/// Keeps the access of the user up to date with the service of the provider
/// of purchases, and buys and restores through that service. The app has
/// one, [appPurchases].
///
/// Every call here fails only with a [PurchasesFailure], whose reason the
/// app shows in a text of its own. An error of another kind becomes a
/// failure with the reason [PurchasesFailureReason.unknown] and the error as
/// its [PurchasesFailure.developerHint].
///
/// The calls run one after another, in the order they were made, and so
/// does what the controller does itself when the user of the app changes or
/// comes back to the app. Before each, the controller identifies the user
/// with the service, unless the service has that user already. So a
/// purchase belongs to the user who made it: a change of the user waits for
/// it.
///
/// An error that no caller sees, of the start, of a change of the user, of
/// the return of the user to the app or of the changes that the service
/// tells of, changes nothing. A failure [PurchasesFailureReason.notConfigured]
/// prints its hint once in debug mode. [PurchasesFailureReason.network],
/// [PurchasesFailureReason.unavailable] and
/// [PurchasesFailureReason.storeProblem], which pass, say nothing. Any other
/// error reaches the handlers of the uncaught errors of the app. So the app
/// starts and runs without purchases when the provider is not set up or the
/// store does not answer.
final class AppPurchasesController extends ChangeNotifier
    implements ValueListenable<AppAccess> {
  /// Creates a controller. The app creates [appPurchases] and no other. A
  /// test creates one to start it with a service of its own, or with a
  /// shorter [startWait], and disposes of it.
  AppPurchasesController({this.startWait = const Duration(seconds: 3)});

  /// How long [start] waits at most for the access of the user and for the
  /// calls made before it.
  final Duration startWait;

  PurchasesService? _service;
  StreamSubscription<AppAccess>? _accessChanges;
  String? Function()? _userId;
  Listenable? _userChanges;
  AppAccess _access = const NoAccess();
  bool _disposed = false;

  /// The service and the user that the service was last identified with,
  /// or `null` while no identification with the service succeeded.
  _Identity? _identified;

  /// Whether [start] was called.
  bool _starting = false;

  /// Whether the controller has started for the first time.
  bool _started = false;

  /// Completes at the first start. Only the first call made before it waits
  /// for it, and each later call waits for the call before it. That call
  /// creates it, so the start completes it in the zone of the call: created
  /// with the controller, it would complete in a microtask of the zone that
  /// read [appPurchases] first, which may run none any more, as the fake
  /// time of a widget test that is over before a later test starts the app
  /// in real time.
  Completer<void>? _untilStarted;

  /// The call that was made last, while a call is on its way: the next one
  /// waits for it. It is `null` when none is, and a call then awaits
  /// nothing. A future that completed in another zone would hold the call
  /// back in a widget test, where the app starts in real time and the test
  /// goes on in fake time.
  Future<void>? _lastCall;

  /// Whether a look at the user and at the access waits for its turn, so
  /// that the changes and returns that come meanwhile need no other.
  bool _lookWaits = false;

  /// Tells when the user comes back to the app.
  _ResumeObserver? _observer;

  /// The hints of the failures [PurchasesFailureReason.notConfigured] that
  /// the controller printed.
  final Set<String?> _printed = {};

  /// The access of the user.
  @override
  AppAccess get value => _access;

  /// Whether the user has premium access, as a guard of the routes reads it.
  ///
  /// It is computed from [value] each time it is read, and its listeners
  /// are those of the controller. A listener is also called for a change of
  /// [value] that leaves this value as it was, such as a plan that renews.
  late final ValueListenable<bool> hasPremium = _PremiumFlag(this);

  /// Starts with [service]: identifies the user with it, takes the access of
  /// the user, and follows the changes of the access that the service tells
  /// of.
  ///
  /// [userId] returns the id of the user of the app, or `null` for the user
  /// of this device, and [userChanges] tells when it may have changed, such
  /// as the session of an app with sign-in. Without them, the purchases are
  /// those of the user of this device. When the user changes, [value] is
  /// [NoAccess] until the service has the new user, and the controller takes
  /// no change of the access that the service tells of meanwhile.
  ///
  /// `initPurchases()` calls it in `bootstrap()`, so [value] is known before
  /// the first frame. It waits for the access at most [startWait]: an access
  /// that comes later still becomes [value], and the app starts without
  /// waiting for it.
  ///
  /// A call made before the first start waits for it: [plans], [purchase]
  /// and [restore]. Such calls run in their order once the start has the
  /// access, and the future of this start completes after them, and after
  /// the calls that their completions make right away: it completes once no
  /// call is on its way in the microtask after the last one ended. The mocks
  /// of the tests of an app use this: `plans().then(...)` that buys a plan,
  /// made before `bootstrap()`, gives the app premium access before its first
  /// frame. A test makes such a call outside the body of a test, as in a
  /// `setUpAll`: made in the body of a widget test, it waits in the fake time
  /// of that body, and a start that runs in real time completes after
  /// [startWait] without it.
  ///
  /// It may be called again, with the service that the controller has from
  /// then on: `initPurchases()` does so in a test of the next launch of the
  /// app, and a test gives it a service of its own. Such a start takes its
  /// turn after the calls that are on their way, and [value] is then that of
  /// the new service.
  Future<void> start(
    PurchasesService service, {
    String? Function()? userId,
    Listenable? userChanges,
  }) =>
      _start(service, userId, userChanges).timeout(startWait, onTimeout: () {});

  /// The plans of the current offer of the app, at least one, in the order
  /// of the provider. Show them only to a user without premium access.
  Future<List<Plan>> plans() => _call((service, _) => service.plans());

  /// Buys [plan] through the sheet of the store, and completes with `true`
  /// once the user has bought it, or with `false` when the user cancelled,
  /// which is no failure. The access that the purchase gave becomes [value],
  /// unless the user of the app changed meanwhile.
  ///
  /// A payment that waits for an approval fails with
  /// [PurchasesFailureReason.pending]: the access comes once the store took
  /// the payment. A purchase whose answer gives no premium access, as with a
  /// plan that the backend of the provider does not tie to the access, fails
  /// with [PurchasesFailureReason.notConfigured]: the user paid, and a
  /// restore gives the access once the provider is set up.
  Future<bool> purchase(Plan plan) => _call((service, identity) async {
    final access = await service.purchase(plan);
    if (access == null) return false;
    if (access is! PremiumAccess) {
      throw const PurchasesFailure(
        PurchasesFailureReason.notConfigured,
        developerHint:
            'The plan was bought, but it gives no premium '
            'access: check the setup of the provider.',
      );
    }
    _take(identity, access);
    return true;
  });

  /// Gives the user what the store account of the user bought, such as on a
  /// new device, and completes with the access of the user then. That access
  /// becomes [value], unless the user of the app changed meanwhile.
  Future<AppAccess> restore() => _call((service, identity) async {
    final access = await service.restore();
    _take(identity, access);
    return access;
  });

  /// Stops following the service, the user and the lifecycle of the app. A
  /// call that is on its way still ends as it would have, but tells no
  /// listener. A start or a look at the access that waits for its turn does
  /// nothing then.
  @override
  void dispose() {
    _disposed = true;
    unawaited(_accessChanges?.cancel());
    _userChanges?.removeListener(_onUserChange);
    if (_observer case final observer?) {
      WidgetsBinding.instance.removeObserver(observer);
    }
    super.dispose();
  }

  Future<void> _start(
    PurchasesService service,
    String? Function()? userId,
    Listenable? userChanges,
  ) async {
    if (_starting) {
      await _turn(() => _use(service, userId, userChanges));
    } else {
      _starting = true;
      await _use(service, userId, userChanges);
      _started = true;
      _untilStarted?.complete();
    }
    await _settled();
  }

  /// Takes [service] as the service of the controller, with the user of
  /// [userId], and looks at the user and at the access, unless the
  /// controller was disposed of while the start waited for its turn.
  Future<void> _use(
    PurchasesService service,
    String? Function()? userId,
    Listenable? userChanges,
  ) async {
    if (_disposed) return;
    unawaited(_accessChanges?.cancel());
    _userChanges?.removeListener(_onUserChange);
    _service = service;
    _userId = userId;
    _userChanges = userChanges?..addListener(_onUserChange);
    _identified = null;
    _set(const NoAccess());
    _accessChanges = service.accessChanges.listen(
      (access) => _onAccessChange(service, access),
      onError: _report,
    );
    if (_observer == null) {
      final observer = _observer = _ResumeObserver(_lookLater);
      WidgetsBinding.instance.addObserver(observer);
    }
    await _quietly(_look);
  }

  /// Completes once no call is on its way, and none was made in the
  /// microtask after the last one ended.
  Future<void> _settled() async {
    while (true) {
      final last = _lastCall;
      if (last != null) {
        await last;
        continue;
      }
      await Future<void>.microtask(() {});
      if (_lastCall == null) return;
    }
  }

  /// Runs [call] with the service and the user of the app, once the calls
  /// made before it are over, and turns whatever it throws that is no
  /// [PurchasesFailure] into one.
  Future<T> _call<T>(
    Future<T> Function(PurchasesService service, _Identity identity) call,
  ) => _turn(() async {
    try {
      final service = _service!;
      final before = _identified;
      final identity = await _identify(service);
      // A call that identified the user again, as after an
      // identification that failed, is followed by a look at the access
      // of the user.
      if (identity != before) _lookLater();
      return await call(service, identity);
    } on PurchasesFailure {
      rethrow;
    } on Object catch (error, stackTrace) {
      Error.throwWithStackTrace(
        PurchasesFailure(
          PurchasesFailureReason.unknown,
          developerHint: '$error',
        ),
        stackTrace,
      );
    }
  });

  /// Runs [job] once the calls made before it are over, and not before the
  /// controller has started for the first time.
  Future<T> _turn<T>(Future<T> Function() job) async {
    final earlier =
        _lastCall ??
        (_started ? null : (_untilStarted ??= Completer<void>()).future);
    final done = Completer<void>();
    final own = _lastCall = done.future;
    if (earlier != null) await earlier;
    try {
      return await job();
    } finally {
      if (identical(_lastCall, own)) _lastCall = null;
      done.complete();
    }
  }

  /// Identifies the user of the app with [service], unless [service] has
  /// that user already, and returns the identity.
  Future<_Identity> _identify(PurchasesService service) async {
    final user = _userId?.call();
    final identified = _identified;
    if (identified != null &&
        identical(identified.service, service) &&
        identified.user == user) {
      return identified;
    }
    // Until the identification succeeds, the service has no user that the
    // controller knows of, and the user has no access.
    _identified = null;
    _set(const NoAccess());
    await service.identify(user);
    final identity = (service: service, user: user);
    if (identical(service, _service)) _identified = identity;
    return identity;
  }

  /// Identifies the user, and takes the access of that user, unless the
  /// controller was disposed of while the look waited for its turn.
  Future<void> _look() async {
    if (_disposed) return;
    final service = _service!;
    final identity = await _identify(service);
    _take(identity, await service.access());
  }

  /// Looks at the user and at the access in its turn, unless a look waits
  /// for its turn already.
  void _lookLater() {
    if (_lookWaits || _disposed) return;
    _lookWaits = true;
    unawaited(
      _turn(() {
        _lookWaits = false;
        return _quietly(_look);
      }),
    );
  }

  /// The user of the app may have changed. If it has, [value] is [NoAccess]
  /// until the service has the new user.
  void _onUserChange() {
    final identified = _identified;
    if (identified != null && identified.user == _userId?.call()) return;
    _set(const NoAccess());
    _lookLater();
  }

  /// Takes [access], which [service] told of, while [service] has the user
  /// of the app.
  void _onAccessChange(PurchasesService service, AppAccess access) {
    final identified = _identified;
    if (identified != null && identical(identified.service, service)) {
      _take(identified, access);
    }
  }

  /// Takes [access], the answer of the service of [identity], as [value],
  /// while the controller has that service and the service has the user of
  /// [identity], who is still the user of the app. The answer for a user
  /// who is no longer the user of the app changes nothing.
  void _take(_Identity identity, AppAccess access) {
    final identified = _identified;
    if (identified != null &&
        identical(identified.service, identity.service) &&
        identical(identity.service, _service) &&
        identified.user == identity.user &&
        identity.user == _userId?.call()) {
      _set(access);
    }
  }

  /// Takes [access] as [value], and tells the listeners when that changes
  /// it, unless the controller was disposed of.
  void _set(AppAccess access) {
    if (_disposed || access == _access) return;
    _access = access;
    notifyListeners();
  }

  /// Runs [job], whose errors no caller sees, and reports what it throws.
  Future<void> _quietly(Future<void> Function() job) async {
    try {
      await job();
    } on Object catch (error, stackTrace) {
      _report(error, stackTrace);
    }
  }

  /// Reports [error], which no caller sees.
  void _report(Object error, StackTrace stackTrace) {
    switch (error) {
      case PurchasesFailure(
        reason: PurchasesFailureReason.notConfigured,
        :final developerHint,
      ):
        if (kDebugMode && _printed.add(developerHint)) {
          debugPrint(
            'Purchases are not set up, so the app runs without them: '
            '$developerHint',
          );
        }
      case PurchasesFailure(
        reason: PurchasesFailureReason.network ||
            PurchasesFailureReason.unavailable ||
            PurchasesFailureReason.storeProblem,
      ):
        break;
      default:
        Zone.current.handleUncaughtError(error, stackTrace);
    }
  }
}

/// What the user may use of the app: [NoAccess], or [PremiumAccess] while a
/// plan that the user bought is active.
sealed class AppAccess {
  const AppAccess();
}

/// The user has no plan that is active, or the app does not know of one.
final class NoAccess extends AppAccess {
  /// Creates the access of a user without premium access.
  const NoAccess();

  @override
  bool operator ==(Object other) => other is NoAccess;

  @override
  int get hashCode => (NoAccess).hashCode;

  @override
  String toString() => 'NoAccess()';
}

/// The user has premium access: a plan that the user bought is active.
/// Every plan of the app gives the same access.
final class PremiumAccess extends AppAccess {
  /// Creates the premium access of a plan, with what the provider knows of
  /// it.
  const PremiumAccess({
    this.expiresAt,
    this.renews = false,
    this.inTrial = false,
    this.period,
    this.manageUrl,
  });

  /// When the access ends unless the plan renews, or `null` for an access
  /// that never ends, as that of a plan paid once.
  final DateTime? expiresAt;

  /// Whether the store renews the plan when [expiresAt] comes: `false` once
  /// the user cancelled, and for a plan paid once.
  final bool renews;

  /// Whether the access is the free trial of its plan: the store charges the
  /// price of the plan once the trial ends, unless the user cancels.
  final bool inTrial;

  /// How often the plan is billed, or `null` for a plan paid once, or when
  /// the provider does not know.
  final BillingPeriod? period;

  /// The page of the store where the user manages or cancels the plan, or
  /// `null` when the store has none for it, as for a plan paid once.
  final Uri? manageUrl;

  @override
  bool operator ==(Object other) =>
      other is PremiumAccess &&
      other.expiresAt == expiresAt &&
      other.renews == renews &&
      other.inTrial == inTrial &&
      other.period == period &&
      other.manageUrl == manageUrl;

  @override
  int get hashCode =>
      Object.hash(expiresAt, renews, inTrial, period, manageUrl);

  @override
  String toString() =>
      'PremiumAccess(expiresAt: $expiresAt, renews: $renews, '
      'inTrial: $inTrial, period: $period, manageUrl: $manageUrl)';
}

/// Why a call of purchases failed.
enum PurchasesFailureReason {
  /// The device did not reach the store or the provider.
  network,

  /// The payment waits for an approval, as one that a parent approves, or
  /// for a payment method that takes a while. The access comes once the
  /// store took the payment, and the service tells of it then.
  pending,

  /// The store account of the user owns the plan already: a restore gives
  /// the user its access.
  alreadyOwned,

  /// The user may not pay on this device, as with parental controls or
  /// payments that are turned off.
  notAllowed,

  /// The store, or the plan, is not available on this device or for this
  /// store account, as on a device without the store.
  unavailable,

  /// The store failed on its side. Trying again later may help.
  storeProblem,

  /// Purchases are not set up, such as a key of the provider that is
  /// missing, or an offer without plans. This is a mistake in the setup of
  /// the app, which [PurchasesFailure.developerHint] explains.
  notConfigured,

  /// Anything else. [PurchasesFailure.developerHint] has the error.
  unknown,
}

/// The failure of a call of purchases: the only thing that such a call
/// throws. A user who cancels a purchase is no failure.
final class PurchasesFailure implements Exception {
  /// Creates the failure for [reason].
  const PurchasesFailure(this.reason, {this.developerHint});

  /// Why the call failed. The app shows a text of its own for each reason.
  final PurchasesFailureReason reason;

  /// What went wrong in the words of the provider, for the developer of the
  /// app, or `null`. It is no text for the user: show it in debug mode
  /// only.
  final String? developerHint;

  @override
  String toString() => developerHint == null
      ? 'PurchasesFailure: ${reason.name}'
      : 'PurchasesFailure: ${reason.name} ($developerHint)';
}

/// The purchases of the users of the app, as the provider of purchases and
/// the store keep them.
///
/// The provider implements it. The code of the app does not call it: it
/// uses `appPurchases` of `app_purchases.dart`, which calls this service and
/// does what is the same with every provider.
///
/// Every implementation keeps to this:
/// - The function that creates the service creates it without a user, asks
///   the user nothing, and never throws. It may be called again, and the
///   service that it returns then has what the store and the provider kept.
/// - [identify] comes before any other call, so a provider can set itself up
///   with the user. Each call is for the user that [identify] last gave.
/// - `identify(null)` makes the user of this device the user whose
///   purchases count. When it follows another user, also one of an earlier
///   launch of the app, it starts a new user of this device, with nothing
///   bought: what a user of the device had before comes back only through
///   [restore].
/// - When the user of this device is identified as a user that no
///   [identify] named before, on any device, that user takes over the
///   purchases of the user of this device, who no longer has them. So a
///   purchase before a sign-up stays with the new account.
/// - Any other [identify] keeps the purchases of each user apart.
/// - [restore] gives the user what the store account bought, and may move
///   purchases from another user to this one, as the backend of the
///   provider decides. So no test relies on a restore that moves them, or on
///   one that leaves them.
/// - [access] completes from what the device keeps, without the network
///   when it keeps anything.
/// - A call fails only with a [PurchasesFailure]. Without what it needs,
///   such as a key, the service fails every call with
///   [PurchasesFailureReason.notConfigured] and a

/// The key with which the app configures RevenueCat on [platform], in a
/// debug build when [debug], from the values of `.env`: [apple], [google]
/// and [test], each `null` while it is empty.
///
/// A debug build takes the key of the Test Store, [test], when `.env` has
/// one, so that a purchase works with nothing but a RevenueCat account. A
/// profile or release build never takes it: RevenueCat stops such a build
/// that is configured with a key of the Test Store, on purpose. Otherwise
/// the app takes the key of the store of the platform: [apple] on iOS and
/// [google] on Android.
///
/// It takes no key when that key has no value in the build, when it is a
/// secret key of RevenueCat (`sk_`), which never goes into an app, and in a
/// profile or release build when it is a key of the Test Store (`test_`).
/// The hint of [RevenueCatKey.none] then names the key and tells what to
/// do.
RevenueCatKey revenueCatKey({
  required TargetPlatform platform,
  required bool debug,
  required String? apple,
  required String? google,
  required String? test,
}) {
  final (String, String?, String)? chosen = debug && test != null
      ? (_testKey, test, 'the Test Store')
      : switch (platform) {
          TargetPlatform.iOS => (_appleKey, apple, 'the App Store app'),
          TargetPlatform.android => (_googleKey, google, 'the Play Store app'),
          _ => null,
        };
  if (chosen == null) {
    return RevenueCatKey.none(
      'The app sells through RevenueCat on Android and iOS only, and runs '
      'on ${platform.name} here.',
    );
  }
  final (name, value, app) = chosen;
  if (value == null) {
    return RevenueCatKey.none(
      '$name has no value in this build. In .env, give it the public API key '
      'of $app in RevenueCat${debug ? ', or give $_testKey the public API key '
                'of the Test Store' : ''}. Then build the app as the section '
      '"Values in .env" of its README says.',
    );
  }
  if (value.startsWith('sk_')) {
    return RevenueCatKey.none(
      '$name in .env is a secret key of RevenueCat, which never goes into an '
      'app: use the public API key of $app.',
    );
  }
  if (!debug && value.startsWith('test_')) {
    return RevenueCatKey.none(
      '$name in .env is a key of the Test Store, which RevenueCat refuses in '
      'a profile or release build: use the public API key of $app.',
    );
  }
  return RevenueCatKey(name, value);
}

/// The period of a subscription in ISO 8601, such as `P1M`, or `null` for a
/// product that the user pays for once.
BillingPeriod? _periodIn(String? iso) {
  final match = RegExp(r'^P(\d+)([DWMY])$').firstMatch(iso ?? '');
  if (match == null) return null;
  final count = int.parse(match[1]!);
  if (count < 1) return null;
  return BillingPeriod(count, switch (match[2]!) {
    'D' => BillingUnit.day,
    'W' => BillingUnit.week,
    'M' => BillingUnit.month,
    _ => BillingUnit.year,
  });
}

/// The code of RevenueCat in [error], or `null` when it is no code of
/// RevenueCat, as for an error of the plugin itself, whose code is no
/// number.

  final number = int.tryParse(error.code);
  if (number == null ||
      number < 0 ||
      number >= PurchasesErrorCode.values.length) {
    return null;
  }
  return PurchasesErrorCode.values[number];
}

    PurchasesErrorCode.receiptInUseByOtherSubscriberError ||
    PurchasesErrorCode.purchaseBelongsToOtherUser =>
      'The store account owns the product already ($said).',
    PurchasesErrorCode.testStoreSimulatedPurchaseError =>

          'told to ($said).',

/// Moves between the locations of the app.
abstract interface class AppNavigator {
  /// Shows [location] with the chain of its parents below it as the stack.
  ///
  /// In the main navigation, it selects the branch of [location] and makes
  /// the chain its stack; for a location outside the main navigation, the
  /// chain replaces the whole stack, main navigation included.
  void go(AppLocation location);

  /// Shows [location] on top of the current stack and completes with the
  /// value the page returns when it closes.
  ///
  /// In the main navigation, the current stack is that of the selected
  /// branch, whichever branch [location] belongs to, and the selected
  /// destination stays; a location outside the main navigation is shown
  /// over it. A location in the main navigation goes only on top of the
  /// main navigation itself: from a page shown over it, this throws a
  /// [StateError] and leaves the stack as it is, so [go] to the location
  /// instead. From a page with no main navigation below it, the main
  /// navigation comes on top with the location.
  Future<T?> push<T extends Object?>(AppLocation location);

  /// Replaces the top of the current stack with [location].
  ///
  /// As with [push], a location in the main navigation cannot replace a
  /// page shown over the main navigation: this throws a [StateError] and
  /// leaves the stack as it is, so [go] to the location instead.
  void replace(AppLocation location);
}

/// A guard of the routes of the app. Without [routes] it is a gate: while
/// it does not allow, the router shows its target in place of every
/// location outside its flow. With [routes] it keeps the user only from
/// those routes, and the router shows every other route as it is.
///
/// While a gate does not allow, `go()`, `push()` and `replace()` of a
/// location that it keeps the user from show its target in place of the
/// whole stack, and `push()` completes with `null`. Once it allows, the
/// router shows the location that the user last asked for, or the one that
/// the gate took the user from if it [resumes], or else the screen that
/// the app starts on.
///
/// While a guard with [routes] does not allow, a request for one of them
/// opens its target over the page that the user is on, and the request
/// waits. Back returns to that page and drops the request. Once the guard
/// allows, the router closes the pages of the flow and does what was asked:
/// `push()` shows the location over the page that the user was on, and
/// completes with the value of its page, `go()` shows it in place of the
/// stack, and `replace()` in place of that page. A further request for one
/// of the [routes] does nothing while the flow is open. A location from
/// the platform opens the target over the screen that the app starts on.
/// When the guard stops allowing, the router closes each page of its
/// [routes] and the pages over it.
///
/// The routes of its flow show only while it does not allow, or while
/// another guard with the same flow does not. At any other time the router
/// shows the screen that the app starts on in place of a location of the
/// flow (see [flowIsOver]), or the target of a gate while that one does
/// not allow. So the code of the app changes what [allows] reads. It
/// navigates into a flow only while a guard with [routes] and that flow
/// does not allow and every gate does, as to a sign-in that a guest opens.
final class RouteGuard {
  /// Creates the guard [name].
  const RouteGuard(
    this.name, {
    required this.allows,
    required this.redirectTo,
    required this.flow,
    this.resumes = true,
    this.routes,
  });

  /// The full name of the guard: its module and its name there.
  final String name;

  /// Whether the guard lets the user see the locations that it keeps them
  /// from otherwise; it notifies its listeners when that changes.
  final ValueListenable<bool> allows;

  /// The target of the guard: the location that the router shows while the
  /// guard does not allow.
  final AppLocation redirectTo;

  /// The full names of the routes that the user may see while the guard
  /// does not allow: the route of [redirectTo] and the routes below it.
  /// Once every guard with this flow allows, the router shows none of them.
  final Set<String> flow;

  /// Whether the router brings the user back to the location that the
  /// guard takes them from when it stops allowing, once it allows again.
  ///
  /// With `false`, the router forgets what it remembers when the guard
  /// stops allowing: where the user was, whichever gate took them from
  /// it, and a location that was asked for before. So once the gates
  /// allow, the user comes to the screen that the app starts on, as the
  /// next user does after a sign-out, unless a location was asked for
  /// since the guard stopped, such as a link.
  ///
  /// The router remembers a location only for a gate. A guard with
  /// [routes] closes its pages when it stops allowing, so the user is on
  /// the page below them, whatever this says. With `false`, such a guard
  /// still makes the router forget what a gate made it remember.
  final bool resumes;

  /// The full names of the routes that the guard keeps the user from while
  /// it does not allow, or `null` for a gate, which keeps the user from
  /// every route outside its [flow].
  ///
  /// A guard with routes stands for something that only those routes need,
  /// such as an account: every other route shows whatever the guard says.
  /// None of its routes is in the [flow] of a guard. To ask for it on one
  /// more route, add the full name of the route here, and that of each
  /// route below it: a route does not ask because the route above it does.
  final Set<String>? routes;
}

/// The guards of the routes of the app, in the order the app asks them:
/// the gates first, and then the guards with [RouteGuard.routes].
final List<RouteGuard> routeGuards = [

    allows: guard0.paywallHasPremium(),
    redirectTo: const PaywallPaywallLocation(),
    flow: const {'paywall.paywall'},
    routes: const {'paywall.subscription'},

/// The location that the router shows when it is asked for the route
/// [routeName] and a guard keeps the user from it, or `null` if the guards
/// let the user see the route.
///
/// [routeName] is the full name of a route, or `null` for a screen that is
/// no route of a module, such as the error screen of the router. The first
/// gate that does not allow decides, and no guard after it is asked: it
/// shows its target in place of every route outside its flow. When every
/// gate allows, the first guard that has the route among its
/// [RouteGuard.routes] and does not allow shows its target: over the page
/// that the user is on, not in place of it.
///
/// A route that the guards let the user see may still be in a flow that is
/// over, in place of which the router shows the screen that the app starts
/// on; see [flowIsOver].
AppLocation? redirectOf(String? routeName) =>
    _guardKeepingFrom(routeName)?.redirectTo;

/// The guard that keeps the user from the route [routeName], or `null` if
/// the guards let the user see it: the first gate that does not allow,
/// unless the route is in its flow, or else the first guard with
/// [RouteGuard.routes] that does not allow and has the route among them.
RouteGuard? _guardKeepingFrom(String? routeName) {
  for (final guard in routeGuards) {
    if (guard.allows.value) continue;
    final routes = guard.routes;
    if (routes == null) return guard.flow.contains(routeName) ? null : guard;
    if (routes.contains(routeName)) return guard;
  }
  return null;
}

/// Whether the route [routeName] is in the flow of a guard and every guard
/// with that flow allows: the flow is over. The router then shows the
/// screen that the app starts on in place of the route, unless another
/// guard does not allow and shows its target instead (see
/// [redirectOf]).
///
/// [routeName] is the full name of a route, or `null` for a screen that is
/// no route of a module, which is in no flow. Two guards with one target
/// have one flow, which is over once both allow.
bool flowIsOver(String? routeName) {
  final guards = routeGuards.where((guard) => guard.flow.contains(routeName));
  return guards.isNotEmpty && guards.every((guard) => guard.allows.value);
}

/// What [GuardedNavigation.asked] answers a router that is not to show the
/// location that it asked about: [ShowInstead], [ShowOver] or [ShowNothing].
sealed class WhenAsked<L> {}

/// What [GuardedNavigation.changed] answers a router that is to change its
/// pages: [ShowInstead] or [ClosePages].
sealed class WhenChanged<L> {}

/// The router shows [location] in place of its whole stack, as `go()` to
/// it does. A `push()` that it asked about completes with `null`.
final class ShowInstead<L> implements WhenAsked<L>, WhenChanged<L> {
  /// Creates the answer.
  const ShowInstead(this.location);

  /// The location to show: the target of a gate, the location that the
  /// user comes back to, or the screen that the app starts on.
  final L location;
}

/// The router shows [location] over the page on top, as `push()` of it
/// does, and keeps the request that it asked about waiting while a page of
/// a route of [flow] is among its pages.
///
/// The router makes the request again once [GuardedNavigation.changed] closes
/// the last of those pages, unless that answer drops the request. And it
/// drops the request when the last of them leaves in another way, as when
/// the user goes back. It keeps one request: a request that waited before
/// is dropped.
final class ShowOver<L> implements WhenAsked<L> {
  /// Creates the answer.
  const ShowOver(this.location, {required this.flow});

  /// The location to show on top: the target of a guard with
  /// [RouteGuard.routes], or a page of its flow that was asked for with no
  /// pages.
  final L location;

  /// The full names of the routes of the flow of that guard.
  final Set<String> flow;
}

/// The router shows nothing and leaves its pages as they are: the flow of
/// the guard is open already. A `push()` that it asked about completes
/// with `null`.
final class ShowNothing<L> implements WhenAsked<L> {
  /// Creates the answer.
  const ShowNothing();
}

/// The router closes the [pages] pages on top, at once and whatever its
/// navigator shows over them, such as a dialog. Each `push()` that showed
/// one of them completes with `null`, at once or when the frame is over.
///
/// Then, if a request waits: with [dropsRequest] the router drops it. And
/// else it makes the request again, if no page of the flow of that request
/// is left.
final class ClosePages<L> implements WhenChanged<L> {
  /// Creates the answer.
  const ClosePages(this.pages, {required this.dropsRequest});

  /// How many pages to close, from the one on top down. The router said of
  /// each that it can close it on its own, and a page stays below them.
  final int pages;

  /// Whether the page that the last flow was opened over is among those
  /// that close: the request that waits for that flow was made on that
  /// page, so it is not made again on the page below.
  final bool dropsRequest;
}

/// The guards of the routes as the router of the app asks them, with what
/// the gates make it remember: the location that the user comes back to
/// once the gates allow it.
///
/// [L] is how the router knows a location that it can show as `go()`
/// does, such as its URI. The router asks [asked] once for each request to
/// show a location, before it shows it, and tells [changed] of its pages
/// each time [guardChanges] notifies. It does what either answers, and shows
/// the location, or leaves its pages as they are, when the answer is
/// `null`.
///
/// A gate answers with a location that takes the place of the whole stack.
/// A guard with [RouteGuard.routes] opens its target over the page that
/// the user is on and closes it again, so the user can go back from it,
/// and the request that opened it waits with the router, not here.
final class GuardedNavigation<L> {
  /// Creates the guards for a router whose location `/`, the screen that
  /// the app starts on, is [start], and which knows a location of the
  /// navigation, such as the target of a guard, as [locationOf] says.
  GuardedNavigation({required this.start, required this.locationOf});

  /// The location `/` of the router: the screen that the app starts on.
  final L start;

  /// The location of the router for a location of the navigation.
  final L Function(AppLocation location) locationOf;

  /// The location that the user comes back to once the gates allow it,
  /// with the full name of its route, or `null` if there is none.
  ({String? route, L location})? _remembered;

  /// The guards that do not bring the user back (see [RouteGuard.resumes])
  /// and that allowed when the class last looked at the guards, which it
  /// does each time it is asked or told. One of them that does not allow
  /// at the next look has stopped allowing. The class first looks when it
  /// is first asked or told, so a guard that does not allow then has not
  /// stopped.
  late final Set<RouteGuard> _allowed = {
    for (final guard in routeGuards)
      if (!guard.resumes && guard.allows.value) guard,
  };

  /// How many pages the flow that [asked] opened last was opened over: the
  /// request that waits for that flow was made on the one on top of them.
  int _below = 0;

  /// What the router does in place of showing [location], whose route has
  /// the full name [route], or `null` to show it.
  ///
  /// The router asks about a location before it shows it: the one the app
  /// starts on, each one that `go()`, `push()` or `replace()` is asked to
  /// show, and each one from the platform.
  /// [onTopOf] are the full names of the routes of the pages that the user
  /// can get back to then, as the router tells [changed] of them. The
  /// router gives none when it has no page yet, and none for a location
  /// from the platform, which takes the place of the stack.
  ///
  /// The answer is the first of these:
  /// - [ShowInstead] of the target of the gate that keeps the user from the
  ///   location (see [redirectOf]). The location is then remembered in place of
  ///   the one before it, so the user comes back to the latest one that
  ///   they or the platform asked for, whether or not that gate brings the
  ///   user back (see [RouteGuard.resumes]). A location in the flow of a
  ///   guard is never remembered: once that guard allows, its flow is over.
  /// - [ShowInstead] of [start] for a location in a flow that is over (see
  ///   [flowIsOver]).
  /// - for a location that a guard with [RouteGuard.routes] keeps the user
  ///   from: [ShowNothing] while a page of the flow of that guard is among
  ///   [onTopOf], on top or below another page, since the flow is open
  ///   already; and else [ShowOver] of the target of the guard, with its
  ///   flow.
  /// - for a location that no guard keeps the user from and that is asked
  ///   for with no pages, in a flow that only guards with
  ///   [RouteGuard.routes] keep open: [ShowOver] of the location itself,
  ///   with that flow. So a page of such a flow never stands alone when a
  ///   link asks for it: the router shows it over [start], and back leads
  ///   into the app. The request that waits is the page itself: asked
  ///   about again once the flow closes, it is answered with [start],
  ///   where the user is then. A flow that a gate keeps open too is the
  ///   gate's, and takes the place of the stack.
  ///
  /// For a guard with routes the class remembers no location, only over
  /// how many pages its flow was opened, for [changed]. So the answer
  /// depends on [onTopOf] and not on what the class answered before. Asked
  /// again about a location that it answered [ShowOver] for, with a page of
  /// the flow among [onTopOf], it answers [ShowNothing] for a location that
  /// the guard keeps the user from and `null` for a page of the flow. With
  /// no pages it answers [ShowOver] again, so a router never asks with none
  /// about a location that it shows over a page.
  ///
  /// What a gate made the class remember is forgotten when no gate keeps
  /// the user from the location and it is outside every flow, or in one
  /// that is over: the user has moved on, as when the code of the app
  /// navigates right when a gate starts allowing. Before that, it is
  /// forgotten if a guard that does not bring the user back stopped
  /// allowing, as [changed] says.
  WhenAsked<L>? asked(
    String? route,
    L location, {
    required Iterable<String?> onTopOf,
  }) {
    _forgetAfterStop();
    final guard = _guardKeepingFrom(route);
    if (guard != null && guard.routes == null) {
      if (!_inAFlow(route)) _remembered = (route: route, location: location);
      return ShowInstead(locationOf(guard.redirectTo));
    }
    final over = flowIsOver(route);
    if (over || !_inAFlow(route)) _remembered = null;
    if (over) return ShowInstead(start);
    if (guard == null) {
      final flow = onTopOf.isEmpty ? _openFlowOf(route) : null;
      if (flow == null) return null;
      _below = 0;
      return ShowOver(location, flow: flow);
    }
    if (onTopOf.any(guard.flow.contains)) return const ShowNothing();
    _below = onTopOf.length;
    return ShowOver(locationOf(guard.redirectTo), flow: guard.flow);
  }

  /// What the router does now that a guard started or stopped allowing, or
  /// `null` to leave its pages as they are. With `null` the router changes
  /// nothing: its pages stay, and so do the routes without a page that code
  /// pushed over them, such as a dialog or the screen that the action of an
  /// onboarding step shows.
  ///
  /// [pages] are the pages that the user can get back to, the one on top
  /// first: those of the root navigator and of the selected branch of the
  /// main navigation, each with the full name of its route, its location,
  /// and whether the router can close it on its own and leave the pages
  /// below it as they are. That holds for a page that `push()` showed, and
  /// for one that `replace()` showed in place of such a page. There are
  /// none for a router that has no page yet.
  ///
  /// First, the remembered location is forgotten if a guard that does not
  /// bring the user back (see [RouteGuard.resumes]) stopped allowing: it
  /// allowed when the class was last asked or told, and does not now. That
  /// holds whichever guard decides and whatever the pages are, and for
  /// whichever gate the location was remembered, so that the next user
  /// does not come to a location of the last one. A guard that stops and
  /// allows again without the class being asked or told in between is not
  /// seen to stop.
  ///
  /// The answer is then the first of these:
  /// - [ShowInstead] of the target of the gate that keeps the user from one
  ///   of the pages. If that gate brings the user back, the location below
  ///   the pages that the router can close is then remembered, or [start]
  ///   if it can close them all, unless one is remembered already or it is
  ///   in the flow of a guard.
  /// - with a location remembered: `null` while a gate keeps the user from
  ///   it. Otherwise the location is forgotten, and the answer is
  ///   [ShowInstead] of it, or of [start] if a guard with
  ///   [RouteGuard.routes] keeps the user from it: the class cannot keep a
  ///   request waiting, so the user moves on to [start].
  /// - for the lowest page that has to leave, which is in a flow that is
  ///   over (see [flowIsOver]) or which a guard with [RouteGuard.routes] keeps
  ///   the user from: [ClosePages] of that page and the pages over it, if the
  ///   router can close each of them and a page stays below; and else
  ///   [ShowInstead] of [start]. The request that waits is dropped when the
  ///   pages that close reach below the flow that [asked] opened last: the
  ///   page that the request was made on closes then, as when it asks for
  ///   a condition that stopped holding while the flow of another one was
  ///   open over it.
  ///
  /// So the pages of a flow close once its guards allow, also below a page
  /// that was pushed from them, and a page that asks for a condition
  /// closes when the condition stops holding. A page that took the place
  /// of the stack, as after `go()` to it, has nothing below it: the user
  /// then comes to [start].
  ///
  /// A known limit of the second answer: a location that a guard with
  /// [RouteGuard.routes] keeps the user from, and that was asked for
  /// behind a gate, is lost once the gate allows. A link to such a route
  /// that opens the app on a first launch, behind an onboarding, leaves
  /// the user on [start], though [asked] opens the flow of the guard over
  /// [start] for the same link when no gate is in its way.
  WhenChanged<L>? changed(
    Iterable<({String? route, L location, bool pushed})> pages,
  ) {
    _forgetAfterStop();
    final all = pages.toList();
    for (final page in all) {
      final gate = _guardKeepingFrom(page.route);
      if (gate == null || gate.routes != null) continue;
      final below = all.where((other) => !other.pushed).firstOrNull;
      if (gate.resumes && _remembered == null && !_inAFlow(below?.route)) {
        _remembered = (
          route: below?.route,
          location: below == null ? start : below.location,
        );
      }
      return ShowInstead(locationOf(gate.redirectTo));
    }
    if (_remembered case final remembered?) {
      final guard = _guardKeepingFrom(remembered.route);
      // The pages are those of the flow of the gate, which is not over.
      if (guard != null && guard.routes == null) return null;
      _remembered = null;
      return ShowInstead(guard == null ? remembered.location : start);
    }
    // No gate keeps the user from a page, so a guard that does is one with
    // routes.
    final lowest = all.lastIndexWhere(
      (page) => flowIsOver(page.route) || _guardKeepingFrom(page.route) != null,
    );
    if (lowest < 0) return null;
    final closed = lowest + 1;
    return all.take(closed).every((page) => page.pushed) && closed < all.length
        ? ClosePages(closed, dropsRequest: all.length - closed < _below)
        : ShowInstead(start);
  }

  /// Forgets the remembered location if a guard that does not bring the
  /// user back stopped allowing since the class last looked at the guards,
  /// and notes which of those guards allow now.
  void _forgetAfterStop() {
    for (final guard in routeGuards) {
      if (guard.resumes) continue;
      if (guard.allows.value) {
        _allowed.add(guard);
      } else if (_allowed.remove(guard)) {
        _remembered = null;
      }
    }
  }

  /// Whether [route] is in the flow of a guard, of whichever guard.
  static bool _inAFlow(String? route) =>
      routeGuards.any((guard) => guard.flow.contains(route));

  /// The flow that [route] is a page of and that only guards with
  /// [RouteGuard.routes] keep open: that of the first guard that does not
  /// allow and has the route in its flow; or `null` if there is none, or if
  /// a gate that does not allow has the route in its flow too, since the
  /// flow of a gate takes the place of the stack.
  static Set<String>? _openFlowOf(String? route) {
    Set<String>? flow;
    for (final guard in routeGuards) {
      if (guard.allows.value || !guard.flow.contains(route)) continue;
      if (guard.routes == null) return null;
      flow ??= guard.flow;
    }
    return flow;
  }
}

  /// location the app would start on the pushed page alone.

  /// [replace] give go_router their location as [go] does: it shows with
  /// the pages of its chain, in place of the error screen, and such a push
  /// completes with `null`. An error screen that a push showed over a page
  /// is a page of go_router, which pushes over it and replaces it like any
  /// other.
  ///
  /// The router asks the guards nothing itself then: the `redirect` of
  /// go_router asks, with no pages.
  bool get _withoutPage =>
      config.routerDelegate.currentConfiguration.matches.isEmpty;

  /// Runs [navigate], a call of go_router that is the router's own: with a
  /// location that it asked the guards about itself, or that they
  /// answered, or with pages that are shown already.
  R _own<R>(R Function() navigate) {
    _asking++;
    try {
      return navigate();
    } finally {
      _asking--;
    }
  }

  /// Runs [navigate], of which the listeners of the screen hear only the
  /// page that it ends on. That page is not there yet while the `redirect`
  /// of go_router has a target to open over `/`: they then hear of the
  /// target when [_redirect] opens it, and nothing of `/`.
  void _quietly(void Function() navigate) {
    final muted = _muted;
    _muted = true;
    try {
      navigate();
    } finally {
      _muted = muted || _opening != null;
      if (!_muted) _showScreen();
    }
  }

  /// What go_router goes to in place of [location] of [route], a location
  /// that it parses on its own: the one that the app starts on, those of
  /// the platform, and that of a branch of the main navigation that the
  /// user selects. Such a location takes the place of the stack, so the
  /// guards are told of no pages.
  ///
  /// For the flow of a guard that they open, go_router goes to the screen
  /// that the app starts on, and the router shows the target over it once
  /// the parse is over: go_router tells nobody of pages that it has
  /// already, as when the user is on that screen. The listeners of the
  /// screen hear only of the target. When the page on top is the target
  /// already, as for a second link to a page of the flow, the router puts
  /// that page back over `/` rather than push a new one: no frame shows the
  /// change, so the page stays as the user left it, and the listeners hear
  /// nothing.
  ///
  /// The push of the target is a call of the router's own, so the
  /// `redirect` is not asked about it. If it ever is, the guards answer by
  /// opening the target again, without end: the router throws rather than
  /// hang the app.
  String? _redirect(String? route, String location) {
    if (_asking > 0) return null;
    switch (_guards.asked(route, location, onTopOf: const [])) {
      case null || ShowNothing():
        return null;
      case ShowInstead(location: final shown):
        return shown;
      case ShowOver(location: final target, :final flow):
        _muted = true;
        final onTop = config.routerDelegate.currentConfiguration.lastOrNull;
        final kept =
            onTop is ImperativeRouteMatch && '${onTop.matches.uri}' == target
            ? onTop
            : null;
        void open() {
          if (_opening != open) return;
          _opening = null;
          _muted = false;
          _open(target, flow, again: () => config.go(location), kept: kept);
          if (_opening == null) return;
          _opening = null;
          throw StateError(
            'The redirect of go_router asked the guards about $target, '
            'which the router pushes itself, and would open it without '
            'end: it must ask nothing within a call of the router.',
          );
        }
        _opening = open;
        scheduleMicrotask(open);
        return _guards.start;
    }
  }

  /// Does what the guards answer for [location], which [go], [push] or
  /// [replace] is asked to show; `false` if they let the user see it.
  ///
  /// [again] makes the request again, and [drop] ends it without showing
  /// its location, as a push does that completes with `null`.
  ///
  /// go_router has a page of a route then; see [_withoutPage]. Without
  /// one, the `redirect` of go_router asks about the location, with no
  /// pages: the target of a guard that stands for a condition then opens
  /// over `/`, in place of the error screen too.
  bool _redirected(
    AppLocation location, {
    required void Function() again,
    void Function()? drop,
  }) {
    final answer = _guards.asked(
      location.routeName,
      location.path,
      onTopOf: [for (final page in _pages) page.route],
    );
    switch (answer) {
      case null:
        return false;
      case ShowInstead(location: final shown):
        _own(() => config.go(shown));
        drop?.call();
      case ShowNothing():
        drop?.call();
      case ShowOver(location: final target, :final flow):
        _open(target, flow, again: again, drop: drop);
    }
    return true;
  }

  /// Shows [target], the target of a guard, over the page on top, and keeps
  /// the request of [again] and [drop] waiting while a page of [flow] is
  /// among the pages: [_close] makes it again, and [_pagesChanged] drops
  /// it. A request that waited before is dropped. With [kept], the page of
  /// [target] that go_router had on top, the router puts that page over
  /// the page on top rather than push a new one.
  void _open(
    String target,
    Set<String> flow, {
    required void Function() again,
    void Function()? drop,
    ImperativeRouteMatch? kept,
  }) {
    _drop();
    _own(() {
      if (kept == null) return unawaited(config.push<Object?>(target));
      config.restore(config.routerDelegate.currentConfiguration.push(kept));
    });
    _waiting = (flow: flow, again: again, drop: drop);
  }

  /// Drops the request that waits, if there is one.
  void _drop() {
    final waiting = _waiting;
    _waiting = null;
    waiting?.drop?.call();
  }

  /// Closes the [count] pages on top, each of which a push showed. Then it
  /// drops the request that waits, with [dropsRequest], or else makes it
  /// again, if no page of its flow is left. The listeners of the screen
  /// hear of the page that the user ends on.
  ///
  /// The pages go out of the pages of go_router at once, with one
  /// `restore()` of its pages without them. `pop()` would close what the
  /// navigator shows on top, such as a dialog over the page, and it cannot
  /// close a page that a push of the same turn showed, which the navigator
  /// has not built yet.
  ///
  /// go_router does not complete the push of a page that leaves that way,
  /// so the router does, once the frame is over. Until its next build the
  /// navigator still has the routes of those pages. When one of them is
  /// popped in that time, by the code of its screen or by the back button
  /// of the system, go_router completes its push itself, and would throw
  /// on a push that is completed already.
  void _close(int count, {required bool dropsRequest}) {
    final waiting = _waiting;
    _waiting = null;
    _quietly(() {
      final shown = config.routerDelegate.currentConfiguration;
      final closing = _pushedPages(
        shown.matches,
      ).toList().reversed.take(count).toList();
      _own(() => config.restore(shown.remove(closing.last)));
      WidgetsBinding.instance.addPostFrameCallback((_) {
        for (final page in closing) {
          if (!page.completer.isCompleted) page.completer.complete();
        }
      });
      if (waiting == null) return;
      if (dropsRequest) {
        waiting.drop?.call();
      } else if (_shows(waiting.flow)) {
        _waiting = waiting;
      } else {
        waiting.again();
      }
    });
  }

  /// Whether a page of a route of [flow] is among the pages of the router.
  bool _shows(Set<String> flow) =>
      _pages.any((page) => flow.contains(page.route));

  /// The pages that the user can get back to, as the guards are told of
  /// them: those that pushes showed, the one on top first, each of which
  /// the router can close on its own, and, below them, the location that
  /// go_router went to last; none before go_router has a page. A page that
  /// [replace] showed over other pages is one that a push showed to
  /// go_router.
  List<({String? route, String location, bool pushed})> get _pages {
    final configuration = config.routerDelegate.currentConfiguration;
    if (configuration.isEmpty && !configuration.isError) return const [];
    final below = config.configuration.findMatch(configuration.uri);
    return [
      for (final page in _pushedPages(configuration.matches).toList().reversed)
        (route: page.route.name, location: '${page.matches.uri}', pushed: true),
      (
        route: below.lastOrNull?.route.name,
        location: '${configuration.uri}',
        pushed: false,
      ),
    ];
  }

  /// Tells the guards of the pages of the router when one of them starts
  /// or stops allowing, and does what they answer: goes to a location,
  /// which is the target of the gate that keeps the user from one of the
  /// pages, the location that the user comes back to once the gates allow
  /// it, or `/`; or closes the pages on top, those of a flow that is over
  /// or of routes whose condition stopped holding.
  ///
  /// The router listens to the guards itself rather than through the
  /// `refreshListenable` of go_router, whose refresh asks only about the
  /// location below the pushed pages. Before its first location, it has no
  /// page to tell the guards of, and no stack that an answer of theirs
  /// could take the place of: go_router asks them about that location when
  /// it shows it.
  void _guardsChanged() {
    final pages = _pages;
    if (pages.isEmpty) return;
    switch (_guards.changed(pages)) {
      case null:
        break;
      case ShowInstead(:final location):
        _own(() => config.go(location));
      case ClosePages(pages: final count, :final dropsRequest):
        _close(count, dropsRequest: dropsRequest);
    }
  }

  /// Follows the pages of go_router, whose delegate notifies its listeners
  /// of each change of them: keeps each push completing with the value of
  /// its page, and tells the listeners of the screen about the page on top.
  /// And it drops the request that waits for a flow once no page of the
  /// flow is among the pages, as when the user went back from it or another
  /// location took the place of the stack.
  void _pagesChanged() {
    _keepPushes();
    if (_waiting case final waiting? when !_shows(waiting.flow)) _drop();
    if (_muted) return;
    _showScreen();
  }

  /// Lets each push complete with the value that its page returns when it
  /// closes, whatever completer go_router gives the page.
  ///
  /// go_router completes a push with the completer that it gives the page
  /// it pushed, which the page completes when it closes. When go_router
  /// shows its pages anew from their encoded form, as on [GoRouter.refresh],
  /// such as when its `refreshListenable` notifies, it gives each pushed
  /// page a new completer, though the page keeps its key and its location,
  /// so the push would never complete
  /// (https://github.com/flutter/flutter/issues/128122). So when a page
  /// comes back at its location with another completer, the router passes
  /// on the value of that completer to that of the push. A branch of the
  /// main navigation that is not selected keeps its pages as they were, so
  /// a page that comes back with its branch passes on its value as before.
  /// Once go_router keeps the completers of its pages, this does nothing
  /// and can go.
  void _keepPushes() {
    final pushed = {
      for (final page in _pushedPages(
        config.routerDelegate.currentConfiguration.matches,
      ))
        page.pageKey: page,
    };
    for (final page in pushed.values) {
      final before = _pushed[page.pageKey];
      if (before == null ||
          before.completer == page.completer ||
          before.matches.uri != page.matches.uri) {
        continue;
      }
      final push = _pushes[before.completer] ?? before.completer;
      _pushes[page.completer] = push;
      unawaited(
        page.completer.future.then((value) {
          if (!push.isCompleted) push.complete(value);
        }),
      );
    }
    _pushed = pushed;
  }

  /// The pages that pushes showed among [matches], in the stacks of the
  /// main navigation too.
  static Iterable<ImperativeRouteMatch> _pushedPages(
    List<RouteMatchBase> matches,
  ) sync* {
    for (final match in matches) {
      if (match is ImperativeRouteMatch) yield match;
      if (match is ShellRouteMatch) yield* _pushedPages(match.matches);
    }
  }

  /// Tells the listeners of the screen about the page on top when another
  /// page comes on top, or the page on top shows another location.
  ///
  /// The delegate of go_router notifies its listeners once for each change
  /// of its configuration, a switch of branches included, and may do so
  /// again without a change of the page on top, which the listeners of the
  /// screen do not hear of twice. The location of a pushed page is its own,
  /// as that of the configuration leaves pushed pages out. The error screen
  /// of go_router has no route match, or, for a location pushed in error, a
  /// route without a name.
  void _showScreen() {
    final configuration = config.routerDelegate.currentConfiguration;
    final top = configuration.lastOrNull;
    final location = switch (top) {
      ImperativeRouteMatch(:final matches) => matches.uri.toString(),
      _ => configuration.uri.toString(),
    };
    final screen = (top?.pageKey, location);
    if (screen == _screen) return;
    _screen = screen;
    for (final listener in _screenListeners) {
      _callAlone(listener, top?.route.name, location);
    }
  }
}

/// Creates the observers of a navigator. An observer can watch only one

/// The listeners of the screen the user sees, which get the full name of

final List<void Function(String? route, String location)> _screenListeners = [];

/// Calls [listener] of the screen with [route] and [location] on its own:
/// what it throws keeps no other listener from hearing the screen, and
/// reaches neither the router nor the handlers of the errors of the app. In
/// debug mode it is printed, so that a listener that fails shows in the

void _callAlone(

  String? route,
  String location,

    listener(route, location);
  } on Object catch (error) {

      debugPrint('A listener of the screen failed: $error');

  }

/// go_router shows its error screen in place of the whole stack, for a

/// it then has no page of a route. Asked to close the route on top, its
/// delegate looks for the last of those pages and throws a [StateError]
/// (https://github.com/flutter/flutter/issues/187616). So on that screen
/// the dispatcher asks the root navigator, the only one there, itself: a
/// route that is shown over the error screen, such as a dialog, closes, and
/// with no route to close the button is left to the system, as on the

final class _BackButton extends RootBackButtonDispatcher {

  /// For each callback that the dispatcher was given, the one that it
  /// calls in its place.
  final Map<ValueGetter<Future<bool>>, ValueGetter<Future<bool>>> _asked = {};

  /// Takes [callback], with which the `Router` of Flutter asks the delegate
  /// of go_router to close the route on top, and calls it only while
  /// go_router has a page. A `BackButtonListener` below the router still
  /// hears of the button first, on the error screen too.
  @override
  void addCallback(ValueGetter<Future<bool>> callback) => super.addCallback(
    _asked[callback] = () {
      final delegate = _router.routerDelegate;
      if (delegate.currentConfiguration.matches.isNotEmpty) return callback();
      return delegate.navigatorKey.currentState?.maybePop() ??
          Future.value(false);
    },
  );

  @override
  void removeCallback(ValueGetter<Future<bool>> callback) =>
      super.removeCallback(_asked.remove(callback) ?? callback);
}

/// at its top right, which [_UnlockCell] is: outlines, some of which light

  _TablePainter(this.animation) : super(repaint: animation);

  final Animation<double> animation;

  /// The cells that light up, by column from the right and row from the
  /// top, each with its colour and the order in which it lights up.
  static const _lit = <(int, int, Color, int)>[
    (2, 1, Color(0x33F1F1E8), 0),
    (1, 2, Color(0x664ADE80), 1),
    (3, 0, Color(0x1FF1F1E8), 2),
    (1, 1, Color(0x994ADE80), 3),
    (0, 1, Color(0x33F1F1E8), 4),
  ];

  @override
  void paint(Canvas canvas, Size size) {
    final outline = Paint()
      ..style = PaintingStyle.stroke
      ..strokeWidth = 1;
    for (var column = 0; column < 4; column++) {
      for (var row = 0; row < 3; row++) {
        // The cell at the top right is the cell that unlocks.
        if (column == 0 && row == 0) continue;
        final rect = Rect.fromLTWH(
          size.width -
              _tableInset -
              _tableCell -
              column * (_tableCell + _tableGap),
          _tableInset + row * (_tableCell + _tableGap),
          _tableCell,
          _tableCell,
        );
        // A narrow card has no room for every column: it leaves out those
        // that would reach the cell of the app on its left.
        if (rect.left < _cardPadding + _cellSide + _tableGap) continue;
        // The outlines fade towards the cell of the app.
        outline.color = _brandCream.withValues(alpha: 0.14 - column * 0.03);
        canvas.drawRect(rect, outline);
        for (final (litColumn, litRow, color, order) in _lit) {
          if (litColumn != column || litRow != row) continue;

          final shown = Interval(
            start,
            (start + 0.25).clamp(0, 1),
            curve: Curves.easeOut,
          ).transform(animation.value);
          canvas.drawRect(
            rect,
            Paint()..color = color.withValues(alpha: color.a * shown),
          );
        }
      }
    }
  }

  @override
  bool shouldRepaint(_TablePainter oldDelegate) =>

/// The state of the paywall: it loads the plans of the current offer, buys
/// the selected plan and restores purchases through the purchases of the
/// app, and tells which call is on its way and what the last one ended
/// with.
class PaywallCubit extends Cubit<PaywallState> {
  /// Creates the cubit that buys through [_purchases] and opens a link with
  /// [_openLink], and loads the plans.
  PaywallCubit(this._purchases, this._openLink) : super(const PaywallState()) {
    _purchases.hasPremium.addListener(_follow);
    unawaited(load());
  }

  final AppPurchasesController _purchases;
  final Future<void> Function(Uri url) _openLink;

  /// Whether a purchase or a restore of this cubit is on its way.
  var _calling = false;

  /// Loads the plans of the current offer, and selects the plan that the
  /// paywall selects first.
  Future<void> load() async {
    if (state.busy != null) return;
    emit(const PaywallState());
    try {
      final plans = await _purchases.plans();
      if (!isClosed) {
        emit(PaywallState(plans: plans, selected: preselectedPlan(plans)));
      }
    } on PurchasesFailure catch (failure) {
      if (!isClosed) emit(PaywallState(loadFailure: failure));
    }
  }

  /// Selects [plan], unless a call is on its way.
  void select(Plan plan) {
    if (state.busy != null) return;
    emit(state.selecting(plan));
  }

  /// Buys the selected plan.
  ///
  /// Once the user has premium access, the router closes the paywall, so
  /// the state stays busy for as long as the user has it. When the user
  /// cancels, the state is again as it was, and a payment that waits for an
  /// approval tells the user so.
  Future<void> purchase() async {
    final plan = state.selected;
    if (plan == null) return;
    await _run(PaywallAction.purchase, () => _purchases.purchase(plan));
  }

  /// Restores what the store account of the user bought.
  ///
  /// Once the user has premium access, the router closes the paywall, so
  /// the state stays busy for as long as the user has it. A restore that
  /// finds nothing tells the user so.
  Future<void> restore() => _run(
    PaywallAction.restore,
    () async => await _purchases.restore() is PremiumAccess,
    otherwise: PaywallNotice.nothingToRestore,
  );

  /// Opens [url], a link of the paywall.
  Future<void> openLink(Uri url) => _openLink(url);

  /// Makes [call], the call of [action], unless a call is on its way or the
  /// plans load. [call] returns whether the user has premium access then,
  /// and the state stays busy if so. Otherwise it is idle again, with the
  /// notice [otherwise], if any.
  Future<void> _run(
    PaywallAction action,
    Future<bool> Function() call, {
    PaywallNotice? otherwise,
  }) async {
    if (state.busy != null || state.loading) return;
    _calling = true;
    emit(state.busyWith(action));
    final bool premium;
    try {
      premium = await call();
    } on PurchasesFailure catch (failure) {
      _calling = false;
      // The user may have left the paywall while the call was on its way.
      if (isClosed) return;
      emit(
        failure.reason == PurchasesFailureReason.pending
            ? state.idle(notice: PaywallNotice.pending)
            : state.idle(failure: failure),
      );
      return;
    }
    _calling = false;
    if (isClosed) return;
    if (premium) {
      _follow();
    } else {
      emit(state.idle(notice: otherwise));
    }
  }

  /// Ends the busy state that a call left once the user has no premium
  /// access: the access ended again before the router took the paywall
  /// away, and the paywall is back.
  void _follow() {
    if (_calling || isClosed || state.busy == null) return;
    if (!_purchases.hasPremium.value) emit(state.idle());
  }

  @override
  Future<void> close() {
    _purchases.hasPremium.removeListener(_follow);
    return super.close();
  }
}

/// The state of the paywall: the plans of the current offer, or why they
/// did not load, the plan that the user selected, which call is on its way,
/// and what the last call ended with.
@immutable
final class PaywallState {
  /// Creates the state, which is loading the plans without [plans] and
  /// [loadFailure].
  const PaywallState({
    this.plans,
    this.loadFailure,
    this.selected,
    this.busy,
    this.failure,
    this.notice,
  });

  /// The plans of the current offer, in the order of the provider of
  /// purchases, or `null` while they load or when they did not.
  final List<Plan>? plans;

  /// Why the plans did not load, or `null`.
  final PurchasesFailure? loadFailure;

  /// The plan that the button of the paywall buys, or `null` while there
  /// are no plans.
  final Plan? selected;

  /// The call that is on its way, or `null` when none is. While it is, the
  /// paywall takes no other call.
  ///
  /// It stays so after a purchase or a restore that gave the user premium
  /// access, for as long as the user has it: what comes next is up to the
  /// router, which closes the paywall. The paywall neither closes itself
  /// nor navigates. When the access ends before the router took the
  /// paywall away, the paywall is idle again.
  ///
  /// While the plans load, the paywall takes no call, so that no plan comes
  /// in to be bought while a restore is on its way.
  final PaywallAction? busy;

  /// Why the last call failed, or `null` if it did not.
  final PurchasesFailure? failure;

  /// What the last call that did not fail tells the user, or `null`.
  final PaywallNotice? notice;

  /// Whether the plans are loading.
  bool get loading => plans == null && loadFailure == null;

  /// The state with [plan] selected, with nothing on its way and nothing to
  /// tell.
  PaywallState selecting(Plan plan) =>
      PaywallState(plans: plans, loadFailure: loadFailure, selected: plan);

  /// The state while [action] is on its way. The plans, or why they did not

    loadFailure: loadFailure,

  );

        loadFailure: loadFailure,

        failure: failure,
        notice: notice,

/// first that renews every year, or else the first plan.
Plan? preselectedPlan(List<Plan> plans) {

    if (_yearly(plan)) return plan;

/// Whether [plan] is the best value of [plans]: a plan that renews every
/// year and costs less than twelve times a plan of [plans] that renews
/// every month, in the same currency.
///
/// The paywall says so on the plan, and never shows a yearly plan by what
/// it costs a month, which Google Play does not allow.
bool isBestValue(Plan plan, List<Plan> plans) {
  if (!_yearly(plan)) return false;
  for (final other in plans) {
    final monthly = switch (other.period) {
      final period? => termOf(period) == PlanTerm.month,
      null => false,
    };
    if (monthly &&
        other.currencyCode == plan.currencyCode &&
        plan.amount < other.amount * 12) {
      return true;
    }
  }
  return false;
}

/// Whether [plan] renews every year.
bool _yearly(Plan plan) => switch (plan.period) {
  final period? => termOf(period) == PlanTerm.year,
  null => false,
};

    null => null,
  };

  if (length == null || (offer.cycles > 1 && suffix == null)) {
    return 'Introductory price';
  }
  return [offer.price, ?suffix, 'for', length].join(' ');
}

/// The font of a key of `.env` and of a hint for the developer: the

const monospace = TextStyle(
  fontFamily: 'monospace',
  fontFamilyFallback: ['Menlo', 'Courier'],
);

/// The white space at which a line of text may break: every white space but
/// the no-break spaces.
final RegExp _breaks = RegExp(r'[^\S\u00A0\u2007\u202F]+');

/// A text that keeps its words whole: it breaks between its words and never
/// inside one.
///
/// A word is what stands between two spaces at which a line may break, such
/// as a space, a tab or a line break. A no-break space keeps the words on
/// each side of it together, as in a price that the store gives.
///
/// It grows with the text size of the device, by [maxScaleFactor] at most.
/// Where its longest word would still not fit the width that the text has,
/// as on a narrow phone with a large text size, the text is as large as
/// that word allows.
class PaywallWords extends StatelessWidget {
  /// Creates the text.
  const PaywallWords(
    this.text, {
    this.style,
    this.textAlign,
    this.maxScaleFactor = double.infinity,
    super.key,
  });

  /// The text.
  final String text;

  /// The style of the text, over that of the text around it. With none,
  /// the text is as the text around it, as the label of a button is in the
  /// style that the theme of the app gives the button.
  final TextStyle? style;

  /// How the lines of the text are aligned.
  final TextAlign? textAlign;

  /// By how much the text grows at most with the text size of the device.
  final double maxScaleFactor;

  @override
  Widget build(BuildContext context) {
    // The style in which a Text paints: over that of the text around it,
    // and bold for a user who asks for bold text.
    var style = DefaultTextStyle.of(context).style.merge(this.style);
    if (MediaQuery.boldTextOf(context)) {
      style = style.merge(const TextStyle(fontWeight: FontWeight.bold));
    }
    final scaler = MediaQuery.textScalerOf(
      context,
    ).clamp(maxScaleFactor: maxScaleFactor);
    return LayoutBuilder(
      builder: (context, constraints) {
        final room = constraints.maxWidth;
        final painter = TextPainter(
          textDirection: Directionality.of(context),
          textScaler: scaler,
          maxLines: 1,
        );
        // How wide the longest word is in a font of [size].
        double widestAt(double size) {
          var widest = 0.0;
          for (final word in text.split(_breaks)) {
            painter
              ..text = TextSpan(
                text: word,
                style: style.copyWith(fontSize: size),
              )
              ..layout();
            if (painter.width > widest) widest = painter.width;
          }
          return widest;
        }

        // The size of a text of Flutter whose style gives none.
        var size = style.fontSize ?? 14;
        var widest = widestAt(size);
        // In a few steps: the text size of a device may grow a small font
        // by more than a large one.
        for (var step = 0; step < 4 && widest > room && room > 0; step++) {
          // A little smaller than the width allows, so that the rounding of
          // the layout breaks no word.
          size *= room / widest * 0.98;
          widest = widestAt(size);
        }
        painter.dispose();
        return Text(
          text,
          style: style.copyWith(fontSize: size),
          textAlign: textAlign,
          textScaler: scaler,
        );
      },
    );
  }
}

/// Lets [child] fade in and rise while [animation] runs, later for a higher
/// [order].
class Rise extends StatelessWidget {
  /// Creates the part [order] of an entrance.
  const Rise({
    required this.animation,
    required this.order,
    required this.child,
    super.key,
  });

  /// The entrance, from 0 to 1.
  final Animation<double> animation;

  /// The place of [child] in the entrance: a part of a higher order comes
  /// in later.
  final int order;

  /// What comes in.
  final Widget child;

  @override
  Widget build(BuildContext context) {
    final start = (order * 0.08).clamp(0.0, 0.5);
    final curve = Interval(
      start,
      start + 0.5,
      curve: Easing.emphasizedDecelerate,
    );
    return AnimatedBuilder(
      animation: animation,
      builder: (context, child) {
        final shown = curve.transform(animation.value);
        return Opacity(
          opacity: shown,
          child: Transform.translate(
            offset: Offset(0, (1 - shown) * 18),
            child: child,
          ),
        );
      },
      child: child,
    );
  }
}

/// The plan of [access] and when it renews or ends, or that it is for
/// good, one below the other on a card, with a line between them.
class _Details extends StatelessWidget {
  const _Details({required this.access});

  final PremiumAccess access;

  @override
  Widget build(BuildContext context) {
    final period = access.period;
    final plan = period == null ? null : termNameOf(context, period);
    final expiresAt = access.expiresAt;
    final rows = [
      if (plan != null)
        _Row(
          icon: Icons.workspace_premium_outlined,
          label: 'Plan',
          value: plan,
        ),
      if (expiresAt == null)
        _Row(icon: Icons.all_inclusive_rounded, label: 'Lifetime access')
      else
        _Row(
          icon: access.inTrial
              ? Icons.hourglass_bottom_rounded
              : access.renews
              ? Icons.autorenew_rounded
              : Icons.event_busy_outlined,
          label: access.inTrial
              ? 'Trial ends on'
              : access.renews
              ? 'Renews on'
              : 'Ends on',
          value: MaterialLocalizations.of(
            context,
          ).formatShortDate(expiresAt.toLocal()),
        ),
    ];
    return Card(
      clipBehavior: Clip.antiAlias,
      child: Column(
        crossAxisAlignment: CrossAxisAlignment.stretch,
        children: [
          for (final (index, row) in rows.indexed) ...[
            if (index > 0) const Divider(height: 1, indent: 56),
            row,
          ],
        ],
      ),
    );
  }
}

/// A row of the card of the subscription: its [icon], its [label] and its
/// [value], if it has one. A screen reader reads it as one line.
class _Row extends StatelessWidget {
  const _Row({required this.icon, required this.label, this.value});

  final IconData icon;
  final String label;
  final String? value;

  @override
  Widget build(BuildContext context) {
    final theme = Theme.of(context);
    final value = this.value;
    return MergeSemantics(
      child: ListTile(
        leading: Icon(icon),
        title: Text(label),
        // Below the label, where a long value has the width of the row.
        subtitle: value == null
            ? null
            : Text(
                value,
                style: theme.textTheme.bodyLarge?.copyWith(
                  fontWeight: FontWeight.w600,
                  color: theme.colorScheme.onSurface,
                ),
              ),
      ),
    );
  }
}
