# AGENTS.md

This guide tells coding agents what the code of this Flutter app does not show. Setup that needs a person or an account is in [README.md](README.md). When you change what a section describes, change the section too.

## App entry

The app is plain Flutter code that nothing regenerates. Change it by hand, unless a section below says what writes a file.

- `main()` in `lib/main.dart` initializes the binding, awaits `bootstrap()` and calls `runApp()`, in this order. When `bootstrap()` throws, `main()` calls `showFailedStart()` of `lib/core/app/failed_start.dart` and returns: the app shows `FailedStartApp`, with the error in a debug build, and the error reaches `FlutterError.onError`. Keep the `try` around `await bootstrap()` in `main()`. Start-up code goes into `bootstrap()`. Do not catch an error there just to let the app start: fix what the error names, such as a step of the setup that has not run.
- `bootstrap()` in `lib/bootstrap.dart` runs before the first frame, in four phases: what must come before anything else, then the platform services, then the services of the app, then what needs them. Put a new statement into its phase, and import neither `package:flutter/material.dart` nor `package:flutter/cupertino.dart` there.
- Put code that features share into `lib/core/<concern>/`, one directory for each concern. Put a feature, with its screens and their state, into `lib/features/<feature>/`.
- The root of the app asks the system for the icons of the status bar that suit the theme, around every screen, with `StatusBarIcons` of `lib/core/app/status_bar_icons.dart`: dark icons on a light theme, light ones on a dark theme. A screen without an app bar needs no `AnnotatedRegion` for them. Add one only to a screen whose top has another brightness than the theme, such as a picture behind the status bar.
- The app has the flavors `dev`, `staging` and `prod`. A `flutter` command without `--flavor` builds `dev`, in release mode too, so a build for a store takes `--flavor prod`. Code reads the flavor from `appFlavor` of `package:flutter/services.dart`. The app has one entry: add no `main_<flavor>.dart`.

- The section "Finish the setup" of the README lists the steps of the setup that no command can do, such as a step in the web console of a service that the app uses. Only the developer of the app does them: when a task depends on one of them, point the developer to that section, and do not try to do the step yourself.

After a change, run:

```bash
dart format lib test
flutter analyze
flutter test
```

Format only `lib/` and `test/`: `dart format .` also formats what Flutter writes into `build/`. The app as generated is formatted, `flutter analyze` finds no issue in it and `flutter test` passes.

- `App` in `lib/app.dart` is the root widget of the app and creates its one `MaterialApp`. Every screen is below it, so create no other `MaterialApp` in `lib/`. The only other one is in `FailedStartApp`, which `main()` runs in its place when the start-up fails.
- The `theme`, `darkTheme`, `themeMode`, `locale` and localizations of the app go into the arguments of that `MaterialApp`.
- Tests mirror `lib/`: the test of `lib/<path>.dart` is `test/<path>_test.dart`.
- The app has only an Android and an iOS project, in `android/` and `ios/`.
- The entitlements of the iOS app, such as Push Notifications or Sign in with Apple, are in `ios/Runner/Runner.entitlements`. Every build configuration of the Runner target signs with this file, even while it is empty. The Signing & Capabilities tab of Xcode edits the same file.
- Each flavor is in `productFlavors` of `android/app/build.gradle.kts`, and on iOS in `ios/Runner.xcodeproj/xcshareddata/xcschemes/<flavor>.xcscheme` and in the build configurations `Debug-<flavor>`, `Profile-<flavor>` and `Release-<flavor>` of `ios/Runner.xcodeproj/project.pbxproj`. Change both places together. A new setting of the Runner target goes into each of its twelve build configurations.

## Feedback

- `appFeedback` in `lib/core/feedback/app_feedback.dart` lets a user write to the developer: call `appFeedback.open(context)` from a button, with a `BuildContext` below the root of the app. It opens the way of the provider, such as the mail app with a new mail, a form or a survey. It completes with `true` once that opened, without waiting for the user, or with `false`. It never throws, and a call while another is on its way does nothing.
- `appFeedback.available` tells whether the provider has what it needs, and does not change while the app runs: hide your own button while it is `false`.
- Never ask anything before or around the review dialog of a store, and never make a way to write depend on whether the user rated the app.
- A new provider implements `FeedbackService` of `lib/core/feedback/feedback_service.dart`, and only the files of its implementation import it. The code of the app calls neither `createFeedbackService()` nor `appFeedback.use()`, which is for tests.

With `url_launcher`:

- `EmailFeedbackService` in `lib/core/feedback/email_feedback_service.dart` implements `FeedbackService` of `lib/core/feedback/feedback_service.dart`: it opens a new mail to `EMAIL_FEEDBACK_ADDRESS` of `.env` with `launchUrl` and a `mailto:` link from `emailFeedbackLink()` of `lib/core/feedback/email_feedback_mail.dart`, with the version of the app from `PackageInfo.fromPlatform()` and the device from `DeviceInfoPlugin()`.
- Build such a link with `Uri.encodeComponent`, never with `Uri(queryParameters: ...)`, which writes a space as `+`.
- Never call `canLaunchUrl` first: Android 11 and later answer false without `<queries>` in the manifest, which the app does not have.
- Where no mail app opens the mail, `showEmailFeedbackSheet()` of `lib/core/feedback/email_feedback_sheet.dart` shows the address to copy.

## Localization

- Show the user no text but the name of the app from a string literal. Read each text as `context.l10n.<name>`, with `lib/core/l10n/l10n.dart` imported, where `context` is a `BuildContext` below the root of the app. Such an expression is no constant, so the widget around it cannot be `const`.
- `lib/core/l10n/app_locale.dart` has `appLocales`, the languages of the app, and `appLocale`, the one that the user chose. Change the language only with `appLocale.choose(locale)`, which also saves the choice in the preferences, and write nothing under the key `localization.locale` yourself. The root `MaterialApp` gets its `locale` and its `supportedLocales` from that file: leave both as they are.
- Every delegate among the `localizationsDelegates` of the root has to support each language of `appLocales`. A new language, one in which Flutter has the texts of its own widgets, goes into `appLocales`, into `CFBundleLocalizations` in the Info.plist of the iOS app, and into the texts of the app.

With `gen-l10n` of Flutter:

- The texts of the app are in the ARB files of `lib/l10n`. `lib/l10n/app_en.arb` has every text in English, and `lib/l10n/app_<code>.arb` the translations into another language. A text that such a file lacks reads in English there.
- To add a text, add it to `lib/l10n/app_en.arb` under a name in lowerCamelCase, and its translations under the same name to the other files.
- After every change of the ARB files, a new file included, run `flutter gen-l10n`, which generates `context.l10n.<name>`. Do not edit `lib/l10n/app_localizations*.dart`: `gen-l10n` writes those files from the ARB files, as `l10n.yaml` says.
- Write an apostrophe in a text once: `l10n.yaml` turns the escapes of `gen-l10n` off (`use-escaping: false`).

## Preferences

- `AppPreferences` in `lib/core/preferences/app_preferences.dart` remembers the settings of the app between its launches, such as the theme mode. It is not encrypted: never save a token, a password, an API key or an encryption key in it.
- To remember a setting, write a function that takes the `AppPreferences` and add it to `_restorers` in that file. In it, read the setting, put it into the state that the widgets listen to, and keep the preferences in that state for its writes. The function awaits nothing, and keeps the current value when nothing is saved.
- Name a key `<owner id>.<setting>`, such as `theme.mode`, where the owner is the feature or the concern whose code keeps the setting.
- In the code of the app, do not call `createAppPreferences()` or `initPreferences()`. `bootstrap()` opens the preferences, and code gets them as the argument of its function in `_restorers`, or, with a DI container in the app, from the container. Widgets use the state and do not touch the preferences. A test may call both: `initPreferences()` opens the preferences again, as the next launch of the app does, and `createAppPreferences()` returns them.

With `shared_preferences`:

- In `lib/`, only `lib/core/preferences/shared_app_preferences.dart` imports the package. Other code uses `AppPreferences`.
- A number is read only as the type that it was saved as: `getDouble()` returns `null` for a key with an `int`, and `getInt()` for a key with a `double`.
- In a test that runs `bootstrap()`, first set `SharedPreferencesAsyncPlatform.instance = InMemorySharedPreferencesAsync.empty()`. Without it, opening the preferences throws. Both names are from the package `shared_preferences_platform_interface`: add it as a dev dependency.
- `pubspec.yaml` keeps `shared_preferences_android` at 2.5.2 or later. With 2.5.0 and 2.5.1, a release build fails to open the preferences on Android, because R8 renames Kotlin classes that the package looks up by name. Before you change the constraint, check that a release build of the app starts on Android.

## Values in .env

- Read a value of `.env` only through a static getter of `AppEnv` in `lib/core/env/app_env.dart`. The getter is the key in lowerCamelCase: `AppEnv.myServiceKey` for the key `MY_SERVICE_KEY`. It returns a `String?` that is `null` while the value is empty or missing, so handle `null`. Never read `.env` or `.env.example` from code.
- Every value ends up in the app, where anyone can read it. Never put a secret into `.env`, such as the secret key of a server, a password or a private key.
- `.env` stays out of git. A new key goes into both `.env.example` and `.env`, in UPPER_SNAKE_CASE with a comment line above it, and `AppEnv` gets a getter for it.
- A release build of an app with keys stops with an error unless its command gives the app the values of `.env`; the note of the provider names the arguments. Never remove or work around the check in `lib/core/env/env_check.dart`, which `bootstrap()` calls in its first phase: give the build the arguments. `AppEnv.supplied` tells whether a build has the values.
- `.vscode/launch.json` and `.run/<flavor>.run.xml` are the run configurations of VS Code and Android Studio, one for each flavor. Each passes the flavor and the arguments that the values need. In VS Code, F5 starts the selected configuration, while the links above `main()` and above a test and the Testing view always use `dev`, whose configuration alone has `templateFor`. In Android Studio, a test gets none of these arguments.

With `--dart-define-from-file`:

- Every command of the `flutter` tool that builds, runs or tests the app takes `--dart-define-from-file=.env`, such as `flutter run --dart-define-from-file=.env`, `flutter test` and `flutter build`. Without it, every getter of `AppEnv` is `null`, and a release build stops with an error.
- A command reads `.env` only when it starts. After a change of `.env`, stop `flutter run` and start it again: hot reload and hot restart keep the values that the app was built with.
- The getter of a new key in `lib/core/env/app_env.dart` reads `const String.fromEnvironment('MY_SERVICE_KEY')`, with the key in place of `MY_SERVICE_KEY`, and returns `null` for an empty value, as the other getters do.
- `AppEnv.supplied` is `true` once `--dart-define-from-file=.env` declared one of the keys that it names, so a new key needs no change there. An app without keys has `true` there: with its first key, make it `bool.hasEnvironment('MY_SERVICE_KEY')` with that key.

## Feedback by email

"Write to us" opens a new mail to you in the mail app of the device, with [url_launcher](https://pub.dev/packages/url_launcher): `lib/core/feedback/email_feedback_service.dart` implements the feedback of the app on it, as the section "Feedback" tells. The texts of the mail and of the sheet are texts of the module, in the files of the languages of the app.

To see the mail, run the app on an iPhone, or on an Android device or emulator with a mail app and an account in it, such as Gmail, and tap "Write to us".

What the mail tells about the app and the device is read on the device, and leaves it only in a mail that the user sends from their own mail app: the app itself sends nothing.

## Feedback

`appFeedback` in `lib/core/feedback/app_feedback.dart` lets the users of the app write to you. Call `appFeedback.open(context)` from a button, with a `BuildContext` below the root of the app:

```dart
TextButton(
  onPressed: () => appFeedback.open(context),
  child: const Text('Write to us'),
)
```

It opens the way to write of the provider of feedback, such as a new mail in the mail app, a form or a survey, and completes with `true` once that way opened, without waiting for the user to send anything. It completes with `false` when the way could not open, after the provider showed the user another way to reach you if it has one, such as the address to copy. It never throws: an error of the provider goes to the handler of the errors of Flutter, such as that of a crash reporter, and counts as `false`. A call while another is on its way does nothing and completes with `false`.

`appFeedback.available` tells whether the provider has what it needs, such as your address, and does not change while the app runs. While it is `false`, `open` does nothing, so hide a button of your own then.

This app has no settings screen, so call it from a button of your own, such as on a screen of help.

Each provider adds to what reaches you the name, the version, the build number and the flavor of the app and its platform, so that you know what the user ran. The section of the provider tells what it sends and how.

The way to write is there whatever the user did with the review dialog of a store. Google Play forbids any question before or around that dialog, so never send the happy users to the store and the unhappy ones here.

A way to write inside the app does not replace the Support URL that App Store Connect asks of every app, a page where its users reach you (App Store Review Guideline 1.5).

What a user writes leaves the device through the provider. A provider that sends it through a service of its own, such as a form, collects data: declare it in App Privacy and in Data safety, as the section of the provider says what it sends. Both stores also require a link to a privacy policy in the listing of the app and inside the app.

## Languages

The app is in the languages of `appLocales` in `lib/core/l10n/app_locale.dart`. It shows its texts in the language that the device prefers among them, and in the first of the list when the device asks for none of them. `appLocale.choose()` puts the app into another of its languages, whatever the device prefers, and the app remembers that choice between its launches. `appLocale.choose(null)` follows the device again.

To add a language in which Flutter has the texts of its own widgets, such as German, add the texts of the app in German, and then:

1. Add `Locale('de')` to `appLocales`, one locale for each language, since the app tells its languages apart by their codes.
2. Add `de` to `CFBundleLocalizations` in `ios/Runner/Info.plist`, which tells iOS the languages of the app.

/// The name of the app in the mail that a user writes to its developer: in
/// the subject, such as "Feedback: My App", and in the line about the app.
/// Change it here if you rename the app.
///
/// Unlike the name that the device shows, it is the same in every flavor,
/// so a filter of your mail finds every such mail by its subject.
const String emailFeedbackAppName = 'My App';

/// The flavor for a release, which users install from a store: the mail
/// names any other flavor, and not this one.
const String _releaseFlavor = 'prod';

/// What an email address may not have: a white space, and what a `mailto:`
/// link or a list of addresses would take apart.
const String _notInAddress = r'\s@?&#,;<>"()\\/:\[\]';

/// One email address, such as `support@example.com`: a name, an `@` and a
/// domain with a dot.
final RegExp _address = RegExp(
  '^[^$_notInAddress]+@[^$_notInAddress.]+(?:\\.[^$_notInAddress.]+)+\$',
);

/// Whether [value], without the spaces around it, is one email address,
/// such as `support@example.com`. Any other value, such as an empty one,
/// two addresses or an address with a query, counts as none.
bool isEmailFeedbackAddress(String? value) =>
    value != null && _address.hasMatch(value.trim());

/// The `mailto:` link of a new mail to [address], with [subject] and
/// [body], which the mail app of the device opens.
///
/// Each part is encoded as RFC 6068 asks: a space is `%20` and never `+`,
/// which a mail app would show as a plus, a line break is `%0D%0A`, and a
/// `+` of the address is `%2B`, which keeps the `@` as it is. So build such
/// a link here, and never with `Uri(queryParameters: ...)`, which writes a
/// space as `+`.
Uri emailFeedbackLink({
  required String address,
  required String subject,
  required String body,
}) {
  final trimmed = address.trim();
  final at = trimmed.lastIndexOf('@');
  final to = at < 0
      ? Uri.encodeComponent(trimmed)
      : '${Uri.encodeComponent(trimmed.substring(0, at))}@'
            '${Uri.encodeComponent(trimmed.substring(at + 1))}';
  return Uri.parse(
    'mailto:$to'
    '?subject=${Uri.encodeComponent(subject)}'
    '&body=${Uri.encodeComponent(body)}',
  );
}

/// The line about the app in the mail, such as `My App 1.0.0 (1), dev`:
/// [emailFeedbackAppName], the [version] and the [buildNumber] of the app,
/// and the [flavor] of the build unless it is the flavor for a release,
/// which users install from a store. A part that is unknown or empty is
/// left out.
String emailFeedbackAppLine({
  String? version,
  String? buildNumber,
  String? flavor,
}) {
  final line = StringBuffer(emailFeedbackAppName);
  if (_known(version) case final version?) line.write(' $version');
  if (_known(buildNumber) case final build?) line.write(' ($build)');
  if (_known(flavor) case final flavor? when flavor != _releaseFlavor) {
    line.write(', $flavor');
  }
  return '$line';
}

/// The line about the device in the mail, such as
/// `Android 14 (SDK 34), Google Pixel 7` or `iOS 17.4, iPhone 15 Pro`: the
/// [system] with its [systemVersion] and, on Android, its [sdk], then the
/// [manufacturer] and the [model]. A model that starts with the name of its
/// manufacturer, whatever the case of its letters, does not repeat it. A
/// part that is unknown or empty is left out.
String emailFeedbackDeviceLine({
  String? system,
  String? systemVersion,
  int? sdk,
  String? manufacturer,
  String? model,
}) {
  final maker = _known(manufacturer);
  final name = _known(model);
  final systemPart = [
    ?_known(system),
    ?_known(systemVersion),
    ?(sdk == null ? null : '(SDK $sdk)'),
  ].join(' ');
  final repeats =
      maker != null &&
      name != null &&
      name.toLowerCase().startsWith(maker.toLowerCase());
  final devicePart = [?(repeats ? null : maker), ?name].join(' ');
  return [
    for (final part in [systemPart, devicePart])
      if (part.isNotEmpty) part,
  ].join(', ');
}

/// The body of the mail: two empty lines in which the user writes, then
/// [header], such as "About the app and the device:", and each of [lines]
/// that is not empty, with a line break of a mail, `\r\n`, between them.
String emailFeedbackBody({
  required String header,
  required List<String> lines,
}) => [
  '',
  '',
  header,
  for (final line in lines)
    if (line.trim().isNotEmpty) line,
].join('\r\n');

/// [value] without the spaces around it, or `null` when that leaves
/// nothing.
String? _known(String? value) {
  final trimmed = value?.trim();
  return trimmed == null || trimmed.isEmpty ? null : trimmed;
}

/// A text that keeps its words whole: it breaks between its words and never
/// inside one. A space, a tab or a line break parts two words, and a
/// no-break space keeps the two words around it together as one.
///
/// It grows with the text size of the device, by [maxScaleFactor] at most.
/// Where its longest word would still not fit the width that the text has,
/// as on a narrow phone with a large text size, the text is as large as
/// that word allows.
class _WholeWords extends StatelessWidget {
  const _WholeWords(
    this.text, {
    this.style,
    this.textAlign,
    this.maxScaleFactor = double.infinity,
  });

  /// The text.
  final String text;

  /// The style of the text, over that of the text around it. With none, the
  /// text is as the text around it, as the label of a button is in the style
  /// that the theme of the app gives the button.
  final TextStyle? style;

  /// How the lines of the text are aligned.
  final TextAlign? textAlign;

  /// By how much the text grows at most with the text size of the device.
  final double maxScaleFactor;

  @override
  Widget build(BuildContext context) {
    // The style in which a Text paints: over that of the text around it, and
    // bold for a user who asks for bold text.
    var style = DefaultTextStyle.of(context).style.merge(this.style);
    if (MediaQuery.boldTextOf(context)) {
      style = style.merge(const TextStyle(fontWeight: FontWeight.bold));
    }
    final scaler = MediaQuery.textScalerOf(
      context,
    ).clamp(maxScaleFactor: maxScaleFactor);
    return LayoutBuilder(
      builder: (context, constraints) {
        final room = constraints.maxWidth;
        final painter = TextPainter(
          textDirection: Directionality.of(context),
          textScaler: scaler,
          maxLines: 1,
        );
        // The words of the text, between its white spaces, where a line may
        // break: every one but a no-break space, which keeps the words
        // around it together.
        final words = text.split(RegExp(r'[^\S\u00A0\u2007\u202F]+'));
        // How wide the longest word is in a font of [size].
        double widestAt(double size) {
          var widest = 0.0;
          for (final word in words) {
            painter
              ..text = TextSpan(
                text: word,
                style: style.copyWith(fontSize: size),
              )
              ..layout();
            if (painter.width > widest) widest = painter.width;
          }
          return widest;
        }

        // The size of a text of Flutter whose style gives none.
        var size = style.fontSize ?? 14;
        var widest = widestAt(size);
        // In a few steps: the text size of a device may grow a small font by
        // more than a large one.
        for (var step = 0; step < 4 && widest > room && room > 0; step++) {
          // A little smaller than the width allows, so that the rounding of
          // the layout breaks no word.
          size *= room / widest * 0.98;
          widest = widestAt(size);
        }
        painter.dispose();
        return Text(
          text,
          style: style.copyWith(fontSize: size),
          textAlign: textAlign,
          textScaler: scaler,
        );
      },
    );
  }
}

/// `Locale('pt', 'BR')` and `Locale('pt', 'PT')`, `appLocale.choose()`

const appLocales = <Locale>[Locale('en'), Locale('uk')];

/// language that the user chose, as the code of the language, such as `uk`.
/// Nothing is saved under it while the app follows the languages of the

const _key = 'localization.locale';

/// The language that the user chose for the app, which the app remembers
/// between its launches.
///
/// The root of the app reads it through [AppLocaleScope], and rebuilds in
/// the new language when the choice changes.
final appLocale = AppLocaleController._();

/// Keeps the language that the user chose for the app, and saves each
/// choice in the preferences of the app.
final class AppLocaleController extends ChangeNotifier {
  AppLocaleController._();

  Locale? _locale;

  /// The preferences of the app, once it opened them.
  AppPreferences? _preferences;

  /// The language that the user chose, one of [appLocales], or `null` while
  /// the app follows the languages of the device.
  Locale? get value => _locale;

  /// Chooses the language of [locale] as the language of the app, or with
  /// `null` lets the app follow the languages of the device again.
  ///
  /// The choice is the one of [appLocales] with the language of [locale],
  /// so `Locale('uk', 'UA')` chooses `Locale('uk')`. A locale of a language
  /// that the app is not in is refused: the future completes with an
  /// [ArgumentError], and nothing changes.
  ///
  /// The language of the app changes at once, and the choice is then saved
  /// in the preferences once the app opened them: before that, it changes
  /// only memory. When saving fails, the future completes with the error of
  /// the preferences. The app stays in the new language while it runs, and
  /// its next launch starts with what was saved before; choosing the
  /// language again saves it again.
  Future<void> choose(Locale? locale) async {
    final chosen = locale == null ? null : _ofApp(locale.languageCode);
    if (locale != null && chosen == null) {
      throw ArgumentError.value(
        '$locale',
        'locale',
        'The app is not in the language of this locale',
      );
    }
    _set(chosen);
    final preferences = _preferences;
    if (preferences == null) return;
    if (chosen == null) {
      await preferences.remove(_key);
    } else {
      await preferences.setString(_key, chosen.languageCode);
    }
  }

  void _set(Locale? locale) {
    if (locale == _locale) return;
    _locale = locale;
    notifyListeners();
  }
}

/// The one of [appLocales] with the language of the code [code], or `null`.
Locale? _ofApp(String? code) {
  for (final locale in appLocales) {
    if (locale.languageCode == code) return locale;
  }
  return null;
}

/// Restores the language that the user chose from [preferences], which the
/// app opened, and keeps them for the choices to come: a restorer of the
/// preferences, which the app calls before its first frame.
///
/// When nothing is saved, or what is saved is not the code of one of
/// [appLocales], the choice stays as it is.
void restoreAppLocale(AppPreferences preferences) {
  appLocale._preferences = preferences;
  final saved = _ofApp(preferences.getString(_key));
  if (saved != null) appLocale._set(saved);
}

/// Gives the root of the app the language that the user chose, and rebuilds
/// the root when the choice changes.
class AppLocaleScope extends InheritedNotifier<AppLocaleController> {
  /// Creates the scope of [notifier] around [child].
  const AppLocaleScope({
    required AppLocaleController super.notifier,
    required super.child,
    super.key,
  });

  /// The language that the user chose, or `null` to follow the device; the
  /// widget of [context] rebuilds when the choice changes.
  static Locale? of(BuildContext context) => context
      .dependOnInheritedWidgetOfExactType<AppLocaleScope>()!
      .notifier!
      .value;
}

/// The settings of the app that are no secret, which it remembers between
/// its launches: the theme mode, the language, whether the user has seen
/// the onboarding.
///
/// Nothing here is encrypted, and a backup of the device carries it: never
/// store a token, a password, an API key or an encryption key in the
/// preferences.
///
/// A key is `<owner id>.<setting>`, such as `theme.mode`, where the owner
/// is the module or the role whose code keeps the setting. A key has one
/// value: a write replaces what the key had, a value of another type too.
///
/// A read is synchronous, from memory, and never throws: it returns `null`
/// when the key has no value of the type it asks for. Whether a number
/// saved as an `int` is read as a `double`, or the other way round, is up
/// to the provider of the preferences. Once the future of a write
/// completes, reads return what it saved, in this run of the app and after
/// its next launch.
abstract interface class AppPreferences {
  /// The text saved under [key], or `null` if it has none.
  String? getString(String key);

  /// The flag saved under [key], or `null` if it has none.
  bool? getBool(String key);

  /// The whole number saved under [key], or `null` if it has none.
  int? getInt(String key);

  /// The number saved under [key], or `null` if it has none.
  double? getDouble(String key);

  /// A copy of the list of texts saved under [key], or `null` if it has
  /// none: a change of the list changes nothing that is saved.
  List<String>? getStringList(String key);

  /// Saves the text [value] under [key].
  Future<void> setString(String key, String value);

  /// Saves the flag [value] under [key].
  Future<void> setBool(String key, bool value);

  /// Saves the whole number [value] under [key].
  Future<void> setInt(String key, int value);

  /// Saves the number [value] under [key].
  Future<void> setDouble(String key, double value);

  /// Saves a copy of the list of texts [value] under [key]: a later change
  /// of [value] changes nothing that is saved.
  Future<void> setStringList(String key, List<String> value);

  /// Removes what is saved under [key], which puts its setting back to its
  /// default: the reads of [key] return `null` again.
  Future<void> remove(String key);
}

/// Opens the preferences of the app and gives them to the restorers of its
/// parts; `bootstrap()` awaits it before the first frame, and nothing else
/// in the app calls it.
///
/// It may run again, as a test does to see what the next launch of the app
/// reads: it opens the preferences anew, with what is saved, and calls the
/// restorers again.
Future<void> initPreferences() async {
  _appPreferences = await impl0.openSharedAppPreferences();
  _restore(_appPreferences);
}

/// The functions of the parts of the app that restore what they keep in the
/// preferences, such as the theme mode. [initPreferences] calls each with
/// the preferences once they are open, so that every part has its settings
/// before the first frame.
///
/// A restorer reads its settings, and keeps the preferences for the writes
/// of its part. It is synchronous and awaits nothing: nothing waits for an
/// asynchronous one, and what such a one throws is not caught. It may run
/// again, with preferences that were opened anew.
final List<void Function(AppPreferences preferences)> _restorers = [
  restoreAppLocale,
];

/// Calls each of [_restorers] with [preferences] on its own: what one
/// throws, an error or an exception, keeps no other from restoring and does
/// not stop the start-up of the app, which goes on with the defaults of
/// that part. In debug mode it is printed, so that a restorer that fails
/// shows in the console.
void _restore(AppPreferences preferences) {
  for (final restore in _restorers) {
    try {
      restore(preferences);
    } on Object catch (error) {
      if (kDebugMode) {
        debugPrint('A restorer of the preferences failed: $error');
      }
    }
  }

import 'app_preferences.dart';

/// Opens the preferences of the app with the shared_preferences package: it
/// reads what is saved into memory, which the reads then answer from.
///
/// The app has one object of its preferences, which
/// `createAppPreferences()` returns once `initPreferences()` opened them.
Future<AppPreferences> openSharedAppPreferences() async => SharedAppPreferences(
  await SharedPreferencesWithCache.create(
    cacheOptions: const SharedPreferencesWithCacheOptions(),
  ),
);

/// The settings of the app that are no secret, with the shared_preferences
/// package, which keeps them in DataStore on Android and in `UserDefaults`
/// on iOS.
///
/// Neither is encrypted, and a backup of the device carries them: never
/// store a token, a password, an API key or an encryption key in the
/// preferences.
///
/// A number is read only as the type that it was saved as: `getDouble`
/// returns `null` for a key with an `int`, and `getInt` for a key with a
/// `double`, a whole number too.
///
/// A write puts its value into memory before it saves it. If the platform
/// refuses the save, as Android does for a text that starts with the prefix
/// that shared_preferences marks a list with, the write fails, and the
/// reads of this run return the value all the same. The next launch reads
/// what was saved before the write, or nothing if the key had no value.
final class SharedAppPreferences implements AppPreferences {
  /// Creates the preferences on [SharedPreferencesWithCache], which has
  /// read what is saved.
  SharedAppPreferences(this._preferences);

  final SharedPreferencesWithCache _preferences;

  @override
  String? getString(String key) => _read<String>(key);

  @override
  bool? getBool(String key) => _read<bool>(key);

  @override
  int? getInt(String key) => _read<int>(key);

  @override
  double? getDouble(String key) => _read<double>(key);

  @override
  List<String>? getStringList(String key) => switch (_preferences.get(key)) {
    final List<Object?> list => _textsOf(list),
    _ => null,
  };

  @override
  Future<void> setString(String key, String value) =>
      _preferences.setString(key, value);

  @override
  Future<void> setBool(String key, bool value) =>
      _preferences.setBool(key, value);

  @override
  Future<void> setInt(String key, int value) => _preferences.setInt(key, value);

  @override
  Future<void> setDouble(String key, double value) =>
      _preferences.setDouble(key, value);

  /// shared_preferences keeps the list that it is given, so it gets a copy.
  @override
  Future<void> setStringList(String key, List<String> value) =>
      _preferences.setStringList(key, List.of(value));

  @override
  Future<void> remove(String key) => _preferences.remove(key);

  /// The value of [key] if it is a [T], or `null`. The reads of
  /// shared_preferences cast the value instead, and throw on a value of
  /// another type.
  T? _read<T>(String key) => switch (_preferences.get(key)) {
    final T value => value,
    _ => null,
  };

  /// A copy of [list] as a list of texts, or `null` if an item of it is no
  /// text.
  ///
  /// When the preferences are opened, the platform returns a list in a form
  /// of its own: a list of objects on iOS, and on Android a list that casts
  /// each item to a text as it is read, and so throws on an item that is
  /// none. Cast to objects, either gives its items as they are.
  static List<String>? _textsOf(List<Object?> list) {
    final items = list.cast<Object?>();
    return items.every((item) => item is String)
        ? List<String>.from(items)
        : null;
  }
}
